## 一、诊断结论

### 1.1 数据真实性问题（最高优先）
- **已确认**：SDI 系列 36+ 个结果 JSON 中，大量**无 run.log 支撑**（tmp_gh 全量配对：18 有 log / 40 无 log）；V6_AUDIT 记录 τ 尺度关系违反（80% 偏差）等科学性问题。
- **风险**：LLM 生成数据作为激励 → 结果拟合而非真实仿真 → 违背科研原则。
- **处置**：无 log 支撑的结果 JSON 一律**隔离标记**，禁止进入论文证据链；论文引用必须满足"三证据"（run.log + seed + 代码版本）。

### 1.2 副本与混乱问题
- **已确认**：55_Guides 项目指南多版本堆积（海河 2026 重大专项 6 变体、NSFC 2 变体、项目指南 8.0 多格式）；导航文件旧路径残留（30_Outputs → 实际 50_Output/51_Papers）；tmp_gh/30_Outputs 旧目录未合并。
- **规模**：vault 本地 28,584 文件 vs git 追踪 12,137（差异含 .smart-env 772MB 缓存、data_local 等**已忽略**部分，属正常）。
- **历史**：Agent/01-Theory-Research 曾因去重指纹失效产生 79% 冗余（60MB）——现行 dedup_* 脚本家族已吸取教训。

## 二、重组原则

1. **单向流动**：00_Inbox → 20_Processing → 30_TCC/40_iNEST → 50_Output → 80_Archive（保持 AGENTS.md §1.4）。
2. **唯一正式版**：每个成果只有一个正式版在 50_Output，中间版本/草稿进 80_Archive 并保留版本台账。
3. **SSOT 真源**：CST/SDI/TCC 定义只存 `10_Knowledge/SSOT/`，各线引用不复制。
4. **三证据闸门**：仿真结果必须（run.log + seed + 代码版本）齐备才可入论文。
5. **不删除原则**：重组只移动/标记，不删除任何内容（80_Archive 收容）。
