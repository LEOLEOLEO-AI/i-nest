# 晶圆级异构集成方案详解

# 软件定义晶上系统（SDSoW）与拓扑中心计算（TCC）答疑汇总

---

## 一、技术方案层面

### 1. 总体方案：8英寸晶圆上集成什么？

**不是在8英寸晶圆上做多个功能芯片，而是"晶圆级基板 + 异构芯粒 + 软件定义互连"的三层架构。** 

具体来说：
- **晶圆基板**：8英寸晶圆作为系统级互连基底，上面部署 SDI（软件定义互连）交换节点阵列，形成统一的物理 Mesh 互联骨架。
- **异构芯粒**：算力 Die（NPU/GPU）、存储 Die（HBM/SRAM）、I/O Die 等，通过混合键合（Hybrid Bonding）或微凸点倒装在晶圆基板上，与 SDI 交换节点直连。
- **工艺策略**：不同 Die 采用各自最优工艺节点——算力 Die 可用 12nm/7nm，SDI 互连 Die 用 28nm 成熟工艺即可，存储用专用工艺。**这正是晶上系统"增维求解"的核心：用成熟工艺通过系统级集成超越单一先进工艺芯片的性能。** 

与 Cerebras 的单片晶圆级集成（整片晶圆做同一种计算单元）不同，我们走的是**异构芯粒 + 可编程互连**路线——晶圆不是"一块超大芯片"，而是"一个可软件定义拓扑的计算基板"。

### 2. SerDes 接口协议与工艺节点

**物理层兼容 UCIe 标准，向上扩展 TCC-Link 拓扑语义层。** 

- **协议栈**：底层 PHY 和链路层与 UCIe 兼容（确保生态互通），网络层以上扩展 TCC 原语（Route/Transform/Control）和 Topology Page 抽象，支持多拓扑动态切换和集合通信加速。
- **SerDes 速率**：SDI 三代芯片路线已验证——一代 32×12.5G（400Gbps），二代持续演进，三代目标单 Lane 25G+，总带宽 5 年增长 16 倍。
- **工艺节点**：SDI 交换芯片当前用 28nm 成熟工艺即可实现（交换逻辑对工艺节点不敏感），PHY 部分根据速率需求可升级到 12nm。**这是我们的差异化优势：用成熟工艺做互连，把先进工艺留给算力 Die。** 

### 3. 可编程互联的配置参数与节点选择

**配置表格可指定的参数**：
- 连接关系：任意节点对之间的通断（虚电路模式）
- 链路权重/带宽分配：多通路划分与带宽调度
- 拓扑模式：Mesh / Ring / Tree / Torus / 全连接等 6 种元拓扑及组合
- 时隙分配：时分复用的时隙表，支持阶段间硬切换
- 路由规则：源路由 / 标签交换 / 最短路径等

**关于"不全节点互联怎么选节点"**：这正是 TCC 的核心创新——不是物理上全连接（那是浪费），而是**根据任务阶段的数据流拓扑，通过 SDI 动态实例化最优连接结构**。

- 训练阶段：实例化 Ring / Tree 拓扑，优化 AllReduce 梯度同步
- 推理阶段：实例化 All-to-All / 胖树拓扑，优化 Token 级调度
- 配置与激活解耦：候选拓扑提前预计算并存入配置表，阶段切换时只需"状态选择 + 生效确认"，切换开销 τ 可压到微秒级。

**实现方式**：纯数字设计实现。SDI 交换节点是标准数字电路（交叉开关 + 配置寄存器 + 调度器），通过寄存器级配置切换拓扑，不依赖模拟可调元件。

### 4. 功能 Die 接口策略：UCIe + Bridge + 定制 IP 三层方案

- **标准 UCIe 接口**：对已有成熟 NPU/GPU Die，直接通过 UCIe 物理接口接入，零改动或少量改动。底层协议完全兼容 UCIe 标准。
- **Bridge 模式**：对 PCIe / CXL / RapidIO 等已有接口的 Die，通过 SDI 上的协议转换 Bridge 接入。SDI 三代芯片已支持 RapidIO、Ethernet、FC、PCIe 四协议统一承载。
- **定制 TCC-Link IP**：对新设计的 NPU Die，推荐集成 TCC-Link 接口 IP——在 UCIe PHY 之上增加拓扑语义层，使 NPU 能直接感知 Topology Page，实现"拓扑重构即计算"的 Route≡Transform 原语融合，这是性能最大化的路径。

**三种集成模式从浅到深**：外挂式（FPGA + PCIe）→ Chiplet 级（UCIe 封装内）→ 片内融合（TCC-Link IP 原生集成）。当前 8 英寸样机处于 Phase 1-2 之间。

### 5. 数据传输校验与 Retry 机制

- **校验机制**：链路层采用 CRC 校验（标准 UCIe 链路层可靠性机制 + SDI 扩展的端到端校验），支持按 Flit 粒度检错。
- **Retry 颗粒度**：以 **Flit（流控单元）** 为粒度进行重传，典型 Flit 大小 64-256B。链路层采用 Go-back-N 或 Selective Reject ARQ。
- **对已有 Die 的兼容方案**：对于已经设计好的功能 Die（如第三方 NPU），**不需要修改 Die 内部逻辑**——校验和 Retry 在 SDI 交换节点与 UCIe 接口层完成，对功能 Die 透明。SDI 作为"智能互连层"承担可靠性保障，功能 Die 看到的就是一个可靠的链路接口。

### 6. 键合工艺：单片内部与晶圆间互联

**单片晶圆内部连接**：
- 采用**硅基板 + RDL（重布线层）** 方案。晶圆级基板上做多层 RDL，实现 SDI 交换节点之间的高密度互连，以及 SDI 节点与功能 Die 之间的微米级间距连接。
- 功能 Die 通过**混合键合（Hybrid Bonding）**或微凸点倒装键合到晶圆基板上，互联密度从传统封装的毫米级跃升至微米级，单个裸片可引出上万根连线。

**晶圆间互联**：
- 当前阶段通过**晶圆级边缘 I/O + 高速 SerDes** 实现多晶圆扩展，不是 CPO（共封装光学）。
- 长期路线预留光互联接口（硅光子），用于更大规模的晶圆间扩展。CPO 是未来演进方向之一，但当前样机阶段以电互联为主，确保成熟可控。
- 垂直方向支持 3D 堆叠：例如存储 Die 堆叠在逻辑 Die 上方，通过混合键合实现 TSV 级垂直互联，单位面积算力可提升 2.5 倍。

### 7. 分布式训练/推理的算力 Die 并行部署与系统工作流程

**并行部署经验**：
- 我们已在仿真层面完成 1024-2048 节点规模的验证，通信与计算完全重叠，效率达到 90% 以上。
- 核心思路：将大模型计算图拆解为"计算阶段 + 通信阶段"的序列，每个阶段匹配最优拓扑（训练用 Ring/Tree 做 AllReduce，推理用 All-to-All 做 Token 调度），通过 TCC 编译器自动完成拓扑映射和阶段调度。

**系统工作流程（从上电起）**：

1. **上电初始化**：晶圆基板电源管理单元（PMU）上电，SDI 交换节点逐行启动自检与 BIST
2. **拓扑发现**：控制平面（运行在主控 CPU 上）扫描所有可用算力 Die、存储 Die 和 SDI 节点，构建资源拓扑图
3. **故障检测与冗余映射**：识别良率缺陷节点，通过冗余路径和备用 Die 自动重映射，确保系统可用
4. **Topology Page 加载**：根据部署的模型和任务，TCC 编译器生成一组拓扑页（训练页、推理页等），预加载到 SDI 配置寄存器
5. **任务启动**：主控下发任务，激活初始拓扑页，算力 Die 开始计算
6. **阶段切换**：任务运行到阶段边界时，SDI 在 τ 时间内（微秒级）切换到下一个拓扑页，算力 Die 无缝继续计算
7. **运行时动态调整**：根据负载和故障情况，控制平面可热更新拓扑页，实现液态拓扑的动态演化

### 8. Die 摆放规则与 512TOPS@FP16 算力要求

**摆放规则**：
- **就近原则**：算力 Die 与相邻 SDI 交换节点直连，减少跳数
- **存储亲和**：HBM/存储 Die 均匀分布在算力 Die 周围，形成"计算-存储"配对的 MacroTile 结构
- **SDI 网格化**：SDI 交换节点按规则 Mesh 排布，作为整个晶圆的"互连骨架"，算力 Die 和存储 Die 挂接在 Mesh 节点上
- **热均衡**：高功耗算力 Die 分散排布，避免局部热点集中，配合微流道散热方案

**512TOPS@FP16 的算力要求**：
- 8 英寸晶圆有效面积约 200cm²（扣除边缘划片区）
- 若采用 28nm 工艺的 NPU Die，单 Die（约 50-80mm²）FP16 算力约 4-8TOPS
- 晶圆上可部署约 60-100 个算力 Die，总算力可达 240-800TOPS
- **结论**：512TOPS 目标完全可达成。单 Die 算力最低要求约 5-6TOPS@FP16（28nm 工艺下 NPU 可轻松达到）。如果用更先进工艺（12nm/7nm）的 Die，单 Die 算力更高，所需 Die 数量更少，良率更优。

## 二、具体性能参数

### 1. 延迟指标定义

**1μs 新节点建立延迟**：
- 起点：控制平面发出"拓扑切换"指令（写入 SDI 配置寄存器）
- 终点：新拓扑配置生效、第一个数据 Flit 成功通过新路径到达目的节点
- 包含的逻辑延时：寄存器配置传播（~10ns）→ 交叉开关切换（~50ns）→ 链路训练/同步（~100-200ns）→ 路由表更新（~100ns）→ 首包传输（取决于路径长度，约 100-500ns）
- **核心优势**：配置与激活解耦，大部分拓扑预计算已完成，切换时只需"选通"操作，远低于传统网络的秒级/毫秒级重配置。

**1ns 老节点数据传输延迟**：
- 起点：数据进入 SDI 交换节点的输入端口
- 终点：数据从相邻 SDI 节点的输出端口送出（单跳延迟）
- 包含的逻辑延时：输入缓冲 → 路由查表 → 交叉开关穿越 → 输出缓冲，均为单周期或几周期操作
- 这是晶圆级短距离互连的物理优势：线长短、信号完整性好，单跳延迟可比板级互连低一个数量级。

### 2. 误码率

- **当前样品**：链路层误码率 < 10⁻¹²（电互连、晶圆级短距离、低损耗环境下的典型值）
- **设计目标**：端到端误码率 < 10⁻¹⁵（通过链路层 CRC + 重传 + 端到端校验三级保障）
- 晶圆级互连的天然优势：传输距离从厘米级缩短到毫米/微米级，信道损耗极低，误码率远低于板级和背板互连。

### 3. 位宽、速度、带宽利用率

| 参数 | 当前样机 | 设计目标 |
|------|---------|---------|
| 单 Lane 速率 | 12.5 Gbps | 25-32 Gbps |
| 每 SDI 节点 Lane 数 | 32 条 | 64-128 条 |
| 单节点总带宽 | 400 Gbps | 1.6-4 Tbps |
| 接口位宽 | 可配置（8/16/32/64 bit） | 同左 |
| 带宽利用率 | >85%（虚电路模式下） | >90% |

**带宽利用率高的原因**：SDI 采用**电路交换 + 分组交换双模**。对大流量稳定通信走虚电路（电路交换模式，无包头开销、接近 100% 利用率）；对小流量突发通信走分组交换。这比纯分组交换网络（通常 40-60% 利用率）高得多。

### 4. 系统算力资源利用率

- **仿真验证结果**：1024-2048 节点规模下，大模型训练/推理任务的**算力利用率达 90% 以上**，远高于传统 GPU 集群（通常 30-50%）。
- **根本原因**：传统系统的瓶颈是"结构性失配"——任务阶段的数据流拓扑与固定互连结构不匹配，大量时间花在等待通信上。TCC 通过动态切换拓扑，让每个阶段的互连结构都匹配通信模式，通信与计算完全重叠，从而把算力利用率拉满。

## 三、产品成熟度

### 1. 良率与提升方案

- **当前良率**：8 英寸样机阶段，SDI 基板良率 > 90%（28nm 成熟工艺 + 规则结构，良率天然高）；系统级良率（考虑 Die 键合缺陷）通过冗余设计保障 > 85%。
- **良率提升方案**：
  - **冗余设计**：SDI 交换节点和互连线预留 10-15% 冗余，故障节点自动旁路
  - **Die 级筛选**：功能 Die 先做 Known-Good-Die（KGD）测试，合格后再键合
  - **可重构容错**：即使部分 SDI 节点或 Die 失效，软件可重新映射拓扑，绕过故障区域，系统功能不中断——这是软件定义架构的天然优势
  - **渐进式测试**：晶圆级探针测试 → 键合后中间测试 → 最终系统测试，层层筛除缺陷

### 2. 散热方案与限制

- **散热方案**：采用**微流道液冷**方案，在晶圆背面或硅中介层内制作微流道，冷却液直接流经高发热区域，散热能力可达 200-500W/cm²。
- **热设计考量**：
  - 算力 Die 分散排布，避免热点集中
  - 3D 堆叠时，高功耗层靠近散热侧
  - SDI 互连层功耗低（交换逻辑功耗远小于计算逻辑），主要热源是算力 Die
- **限制**：当前液冷方案可支持单晶圆 5-10kW 总功耗，满足 512TOPS@FP16 量级的算力需求。更高功耗需更激进的两相流或浸没式液冷方案。

### 3. 晶圆板稳定性与物理变形

- **弯曲/翘曲控制**：晶圆基板采用低应力设计，通过多层 RDL 的应力匹配、晶圆减薄后的支撑框架（carrier wafer）来控制翘曲度 < 100μm。
- **抗震与机械稳定性**：晶圆级系统封装在刚性基板/框架内，通过底部填充（underfill）和全局灌封增强机械强度。
- **热膨胀匹配**：选择与硅热膨胀系数接近的封装材料（如硅中介层、低 TCE 基板），减少温度循环中的应力累积。
- **已有方案**：团队在 SDI 三代芯片和晶圆级集成方向有多年技术积累，晶圆键合、应力控制、可靠性测试均有成熟工艺方案。

### 4. 动态管理软件与工具链

**动态管理软件**：
- **TCC 控制平面**：运行在主控 CPU（或晶圆上的管理 Die）上，负责拓扑管理、故障检测、资源调度
- **拓扑编译器（TCC Compiler）**：将计算图自动分解为 Topology Page 序列，生成 SDI 配置流
- **运行时管理器**：负责阶段切换、负载均衡、故障恢复

**部署位置**：
- 控制平面和编译器：运行在晶圆外的主控 CPU / 服务器上（当前阶段）
- 运行时管理器：部分关键逻辑可下沉到 SDI 节点内置的 RISC-V 核上，实现更快的本地切换

**工具链现状**：
- SDI 芯片的配置工具、SDK、驱动已成熟（三代芯片演进，TRL 7-8 级）
- TCC 编译器、拓扑页生成工具处于研发阶段，已有原型版本，支持主流大模型框架的接入
- 长期目标：对接 PyTorch / TensorFlow 等主流框架，通过 TCC-NCCL Plugin 等方式实现透明加速，用户无需修改模型代码

## 四、软件系统方向

### 1. 8英寸晶圆测试样机的算力 Die 与软件栈

**当前封装的算力 Die**：
- 样机阶段采用 **FPGA 原型验证方案**：在晶圆基板上键合 FPGA Die（作为算力节点原型）+ SDI 交换 Die，验证晶圆级互连和拓扑切换功能。
- 这是 Phase 1（外挂式 / FPGA 原型）到 Phase 2（Chiplet 级 ASIC）的过渡形态。

**晶圆与 Die 的交互方式**：
- Die 通过混合键合/微凸点连接到晶圆基板的 RDL 层
- Die ↔ SDI 交换节点 ↔ 其他 Die，所有通信通过 SDI 互连矩阵完成
- 晶圆基板上的 SDI Mesh 是"系统总线"，所有 Die 挂接在上面

**支撑软件栈**：
- 底层：SDI 驱动 + 配置工具（成熟）
- 中间层：TCC 运行时 + 拓扑管理 + 资源调度（原型可用）
- 上层：TCC 编译器 + 模型适配层（研发中，已支持典型大模型的拓扑映射）

### 2. 软件工具链完备度与开放程度

| 层级 | 完备度 | 开放程度 |
|------|-------|---------|
| SDI 驱动/配置工具 | ★★★★★（成熟量产） | 提供 SDK + API |
| TCC 运行时 | ★★★☆☆（原型可用） | 计划开源核心接口 |
| TCC 编译器 | ★★☆☆☆（研发中） | 计划提供插件机制 |
| 大模型框架适配 | ★★☆☆☆（原型验证） | 对接 PyTorch/TF |
| 第三方软件适配 | ★★☆☆☆ | 提供标准接口 + 参考实现 |

**第三方适配能力**：
- 底层走 UCIe 标准，任何支持 UCIe 的 Die 都能接入
- 网络层提供标准 API，第三方框架可通过 TCC-NCCL Plugin 等方式接入
- 长期目标是成为开放的晶上系统软件生态，而非封闭平台

### 3. 片上资源配置：固化还是可编程？更新代价？

**不是完全固化的，而是"硬件资源固定 + 拓扑软件定义"的模式**：
- **硬件资源**：晶圆上的算力 Die 数量、存储容量、SDI 节点数——这些是制造时确定的，出厂后物理上不可变
- **逻辑拓扑**：算力 Die 之间的连接关系、拓扑结构、带宽分配——这些完全由软件定义，可运行时动态切换，零硬件改动
- **更新代价**：拓扑更新是寄存器级配置，代价极低（微秒级切换时间，几乎零功耗开销）

**与外部存储的交互**：
- 与传统计算机有相似之处（通过存储控制器访问外部 DDR/HBM），但有本质区别：
  - 传统架构：计算→通过总线访存→计算，存储是"外设"
  - 晶上系统：存储 Die 与算力 Die 在同一晶圆基板上，通过 SDI 直连，延迟和带宽接近片上水平，存储是"一等公民"
  - 更关键的是：**存储与计算的连接拓扑也可编程**，可根据访存模式动态调整存储访问路径

### 4. 大模型推理验证与模型部署方式

**已做的验证**：
- 在仿真平台上完成了主流开源大模型（LLaMA 系列、Transformer 类）的推理映射验证
- 验证了"训练拓扑 ↔ 推理拓扑"的动态切换，证明训推一体架构的可行性
- 针对大模型推理的 All-to-All 通信模式，优化了 SDI 拓扑配置，Token 级调度延迟显著降低

**模型部署方式**：
- **目标是自动化排布**：TCC 编译器接收计算图 → 自动分析各阶段的通信模式 → 生成最优 Topology Page 序列 → 映射到 SDI 配置
- 当前阶段：对于标准 Transformer 类模型，可实现半自动排布（编译器生成 + 人工微调）
- 长期目标：完全自动化，用户只需上传模型，编译器自动完成拓扑优化和部署调度

**核心竞争力**：不是"把模型塞进晶圆"，而是**让晶圆的互连拓扑跟着模型的数据流走**——每个计算阶段都匹配最优拓扑，这是传统固定拓扑系统做不到的。

### 5. 端侧应用场景

晶上系统 + TCC 的端侧应用，核心价值在于**"小体积、低功耗、高算力、灵活拓扑"**，典型场景包括：

- **智能射频/雷达**：DBF（数字波束成形）+ 实时目标识别，需要 RF 前端 + 计算 + 高速互连的紧耦合，TCC-RF 产品方向可支持波束成形拓扑与推理拓扑的动态切换。
- **超低轨卫星智能载荷**：空间受限、功率受限，需要感传存算智一体、通导遥融合。晶上系统的高集成度 + 液态拓扑，恰好匹配卫星载荷的极端约束。
- **边缘 AI 盒子**：工业视觉、自动驾驶域控制器等场景，需要在有限功耗下提供高算力，同时支持多任务动态切换（检测→跟踪→识别各阶段拓扑不同）。
- **智能终端**：AR/VR 设备、无人机等，对体积、重量、功耗敏感，晶上系统的集成度优势明显。

**端侧的差异化**：不是跟 GPU 比绝对算力，而是比**单位体积算力、单位功耗算力、以及拓扑灵活性**——在端侧约束下，这三个维度的价值远大于峰值算力。

## 我们的核心竞争力总结

一句话概括：**别人在做"更大的芯片"，我们在做"可软件定义的计算系统"。**

1. **范式级创新**：TCC（拓扑中心计算）是继计算中心、存储中心之后的第三类体系结构范式，有完整的理论体系（三条可证明定理）和工程落地路径，不是简单的工艺改进。
2. **换道超车**：用 28nm 成熟工艺 + 系统级架构创新，实现超越先进工艺的系统性能，避开了先进制程卡脖子的问题。
3. **软件定义的深度**：从物理层拓扑就开始软件定义，不是在固定硬件上做软件调度，而是让硬件连接本身成为可编程的一等对象。
4. **全栈可控**：从 SDI 芯片（三代自研）→ 晶上系统集成 → TCC 编译器 → 应用适配，全链条自主可控。
5. **从架构到智能的想象力**：TCC 不仅是通信优化方法，更可能成为"智能载体构造方法"——把网络时空协同复杂度从偶然结果变成可工程调节的设计变量，通向 iNEST 智能涌现的终局。
