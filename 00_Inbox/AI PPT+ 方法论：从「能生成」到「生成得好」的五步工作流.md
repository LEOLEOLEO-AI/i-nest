# AI PPT+ 方法论：从「能生成」到「生成得好」的五步工作流

### 🎯 PPT Master 已经够用了，为什么还要折腾 AI PPT+？

**PPT Master 解决「生成」，AI PPT+ 解决「生成得好」**。
- **PPT Master 定位**：运行在 Agent 环境里的 PPT 工作流，可将 PDF、DOCX、Markdown 等材料转成**可编辑的 PPTX**，不是单纯输出图片。
- **核心公式**：`Harness + Model = Agent` → 工作流由 PPT Master 负责，质量上限由模型决定。
- **现有痛点**：材料多的时候直接生成，要么内容太简单（被压成几张卡片），要么表达方式单一（标题+四个方框+一排图标），**缺少主次关系和视觉节奏**。

### 💡 「生成得好」的关键突破是什么？

**在文字和 PPT 之间加一层「视觉中间态」**。
- **传统路径**：材料 → 大纲 → PPT
- **AI PPT+ 路径**：材料 → 表格化大纲 → PPT 视觉稿 → 可编辑 PPT
- **为什么多这一步**：语言和视觉之间有缝隙，用文字描述「高级一点」「有空间感」，模型理解和你想的未必一致，反复修改很消耗；生图模型直接画出页面，**几秒就能判断布局、主次、焦点**，达成一致后再还原成可编辑 PPT，难度大幅降低。
  说白了，先让 AI 把样子画出来给你看，对了再动工做真 PPT，省得来回扯皮。

### 📋 第一步：为什么先做表格而不是直接做 PPT？

**先用「PPT 表格思路法」把内容结构定下来**。
- **表格四列**：
  - 页码：第几页
  - 标题/核心思想：这一页想让别人记住什么
  - 页面大纲：具体讲哪些内容
  - 我的修改意见：人工批注调整
- **作用**：把「写 PPT」从模糊任务变成**可快速审阅的结构化原型**，先解决「整份汇报讲什么、每一页为什么存在」，不关心页面好不好看。

### 🎨 第二步：为什么要先生图再做 PPT？

**用生图模型先解决审美问题，文字对错不重要**。
- **推荐生图模型**：`gpt-image-2`（PPT Master 官方推荐）；国内字节 Seed 团队 **2026 年 7 月**发布的 `Seedream 5.0 Pro`，重点强化复杂信息可视化、结构一致性、文字渲染和视觉美学。
- **核心观点**：视觉稿阶段**不在意汉字准不准**，要的是构图、比例、层次、留白、色彩、视觉动线；文字后面会在 PPT 重建阶段按大纲重新填。
- **踩坑经验**：不要一页换一个模型 → 单页好看但整套风格不统一；**风格一致性 > 单页极致**，整套 PPT 尽量在同一个模型、同一个上下文里连续生成，前一页的视觉语言会自然延续。

### 🔧 第三步：怎么让 Agent 忠实还原视觉稿？

**把「生成 PPT」改成「工程化还原」，用「交付契约」明确边界**。
- **错误指令**：「根据这张图片帮我生成 PPT」→ Agent 会重新设计，布局、细节、图标都会丢。
- **正确任务**：把已确认的视觉设计，**工程化还原成可编辑的 PowerPoint**。
- **Agent 交付契约（9 条硬性要求）**：
  1. PPT 默认 **16:9**
  2. 所有文字必须是真实文本框，可直接修改，不能固化在图片里
  3. 简单图形、线条、卡片、标签用 PowerPoint 原生形状或可编辑矢量重建
  4. 小图标可用相似矢量图标替代，优先保证整体视觉一致性
  5. 可独立拆分的图片作为独立对象放入，保证后续可替换调整
  6. 无法可靠重建的复杂插画/素材，保留占位区域并告知需补充的素材；有原始素材则按位置嵌入
  7. 同时提供大纲和参考图时，**大纲管文字内容，参考图管布局与视觉**
  8. 还原优先级：信息层级 → 页面结构 → 空间关系 → 字体与字号 → 图形与图标 → 装饰细节
  9. 每完成一页，确保文件可正常打开、渲染，所有对象可编辑

### 🐎 不同 Agent + 模型组合实测效果怎么样？

**大模型不是全部，Harness（执行框架）同样决定体验上限**。
> 以下为单次任务个人体验，非严格 Benchmark。

| 组合方案 | 生成质量 | 执行速度 | 上下文压力 | 特点 |
| :--- | :--- | :--- | :--- | :--- |
| Codex + GPT-4o / gpt-image-2 | 9/10 | 8.5/10 | 7/10 | 效果稳，长会话上下文压力大，建议每 3-5 页新开会话 |
| WorkBuddy + qwen3.8-max | 8/10 | 5/10 | 4/10 | 多模态能力强、上下文 **1M**，但链路重速度慢，适合时间充裕场景 |
| 轻量代码 Agent + qwen3.8-max | 8.5/10 | 8.5/10 | 6.5/10 | 速度快，自动适配 PPT Master Skill，当前效率最佳 |
- **关键结论**：同一个模型放在不同 Agent Harness 里，效率和体验可能完全不同；选模型之外，还要选**承载它的执行框架**。

### ⚠️ 这套流程里最容易踩哪些坑？

**7 个常见坑及对应解法**：
- **坑 1：一步生成** → 难控制每页逻辑，解法：先表格化大纲，人先控制叙事
- **坑 2：过早做 PPT** → 纠结细节浪费时间，解法：先生成视觉中间态，先解决审美
- **坑 3：频繁换生图模型** → 风格不统一，解法：固定模型和上下文
- **坑 4：纠结视觉稿错别字** → 耗在不重要的事上，解法：视觉稿只管视觉，文字重建时再填
- **坑 5：指令太模糊** → Agent 重新设计不还原，解法：用「Agent 交付契约」明确任务边界
- **坑 6：一个会话干到底** → 速度和稳定性下降，解法：主动切片，做几页就新开会话
- **坑 7：只看模型不看框架** → 体验差异大，解法：不只赛马模型，还要赛马 Harness

### 📝 整套 AI PPT+ 方法浓缩成哪 5 步？

**内容 → 结构 → 视觉 → 工程 → 判断**，五层各司其职。
1. **Source 汇集**：把项目材料、专项汇报、讨论记录、原始文档统一放入项目 Source，先让 AI 理解材料
2. **表格化大纲**：形成「页码 + 核心思想 + 页面内容 + 人工修改意见」，人工在这层控制叙事
3. **视觉中间态**：用同一个生图模型生成高保真视觉稿，解决布局、审美、层次、空间表达
4. **Agent 工程还原**：视觉稿 + 大纲 + 交付契约交给 PPT Master，生成原生可编辑 PPT
5. **人工收口**：调整文字、数字、图表、素材、对齐细节，完成最终交付
> 一句话总结：**AI 负责扩大方案空间，人负责做判断；图片负责确定设计，Agent 负责工程化**。

### ⏱️ 用这套方法效率提升了多少？

**传统约 20 个工作日，AI PPT+ 半天到一天可完成主体**。
- **传统方式估算**：一张重点内容页认真做接近一天，24 页 PPT 中约 **20 页**需重点设计，约 20 个工作日（非严格工时 Benchmark）。
- **AI PPT+ 耗时**：主体半天到一天；真正花时间的是第一次研究方法，方法沉淀后可反复复用。

### 🔍 补充细节
- **方法论的通用启示**：不要让一个模型包办所有事，内容理解、视觉设计、工程还原、确定性规则、最终判断，**每层只做自己最擅长的事**，把不同能力编排成自己的工作系统。
- **未来迭代空间**：图像模型、Agent 速度、多模态能力还会进步，现在的中间步骤未来可能被模型自动完成，但当前这套方法已可直接复用。
