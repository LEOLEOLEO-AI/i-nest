# 华为ISCAS 2026报告：τ定律与数据中心芯片的逻辑折叠之路

### 🏆 这份报告核心讲了什么新理论？

提出**τ定律（Tau Law）**，替代摩尔定律，从几何微缩转向**时间维度微缩**。
- **核心逻辑**：半导体进步不只是工艺缩小 → 最终都沉淀为时间缩短（更快开关、更快响应）。
- **路径方向**：系统 → 芯片 → 电路 → 器件，四层逐层折叠压缩时间开销。
- **当前重点**：前三层（系统/芯片/电路）已落地实践，器件级（类3D NAND原生3D）尚不成熟。

### 📊 为什么要做系统级折叠？

AI模型规模**8年增长10万倍**，单芯片已无法承载，瓶颈在互联。
- **模型规模演进**：
  - 2018年 BERT-Large：0.34B（亿级）
  - 2020年 GPT-3：175B（千亿级）
  - 2024年 GPT-4o：2T+（万亿级）
  - 2026年 Claude Mythos5：10T（十万亿级）
- **核心矛盾**：模型越大，瓶颈越不在单芯片算力，而在**成千上万芯片的协同效率**。
- **目标定义**：System Folding = 用UB总线把NPU/CPU/存储连起来 → 让数千芯片像**一颗巨型芯片（Giant Chip）** 一样工作。

### ⚡ 昇腾910C + DeepSeek-V3 实践效果如何？

在50ms延迟约束下，单卡吞吐达**1920 Token/s**，通信占比仅23%。
- **专家并行部署**：
  - EP规模从16扩到288 → 单芯片权重从55GB降到4GB
  - 50ms TPOT（每Token延迟）下，单卡支持96用户 → 1920 TPS
- **低延迟模式**：单卡用户降到30以内 → 延迟低至**17ms**（约60 Token/s）
- **通信开销**：推理全程通信占比**23%**，业界普遍水平 >40%
- **成本测算**：DeepSeek-V3 成本约 **1元/百万Token**，显著低于OpenAI的十美元以上水平

### 🔧 系统折叠怎么解决MoE通信风暴？

用UB总线的**Posted Write**机制，把海量小包通信降维成内存写操作。
- **"平安信"问题**：MoE中96%的通信是2bit的"未选中"通知包，而非选中的7K-14K数据包。
  - 288卡 × 256专家 × 96用户 = 每层**700万小包**，传统网络会形成All-to-All拥塞风暴。
- **UB互联方案**：
  - 基于全局地址直接写入专家内存窗口，无需复杂寻址/打包/解析
  - 片间通信复用片内总线Store行为，把通信风暴降维成处理器写动作

### 🚀 未来超节点路线图是怎样的？

从910C到960 SuperPod，规模和带宽**指数级扩张**，引入硅光互联。

| 代际 | NPU数量 | 总带宽 | 年份 |
| :--- | :--- | :--- | :--- |
| 昇腾910C SuperPod | 384 | 301 TB/s | 2024 |
| 昇腾950 SuperPod | 8,192 | 16.3 PB/s | 2026 |
| 昇腾960 SuperPod | ≥16,384 | >16 PB/s | 2028 |
- **关键技术**：Hi-One 8T硅光引擎，单芯片**8Tbps/方向**光带宽，支持224G×36Lane每端口
- **拓扑优化**：FatTree ↔ Mesh ↔ Clos 可重构光交换，实现连线折叠与拓扑折叠

### 💡 补充细节
- **报告背景**：华为Fellow夏菁在ISCAS 2026上的分享，主题为数据中心芯片设计实践与工程取舍。
- **τ定律四层时间尺度**：系统级ms→s、芯片级μs→ms、电路级ns→μs、器件级ps→ns。
- **MoE部署反常识**：云端部署MoE时，因多用户专家选择随机，最终仍需激活全部专家，核心收益来自专家分散部署+低通信开销。
