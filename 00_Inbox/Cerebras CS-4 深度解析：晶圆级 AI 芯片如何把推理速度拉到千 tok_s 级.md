# Cerebras CS-4 深度解析：晶圆级 AI 芯片如何把推理速度拉到千 tok/s 级

### 🚀 CS-4 是什么，核心参数有多强？

CS-4 是**3 片 WSE-3 Turbo 晶圆**组成的机柜级 AI 推理系统，主打**单用户低延迟**。
- **发布信息**：2026 年 8 月 18 日，Cerebras 在 Supernova 2026 上推出。
- **单片 WSE-3 Turbo**：
  - 晶圆面积 **46,225 mm²**，4 万亿晶体管，900,000 个 AI core
  - 44GB 片上 SRAM，**250 PFLOPS** 稀疏 FP16 算力
- **系统级（3 片）**：
  - 总算力 **750 PFLOPS**
  - 内存带宽 **129.6 PB/s**
  - 片上 fabric 带宽 160.5 PB/s
  - I/O 带宽 7.2 Tbit/s
  - wafer-to-wafer 延迟 **2 微秒**

### ⚡ 为什么要做晶圆级路线，瞄准 GPU 哪个痛点？

GPU 集群的**单用户 decode 延迟**被多芯片搬运拖慢，Cerebras 用整片晶圆减少「过桥税」。
- **GPU 集群矛盾**：模型切到多芯片 → 每生成一个 token 都要在显存、互联、调度间来回传输 → 吞吐能靠 batch 堆，但单用户速度上不去。
- **Cerebras 思路**：把权重、计算、通信尽量留在一整片晶圆内部，减少跨芯片、跨节点的搬运开销。
- **产品演进**：CS-1 → CS-2 → CS-3 验证「大芯片能跑」，CS-4 是**从能跑到能大规模部署**的一代。

### 📊 推理速度到底有多快，和 GPU 比怎么样？

官方称 CS-4 推理最高比 GPU 快 **30 倍**，10T+ 模型可超 **1000 tok/s decode**。
- **官方对比数据（每用户 tokens/s）**：

| 模型 | CS-4 表现 | 核心结论 |
| :--- | :--- | :--- |
| Gemma 4-31B | ~3600 | 大幅领先 GPU |
| Llama 3.3 70B | ~3700 | 大幅领先 GPU |
| GPT-OSS-120B | ~4500 | 速度最高 |
| GLM 4.7-355B | ~2050 | 仍超千 tok/s |
| Kimi K2.7 1T | ~2050 | 仍超千 tok/s |
| GPT 5.4 | ~1550 | 仍超千 tok/s |
| GPT 5.6 SOL | ~1400 | 仍超千 tok/s |
- **Kimi K3 推算**：K3 是 2.8T 总参数、约 104B active 的 MoE；vLLM 在 16 张 GB300 NVL72 上最高 370 tok/s per user → 按 CS-4 「10T+ 模型超 1000 tok/s」口径推算，K3 至少有 **2.7 倍提速空间**。
- **对 agent 的意义**：模型生成→调工具→读结果→再生成，每一环慢一点，用户感知都会被放大；快会直接改变用户愿不愿意连续交互。

### 🔗 2 微秒互联怎么实现，架构上有什么新设计？

CS-4 用 **Direct Wafer Links** 实现晶圆间低延迟，还支持**解耦推理**分工。
- **两种连接模式**：
  - RoCE v2 RDMA over Ethernet：标准化接入
  - Direct Wafer Links：机柜内/跨机柜无交换机直连，延迟低至 **2 微秒**
- **解耦推理（disaggregated inference）**：
  - prefill（处理输入上下文）→ 交给通用系统（如 AMD Helios、AWS Trainium）
  - decode（逐 token 生成）→ 交给 Cerebras 晶圆级引擎
- **定位**：Cerebras 不打算吃下全部 AI 计算，只卡住**最影响交互体验的 decode 段**。

### ❄️ 整片晶圆怎么散热，工程难点在哪？

CS-4 采用**直液冷夹层结构**，把散热做成系统架构的一部分。
- **散热挑战**：单晶圆面积远大于 GPU，总热量可达十几到二十多千瓦，普通风冷兜不住；还要保证整片温度均匀，避免局部热点拖垮频率和可靠性。
- **封装思路**：晶圆、连接层、PCB、冷板压成大面积夹层 → 热从晶圆表面导入冷板 → 由 manifold 分配冷却液带走。
- **额外难题**：硅、铜、PCB 热膨胀系数不同，放大到整片晶圆后，热循环形变会影响良率和寿命。
- **CS-4 方案**：把晶圆、供电转换、直液冷、高速 I/O、控制电子全部塞进 Wafer-Scale Backpack，散热与供电、I/O、封装一体化设计。

### 📦 Nexus 机柜有什么改进，怎么走向大规模部署？

Nexus 平台**组件减半、部署从天降到小时**，把晶圆级芯片做成数据中心标准模块。
- **三大模块**：Compute、Power、I/O
- **工程化改进**：
  - 组件数量减少 **50%**
  - 自动化制造比例提升 **60%**
  - 部署时间从「天」降到「小时」
- **供电优化**：供电距离处理器仅 **0.5 毫米**，对比传统 GPU 板约 50 毫米，接近 100 倍更近 → 减少传输损耗。
- **核心逻辑**：同时缩短**电路径**和**热路径**，适配当前电、液冷、调试、产能、维护都稀缺的数据中心现状。

### ❓ 有哪些争议和待验证的问题？

CS-4 的速度优势有前提，**成本、可靠性、并发换算**还需验证。
- **官方边界说明**：30 倍 GPU 对比依赖具体 workload、配置、日期和模型；实际推理速度随测试条件变化。
- **社区追问**：
  - 单用户 tokens/s 与高并发总吞吐如何换算
  - 大模型跨 wafer 后互联成本怎样计算
  - token 消耗、缓存缺失、请求限流、模型更替对生产迁移的影响
- **时间节点**：首批出货从 2026 年第三季度开始，第三方大规模实测、成本曲线、长周期可靠性待客户部署后验证。

### 📝 补充细节
- **Cerebras 动态**：CEO Andrew Feldman 反复强调速度是 agent 体验核心，并称 Cerebras 正在为 OpenAI 前沿模型提供高速推理。
- **行业趋势**：AI 基建比拼点正在从「卡的数量、峰值算力」转向「每个 token 抵达用户的速度、成本和稳定性」。
