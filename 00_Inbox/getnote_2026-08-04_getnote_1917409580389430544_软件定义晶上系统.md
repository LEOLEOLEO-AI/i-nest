# 软件定义晶上系统

好，我把方案聚焦到晶上系统场景。先检索一下晶上系统、软件定义晶上系统（SDSoW）、芯粒互联等相关资料，确保方案贴合晶上的技术语境。下面是聚焦晶上系统场景的 TCC（拓扑中心计算）总体方案。核心定位：**在 NCCL 集合通信能力的基础上，融合软件定义晶上系统（SDSoW）的全维可定义互联能力，发展晶圆级拓扑中心计算新范式**——让数千个芯粒的互连拓扑从"出厂固定"变为"软件按需定义"，实现"以算定拓扑、以拓扑促算"的晶上系统架构跃迁。

---

## 一、背景与定位：为什么晶上系统必须走向 TCC

### 1.1 晶上系统的核心矛盾

软件定义晶上系统（SDSoW）将数千个异构芯粒集成在整片晶圆上，通过晶圆基板实现高密度互连，在 28nm 工艺条件下算力密度较传统方案提升 3 个数量级 。但晶上系统面临一个根本性挑战：

> **应用需求的多样性 vs 互连拓扑的固定性之间的矛盾。**

传统芯粒系统（Chiplet）的互连拓扑在设计时就已确定——Mesh、Ring、Fat-Tree 二选一，流片后无法更改 。而不同计算任务的通信模式差异极大：
- 大模型数据并行 → All-Reduce 主导，需要 Ring/分层 Ring 拓扑
- MoE 模型 → All-to-All 主导，需要全互连/胖树拓扑
- 张量并行 → All-Gather 主导，需要高带宽 Mesh 拓扑
- 流水线并行 → 线性链拓扑最优

固定拓扑只能在某一类 workload 上接近最优，其他场景下链路利用率不足 40% 。

### 1.2 TCC 的核心主张

拓扑中心计算（Topology-Centric Computing, TCC）的核心主张是：**拓扑不再是硬件给定的约束，而是可以被软件动态编排的第一类计算资源**。

在晶上场景下，TCC 依托 SDSoW 的软件定义互连（SDI）能力 ，通过晶圆级可重构开关矩阵（CBRAM、Flash 开关或有源中介层路由），实现芯粒级拓扑的软件定义与运行时重构，使拓扑形态与计算任务的通信模式精准匹配。

这与 SDSoW 提出的"应用驱动动态架构重构（ADR）"理念一脉相承——ADR 是系统级范式，TCC 是其中拓扑维度的具体方法论 。

### 1.3 与 NCCL 的关系

NCCL 是 TCC 在集合通信层面的**执行引擎**，TCC 是 NCCL 在晶上场景的**拓扑大脑**：

- NCCL 解决"给定拓扑下如何高效通信"的问题（Ring/Tree 算法、多协议优化）
- TCC 解决"应该用什么拓扑来通信"的问题（拓扑编排、动态重构、计算-拓扑协同）
- 两者结合：TCC 定义拓扑 → NCCL 在最优拓扑上跑满带宽

## 二、晶上 TCC 总体架构

### 2.1 四层架构

```
┌──────────────────────────────────────────────┐
│   应用层：AI 框架 / 科学计算 / 信号处理        │
├──────────────────────────────────────────────┤
│   TCC 拓扑中心计算引擎（核心新增）             │
│  ┌──────────┬──────────┬─────────────────┐  │
│  │通信模式   │拓扑-算法  │ 拓扑感知芯粒     │  │
│  │识别引擎   │匹配引擎   │ 映射与调度器     │  │
│  └──────────┴──────────┴─────────────────┘  │
├──────────────────────────────────────────────┤
│   晶上 SDI 控制面（软件定义互联控制器）        │
│  全局拓扑管理 · 开关矩阵配置 · 健康监控        │
├──────────────────────────────────────────────┤
│   NCCL-W 晶上集合通信层（NCCL 晶上适配版）     │
│  集合通信原语 · Ring/Tree 算法 · 多协议       │
├──────────────────────────────────────────────┤
│   晶上硬件基座：芯粒 + 可重构互连 + 开关矩阵   │
└──────────────────────────────────────────────┘
```

### 2.2 硬件基座：晶上可重构拓扑的物理基础

晶上 TCC 的物理前提是**晶圆级可重构互连网络**。当前已有多条技术路线可支撑：

- **CBRAM 开关矩阵**：基于导电桥接随机存取存储器的无源交叉开关，支持 30GHz 带宽、插入损耗 <3.8dB，静态功耗为零，适合晶上无源中介层的可重构互连 
- **Flash 开关单元**：2T p 沟道 Flash 单元，面积小、信号传输能力强，适合存算一体芯粒的可重构互连 
- **有源中介层可重构路由**：在中介层中集成可重构节点（RN），支持动态旁路和网络重构，HiRe 架构已验证可降低 14%-45% 的能耗延迟积（EDP）
- **小世界光互连**：晶圆级可重构光互连架构，基于小世界理论优化长程链路，64 节点规模下延迟比 Mesh/Torus 降低 40%/21% 

**TCC 不绑定具体物理实现，而是向上提供统一的拓扑可编程抽象**。

## 三、核心功能模块（晶上场景聚焦版）

### 3.1 NCCL-W：晶上集合通信适配层

**定位：** 将 NCCL 从"板级/机架级"迁移到"晶圆级"，作为 TCC 的数据面执行引擎。

**核心工作：**

1. **晶上拓扑发现与注入接口**
   - 扩展 NCCL 的拓扑发现机制，支持芯粒级（而非 GPU 级）的拓扑探测
   - 新增**拓扑注入接口**：TCC 引擎可主动写入虚拟拓扑，替代自动探测结果——这是 TCC 能"定义拓扑"的关键入口
   - 支持多层拓扑抽象：芯粒内 NoC → 芯粒间互连 → 晶圆间互联

2. **晶圆级集合通信算法优化**
   - Ring/Tree 算法的晶圆级适配：针对晶圆上 2D Mesh/Torus 物理拓扑（类似 Cerebras WSE 的结构），优化 Ring 的构建路径和 Tree 的分支策略
   - 支持 Switch-Less Dragonfly 等晶圆级直连拓扑的集合通信算法 
   - 分层集合通信：芯粒内（NoC）→ 芯粒间（晶上互连）→ 晶圆间，三层协同

3. **动态拓扑重配钩子**
   - 运行时支持拓扑变更通知与 communicator 热重建
   - 重配期间的通信状态保存与恢复

**工作量（软件）：** 约 6-8 人月。

### 3.2 晶上 SDI 控制器

**定位：** 晶圆级拓扑资源的统一操作系统，向下管理可重构开关矩阵，向上提供拓扑可编程接口。

**核心模块：**

1. **晶圆级拓扑数据库**
   - 全晶圆芯粒-链路-开关的统一建模（千级芯粒、万级链路规模）
   - 多粒度视图：物理拓扑（开关级）、逻辑拓扑（芯粒级）、虚拟拓扑（任务级）
   - 健康状态管理：基于心跳包的链路/路由器故障检测 ，缺陷芯粒/链路的自动旁路

2. **开关矩阵配置引擎**
   - 将 TCC 下发的虚拟拓扑需求转化为具体开关配置（CBRAM/Flash/有源路由寄存器）
   - 增量配置：只修改变化的链路，最小化重配开销
   - 配置验证：配置后回读确认，确保拓扑正确性

3. **晶圆级拓扑模板库**
   - 预置经典拓扑模板：
     - **Ring / 分层 Ring**：适合 All-Reduce 数据并行
     - **Mesh / Torus**：适合 2D 网格类并行（如张量并行、Stencil 计算）
     - **Fat-Tree / 胖树**：适合 All-to-All（MoE、参数服务器）
     - **全互连（Crossbar）**：小规模高带宽需求场景
     - **小世界拓扑**：长程链路优化的低延迟拓扑 
     - **Dragonfly（无交换机版）**：大规模直连拓扑 
   - 每个模板附带参数化生成器（维度、度数、链路带宽分配）

4. **多任务拓扑隔离与调度**
   - 晶圆级资源分区：一片晶圆同时跑多个任务，各自拥有独立虚拟拓扑
   - 拓扑资源的时分复用/空分复用调度

**工作量（软件 + 硬件接口）：** 约 12-15 人月（软件 8-10 人月，硬件驱动 4-5 人月）。

### 3.3 TCC 拓扑中心计算引擎（核心创新层）

**定位：** 晶上系统的"拓扑大脑"，实现计算任务-互连拓扑-集合通信的全链路协同优化。

**核心模块：**

1. **通信模式识别引擎**
   - 静态分析 + 运行时 profiling，识别任务的通信特征矩阵
   - 分类维度：集合通信类型分布、消息大小分布、通信-计算比、同步频率、空间局部性
   - 支持并行策略自动识别：数据并行 / 张量并行 / 流水线并行 / MoE 并行 / 混合并行 

2. **拓扑-算法匹配引擎**
   - 为不同通信模式匹配最优拓扑形态 + NCCL 算法参数
   - 匹配策略库（示例）：

| 计算场景 | 通信模式 | 推荐拓扑 | 推荐 NCCL 算法 | 带宽分配策略 |
|---|---|---|---|---|
| 数据并行训练 | All-Reduce 主导 | 分层 Ring | Ring + LL/LL128 | 均匀分配 |
| MoE 训练 | All-to-All 主导 | Fat-Tree / 全互连 | Tree + 多通道 | 热点链路加倍 |
| 张量并行 | All-Gather 主导 | 2D Mesh | Ring + 分层 | 邻近链路优先 |
| 流水线并行 | P2P 线性 | 链状拓扑 | P2P + 流水线调度 | 相邻芯粒高带宽 |
| 推理服务 | 低延迟单播 | 小世界拓扑  | 按需 | 长程链路保障 |

   - 支持基于强化学习的拓扑寻优（针对复杂混合场景）

3. **拓扑感知芯粒映射器**
   - 将计算任务（算子/层/进程）映射到具体芯粒上，使通信密集的芯粒在拓扑上邻近
   - 联合优化：拓扑选择 + 芯粒放置 + 路由规划，三者协同寻优
   - 支持异构芯粒混合映射：计算芯粒、存储芯粒、I/O 芯粒的拓扑组织 

4. **运行时拓扑重配控制器**
   - 触发时机：训练阶段切换（前向/反向/重计算）、并行策略变化、业务负载迁移
   - 重配流程：状态冻结 → 增量配置 → 拓扑验证 → 通信恢复
   - 目标重配时延：微秒级（CBRAM/Flash 开关 ns~μs 级切换）
   - 预配置与预测：基于卡尔曼滤波的流量预测，提前准备下一个拓扑配置 

5. **计算-拓扑协同优化器（前沿探索）**
   - 不只是"给定计算优化拓扑"，而是**联合优化计算并行策略和互连拓扑**
   - 例如：在晶圆面积约束下，联合决策"用多少计算芯粒 + 用多少存储芯粒 + 用什么拓扑连接 + 采用什么并行策略"
   - 目标函数：端到端吞吐 / 时延 / 能效 / 晶圆利用率
   - 对应 SDSoW 中的"涌现智能"方向：大规模异构系统的结构内生多样性可能催生出涌现智能 

**工作量（软件）：** 约 15-18 人月。

### 3.4 晶上物理智能与拓扑协同（前瞻方向）

**定位：** 将 TCC 与你提出的"晶上物理智能"方向结合，探索拓扑层面的类脑计算新范式。

**核心思路：**

- **拓扑即计算**：利用晶上互连网络的拓扑形态本身实现计算功能（如拓扑光子计算、神经形态网络的拓扑结构）
- **动态拓扑演化**：借鉴脑网络的可塑性，让晶上拓扑在学习过程中自适应演化（类似 Hebb 规则的"连得通就加粗"）
- **对称性破缺与拓扑相变**：探索晶上拓扑相变与智能涌现之间的关系（对应你关注的对称性破缺与智能涌现机制方向）

**工作量（研究探索）：** 约 8-10 人月（偏理论+仿真，适合作为前沿研究方向）。

## 五、实施计划（晶上场景四阶段，共约 24 个月）

### 第一阶段：FPGA 原型验证（第 1-5 个月）

**目标：** 在 FPGA 阵列上验证"拓扑可重构 + NCCL 集合通信"的技术路径。

- 搭建 64-128 节点 FPGA 仿真平台（模拟晶圆上百芯粒规模）
- 实现 NCCL-W 基础版（拓扑注入接口 + Ring/Tree 算法适配）
- 实现基础版晶上 SDI 控制器（静态拓扑配置 + 3-5 种拓扑模板）
- 在 All-Reduce 场景下对比"固定 Mesh 拓扑"vs"TCC 优化 Ring 拓扑"的性能差异
- **里程碑：** FPGA 原型验证通过，TCC 优化的 All-Reduce 吞吐比固定 Mesh 提升 30%+

**投入：** 8-10 人（软件 5-6 人，硬件 3-4 人）。

### 第二阶段：晶上 SDI 控制面 + 动态重构（第 6-12 个月）

**目标：** 建成完整的晶上 SDI 控制面和运行时拓扑重构能力。

- 开发完整晶上 SDI 控制器（拓扑数据库 + 开关配置引擎 + 健康监控）
- 实现运行时拓扑动态重配（增量配置、微秒级切换）
- 扩展拓扑模板库（Ring/Mesh/Fat-Tree/小世界/Dragonfly 等 8+ 种）
- 实现多任务拓扑隔离
- 在 256-512 芯粒仿真规模下验证多种典型场景
- **里程碑：** 拓扑重配时延 <10μs；典型 AI 训练场景端到端性能提升 25%-40%

**投入：** 12-15 人。

### 第三阶段：TCC 协同引擎 + 计算-拓扑闭环（第 13-19 个月）

**目标：** 实现计算-拓扑-通信的全链路协同优化。

- 开发通信模式识别引擎和拓扑-算法匹配引擎
- 实现拓扑感知芯粒映射器
- 开发运行时拓扑重配控制器（含预测式预配置）
- 与主流 AI 框架集成，在大模型训练/推理任务中验证
- 完成与真实晶上芯片的联调（如果有流片计划）
- **里程碑：** 在 LLM/MoE 典型 workload 中，端到端吞吐提升 30%-50%，能效比提升 2 倍以上（对标固定拓扑方案）

**投入：** 15-18 人。

### 第四阶段：物理智能前瞻 + 生态化（第 20-24 个月）

**目标：** 探索拓扑中心计算的前沿方向，形成技术壁垒和生态影响力。

- 晶上物理智能与拓扑协同的原理验证
- 对称性破缺、拓扑相变与智能涌现的仿真探索
- TCC 开源：NCCL-W + 晶上 SDI 控制器 + TCC 引擎核心模块开源
- 发布晶上 TCC 技术白皮书，推动成为晶上系统联盟标准方向
- **里程碑：** 物理智能方向产出 2-3 篇高水平论文；开源社区初步建立；形成 1-2 项联盟标准提案

**投入：** 10-12 人。

## 七、关键技术风险与应对

| 风险 | 影响 | 应对策略 |
|---|---|---|
| 晶上可重构开关技术不成熟 | 高 | 多路线并行：CBRAM、Flash 开关、有源中介层三路探索；前期用 FPGA 验证架构，不绑定单一物理实现 |
| 拓扑重配开销抵消收益 | 中 | 第一阶段量化重配时延；设计增量重配、预配置、预测式切换；只在粗粒度阶段切换 |
| 千芯粒规模的拓扑寻优复杂度高 | 中 | 分层策略：全局粗粒度（模板匹配）+ 局部细粒度（启发式优化）；避免全规模暴力搜索 |
| 流片成本高、周期长 | 高 | FPGA 先行验证 → 小批量 MPW 试错 → 全功能流片；与海河实验室/苏州实验室等平台合作 |
| 良率与缺陷管理 | 中 | 拓扑层面天然支持缺陷旁路（SDI 控制器自动绕开故障芯粒/链路）；将良率管理纳入 TCC 调度框架 |
