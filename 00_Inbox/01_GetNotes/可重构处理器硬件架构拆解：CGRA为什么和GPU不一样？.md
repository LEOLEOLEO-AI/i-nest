# 可重构处理器硬件架构拆解：CGRA为什么和GPU不一样？

### 🔄 可重构处理器的设计思路和GPU有什么根本不同？

GPU是**硬件先定型、软件来适配**，可重构处理器是**先定义理想AI硬件、再倒推硅片实现**。
- **设计起点**：基于深度学习三大特征——**确定性数据流**、非集中式数据访问、不同算子底层计算单元共通。
- **核心差异**：从计算引擎、数据流、存储到多卡扩展，几乎每个层面都和GPU不同。

### ⚙️ 计算核心为什么要做"双引擎"？

**CGRA Tensor 扛大头计算，CGRA Vector 处理长尾算子**，两者分工协同。

| 引擎 | 定位 | 适用场景 |
| :--- | :--- | :--- |
| CGRA Tensor | 脉动计算阵列 | 矩阵乘、卷积等规则密集计算 |
| CGRA Vector | 可重构PE阵列 | 激活、归一化等不规则计算 |
- **CGRA Tensor**：大模型**90%以上**计算是矩阵乘加（MAC），数据沿阵列行列脉动前进，每到一个交叉点做一次乘累加。
  - 预填充完成后，**每个时钟周期**输出一组结果，无需指令调度、缓存查询、分支判断。
  - 解决GPU痛点：GPU Tensor Core需要程序员手动处理K维分块、Fragment管理、累加逻辑，可重构处理器把这些控制逻辑固化进数据通路，**数据流本身就是调度器**。

- **CGRA Vector**：处理element-wise等"长尾"操作，核心是**可重构互联网络**。
  - PE（处理单元）之间连线可动态改变，**微秒级**切换成不同算子的专用流水线。
  - 不靠指令切换，靠配置信息写入新的互联关系和PE功能，同一块硅片可"变身"不同加速器。
  - 数据直接流过"临时专线"，无需写回内存再读出，消除中间开销。

### 📡 没有指令，计算单元怎么知道什么时候工作？

**数据到，计算就触发**，靠"算力网格数据流"结构实现。
- **算力网格**：计算阵列是二维网格，每个Tile（计算单元）有确定空间位置，相邻Tile通信成本更低。
  - 任务分配原则 = 让连续的计算落在相邻的Tile上
- **数据流**：编译器提前把算法转成**数据流图（DFG）**，映射到PE阵列上，每个PE知道从哪收数据、做什么计算、发往哪个邻居。

- **GPU vs 可重构处理器**：
  - GPU = **时间复用** → warp调度器决定下一个谁跑，靠线程切换隐藏长延迟
  - 可重构处理器 = **空间展开** → 计算直接铺在二维阵列，数据从上游流到下游，没有"该谁跑"的问题
  - 本质区别：GPU的warp切换是对"访存延迟不可预测"的兜底，AI场景访存模式**可预测**，可重构处理器把延迟吸收进计算流水线，不需要Scoreboard跟踪寄存器依赖等机制。

### 💾 存储体系为什么不是缓存而是流水线？

因为**访存模式可预测**，不需要靠缓存"猜"下一步访问什么，直接做单向数据流水线。
- **GPU存储体系**：Register→L1 Cache/Shared Memory→L2 Cache→HBM，多级缓存+显式管理，命中则快、不命中则加倍慢。
- **可重构处理器三级数据通路**：

| 层级 | 通路 | 特点 |
| :--- | :--- | :--- |
| 系统级 | 3D DRAM → SPM | 大粒度搬运、低频 |
| 阵列级 | SPM ↔ CGRA | 流式灌入、批次流动 |
| 片内级 | PE间直连 | 低延迟、高确定性 |
- **第一级（系统级）**：3D DRAM通过3D封装（TSV/Hybrid Bonding）和计算逻辑垂直堆叠，把计算和存储的物理距离从**厘米级铜线**缩短到**微米级金属柱**，只做大批量数据搬运。
- **第二级（阵列级）**：SPM（片上存储）**不是缓存**，是数据流图中的显式节点，充当流水缓冲、窗口缓冲或复用缓冲，数据以流式方式灌入计算阵列，不是随机访问。
- **第三级（片内级）**：PE之间直接连，上游PE输出直接流入下游PE输入，不需要绕道中间存储。

### 🖇️ 多卡扩展为什么是"拼计算图"而不是"复制执行"？

可重构处理器把多卡抽象成**统一的数据流算力平面**，扩展性内建于全栈架构。
- **GPU多卡逻辑**：每张卡是完整封闭的机器，跨卡通信是"例外事件"，靠NCCL显式触发批量同步（all-reduce/all-gather），本质是线程并行的延伸。
- **可重构处理器多卡逻辑**：遵循**"Scale-First"**原则，形成**"Tile→Die→Chip→Pod"**全栈扩展范式。
  - **单芯片内部**：Tile（带独立计算和本地缓存）→ Die（片上网络互联）→ Chip（Die-to-Die互联融合），单颗芯片本身就是小规模集群。
  - **芯片间扩展**：专用**TSM-Link高速端口**，内置片上路由和融合通信协议栈，**不需要交换芯片**，消除层级转发延迟和交换机成本。
  - 原生支持Mesh（网格）与Torus（环面）拓扑，理论可构建**256×256（65536颗芯片）**的计算网络，远大于典型交换范式组网规模。

- **三层扩展能力**：
  - 卡内：Tile阵列就是算力网格，数据按DFG流动
  - 卡间：多张卡拼成更大的CGRA，支持单向流水、双向流水、多播
  - 机柜间：机间链路建模为"高延迟、低带宽但确定性的数据流边"，编译器在DFG中显式插入latency padding和buffering PE，把跨机延迟吸收进流水线

说白了，GPU遇到跨机超长延迟靠线程切换藏不住，可重构处理器直接在编译阶段就算好延迟有多长，提前给它留好位置。

### 🎯 两种架构最核心的取舍是什么？

**不要把"灵活处理不确定性"的代价，强加给"确定性的计算"**。

| 维度 | GPU设计逻辑 | 可重构处理器设计逻辑 |
| :--- | :--- | :--- |
| 驱动模型 | 指令驱动 | 数据流驱动 |
| 延迟处理 | warp调度隐藏延迟 | 编译器预规划流水线 |
| 存储体系 | 层级缓存（L1/L2/L3） | 三级流水线数据通路 |
| 跨卡通信 | 外部事件 | 计算图的一个边 |
| 存储架构 | HBM集中共享存储 | 3D存算+分布式SPM |
- GPU是为"不确定"设计的机器，AI是"确定"的计算问题，为AI定制的硬件可以更简洁、更高效、更可预测。
