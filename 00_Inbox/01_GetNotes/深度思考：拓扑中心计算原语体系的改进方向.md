# 深度思考：拓扑中心计算原语体系的改进方向

## 核心判断

对照集合通信四大原语的成熟体系，拓扑中心计算的原语定义当前面临三个根本问题：

1. **拓扑依赖性未显式建模**——原语仍是功能描述而非结构描述，拓扑只是约束条件而非一等公民
2. **缺少"拓扑操作"原语层**——现有原语全是数据操作，没有对拓扑本身进行操作的原语
3. **性能映射不闭合**——无法从拓扑结构参数直接推导原语性能下界，依赖经验实测

---

## 三层改进路径

### 第一层：把数据原语"拓扑化"

将四大原语从"数据移动模式"重新定义为"拓扑流模式"：

| 传统定义 | 拓扑中心定义 | 拓扑签名 |
|---|---|---|
| All-Gather | 沿拓扑轴的信息扩散 | 直径 × 轴数，流水效率取决于周长/直径比 |
| Reduce-Scatter | 沿拓扑轴的信息汇聚 | All-Gather 的拓扑流向对偶 |
| All-Reduce | 扩散+汇聚的复合 | 2× 单原语代价（可被网内计算折减） |
| All-to-All | 拓扑空间中的置换 | 复杂度与拓扑直径正相关 |

**关键**：每个原语必须附带"拓扑签名"——在什么拓扑下达到下界、退化条件是什么、退化倍率是多少。

### 第二层：新增拓扑操作原语

这是拓扑中心计算区别于传统集合通信的本质差异：拓扑本身是可重构的计算资源。

**需新增的原语类别**：

- **拓扑重构类**：reconfigure / split / merge / wrap / unwrap
  - 代价度量：不是数据量，而是拓扑变化的能量/时间/面积开销
- **拓扑嵌入类**：embed / project / unfold
  - 将逻辑拓扑映射到物理拓扑，分层算法是嵌入的特例
- **拓扑度量类**：diameter / bisection / connectivity / curvature
  - 计算拓扑结构属性，直接决定数据原语的性能下界

### 第三层：建立原语-拓扑-性能闭包模型

目标：给定拓扑 G 和原语 P，从 G 的结构参数直接推导性能下界，不需要实测。

**已知经验散点（待统一）**：
- Torus ring: T ≈ D / (N_axes × BW_bi)
- Fat tree: T ≈ D / BW_node（一阶近似）
- Tree 延迟: T ≈ log₂N × t_hop

**统一理论需要回答**：
- 为什么 torus 上 All-Gather 时间与节点数无关？
- 为什么 fat tree 上 All-Reduce 受限于节点注入带宽？
- 为什么 All-to-All 在全连接下比 ring 快近一半？

## 工程实现五大借鉴点

### 1. 带宽层级金字塔必须显式建模

参照 v5e 带宽层级（VMEM→HBM→ICI→PCIe→DCN，每层约一个数量级差），为晶上系统建立对应层级：
- 片上 SRAM/eDRAM → 芯粒间 bump/bridge → 晶圆级互连线 → 封装间 → 板级
- 原语性能模型按"数据穿越层数"累加，不只用最外层带宽

### 2. 延迟/吞吐分界点必须量化

参照 ICI 45 GB/s × 1 μs = 45 KB 分界点：
- 晶上互连每层都算一个"分界消息大小"
- 小于分界：延迟主导，用 tree 类算法（log₂N 步）
- 大于分界：吞吐主导，用 ring 类算法（流水效率高）
- 原语调度器自动按消息尺寸选算法，类似 NCCL

### 3. 利用对偶性减少实现量

All-Gather ↔ Reduce-Scatter 的对偶不是巧合，是拓扑流向的必然：
- 原语框架按"拓扑路径 schedule + 边处理算子"分离
- schedule 由拓扑决定，算子由功能决定，二者正交组合
- 每新增一个扩散型原语，自动得到汇聚型对偶

### 4. 分层算法是规模化必由之路

参照 GPU 分层集合（节点内 NVSwitch + 跨节点 IB + 多层流水）：
- 晶圆级天然分层：芯粒内→芯粒间→晶圆内→晶圆间
- 原语接口增加"拓扑域"参数，运行时自动分层分解+流水调度
- 每层选最优算法，层间时间重叠取 max 而非 sum

### 5. 网内计算加速比必须打折

参照 SHARP 理论 2×、实测 ~1.3× 的教训：
- gap 来源不是算力不足，而是 pipeline 重叠效率
- 晶上网内计算/存内计算的性能模型预留 0.6-0.7 折减系数
- 禁止用理论峰值做架构选型依据，必须实测校准

---

## 三个警惕

1. **警惕换皮陷阱**——如果原语还是那四个、只是改名，就不是范式跃迁。检验标准：拓扑操作是不是计算的一部分
2. **警惕小消息盲区**——类脑/脉冲场景是小消息高频次，延迟主导。只优化大消息吞吐会在目标场景失效
3. **警惕均匀假设**——晶上拓扑因良率、功耗、异构芯粒必然不均匀。原语必须支持非均匀拓扑，不能只在理想拓扑下成立
