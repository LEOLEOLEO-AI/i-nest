# 晶上类脑架构设计

---

## 任务一：晶上类脑系统体系架构与拓扑设计

**牵头单位**：天津大学  
**定位**：基于南湖研究院已有的 NPU/SNN + SoC 融合计算芯粒，定义晶上类脑系统的整体架构、晶圆级互连网络与动态拓扑重构机制，完成互连与接口芯粒规格定义及运行时系统设计，输出全套系统设计规范作为课题二和后续任务的输入。

---

### 2.1.1 核心研究内容

#### （1）面向多阶段任务的晶上类脑系统总体架构设计

**核心问题**：大模型推理 Prefill/Decode 两阶段与类脑脉冲计算对系统资源的需求差异显著，单一固定架构难以同时高效支撑，需要从顶层构建可阶段适配的系统架构。

-   **多阶段任务的资源需求特征分析**
    
    -   大模型推理 Prefill 阶段：计算密集、集合通信为主（All-Reduce / All-Gather）、数据并行度高
        
    -   大模型推理 Decode 阶段：访存密集、激活稀疏（MoE 专家路由）、通信模式不规则
        
    -   SNN 类脑计算：异步事件驱动、时空稀疏、低延迟要求、脉冲多播为主
        
    -   在线学习模式：前向 + 反向 + 权重更新三通路协同、双向流量特征
        
    -   各阶段对计算、存储、互连三维资源的需求矩阵与差异度量化
        
-   **三层架构定义与全局部存储体系**
    
    -   融合计算芯粒 / 互连与接口芯粒 / 晶圆级互连基板的三层架构定义
        
    -   面向 5000 万神经元、512 TFLOPS 的芯粒规模与数量配置
        
    -   **全局部存储架构**：所有存储为计算芯粒 PE 级局部存储，无集中式存储阵列，跨芯粒数据交换完全依赖晶圆级互连网络，系统性能由互连拓扑与数据映射共同决定
        
    -   芯粒类型谱与功能规格定义：计算芯粒、互连芯粒的功能边界与资源配比
        
-   **SoC 控制面与计算面的系统级划分**
    
    -   控制面功能集：全局配置分发、任务调度编排、拓扑重构控制、状态聚合反馈
        
    -   计算面功能集：NPU 张量计算 + SNN 脉冲计算 + PE 级局部存储
        
    -   控制面-计算面交互接口与协同粒度（任务级 / 阶段级 / 帧级）
        
-   **阶段化工作模式与状态定义**
    
    -   大模型推理模式（Prefill 优先 / Decode 优先 / 混合模式）
        
    -   类脑脉冲计算模式（前向传播 / 在线学习 / 状态读出）
        
    -   各模式下的资源配置状态、拓扑形态与切换触发条件

#### （2）晶圆级互连网络拓扑族与动态重构机制

**核心问题**：物理互连是固定的，但任务的通信结构是变化的。如何在一套物理网络基底上，通过逻辑拓扑的动态重构，使互连形态与各阶段的通信需求精准匹配？

-   **物理拓扑基底设计**
    
    -   晶圆级 2D Mesh / 高阶拓扑的物理实现可行性分析
        
    -   长程互连弦的引入与维度优化，降低网络直径与平均跳距
        
    -   物理层设计原则：保守选型、一次做对，为上层重构预留充足链路资源
        
-   **面向多阶段流量的逻辑拓扑族设计**
    
    -   **集合通信优化拓扑**：面向 Prefill 阶段 All-Reduce / All-Gather 的规约树、环形归约、分层聚合拓扑
        
    -   **流水推理优化拓扑**：面向 Decode 阶段流水线的线性链、脉动阵列拓扑
        
    -   **稀疏激活优化拓扑**：面向 MoE 专家路由的全连接子集、置换网络拓扑
        
    -   **脉冲多播优化拓扑**：面向 SNN 层间投射的多播树、区域广播拓扑
        
    -   各类拓扑的性能特征与适用场景分析
        
-   **拓扑-任务的映射与适配机制**
    
    -   任务通信结构特征到逻辑拓扑的匹配算法
        
    -   逻辑拓扑到物理芯粒与链路的资源绑定方法
        
    -   拓扑适配度量化指标：通信跳数、链路利用率、负载均衡度
        
    -   基于强化学习的拓扑-映射联合优化方法
        
-   **动态拓扑重构机制**
    
    -   重构触发条件：阶段边界切换、负载分布变化、故障容错、能效优化
        
    -   **原子重构技术**：双缓冲配置预加载 + 状态翻转机制，实现微秒级拓扑切换
        
    -   重构过程的一致性保证：流量排空、配置同步、状态校验
        
    -   重构开销的量化模型与收益门限分析：切换收益 = 阶段性能提升 - 重构开销

#### （3）混合通信架构与互连芯粒规格定义

**核心问题**：集合通信、脉冲路由、通用包交换三种通信范式如何在同一互连芯粒中一体化实现，共享物理资源又服务不同语义？

-   **三范式混合通信架构**
    
    -   **电路交换通路**：面向持续高频的固定连接，通过交换矩阵交叉点配置建立直通物理通路，零排队延迟、高能效，承载阶段内稳定的核心数据通路
        
    -   **虚电路通路**：面向规则的层间投射与多播流量，基于虚电路标签的快速转发，支持一对多多播，承载脉冲通信与规则数据流
        
    -   **分组交换通路**：面向不规则稀疏流量与控制配置，传统存储转发 / 虫孔路由，承载控制面流量与不规则数据传输
        
    -   三范式的资源分配机制：虚通道空间隔离 + 优先级时间调度，高优先级流量的延迟确定性保证
        
-   **脉冲路由的一体化实现**
    
    -   脉冲包的轻量化格式设计（范式标记 + 虚电路标签 + 源/目的地址压缩）
        
    -   两级路由架构：芯粒间粗粒度路由（互连芯粒承担）+ 芯粒内细粒度路由（计算芯粒承担）
        
    -   区域广播与多播虚电路的协同机制，降低路由表规模
        
    -   脉冲事件的时序保持与乱序处理机制
        
-   **互连与接口芯粒功能定义与微架构**
    
    -   核心功能：多端口高速交换、三范式路由控制、拓扑重构配置、网内计算加速
        
    -   交换矩阵设计：共享交叉矩阵 + 多范式调度器
        
    -   输入/输出端口组织与缓冲结构
        
    -   拓扑重构的硬件加速单元：路由表快速切换、端口重映射、多播表更新
        
-   **网内计算加速机制**
    
    -   面向集合通信的网内规约加速：数据在交换节点中完成聚合运算，减少回传流量
        
    -   面向数据重排的网内置换加速：通过拓扑路径配置直接完成数据置换，无需节点内搬运
        
    -   网内计算与节点计算的协同分工与边界划分
        

---

#### （4）数据流驱动的算网融合执行架构

**核心问题**：计算和网络不是主从关系，而是协同关系。如何在指令和执行模型层面消除"计算指令 + 通信 I/O"的二元划分，让数据流动和计算执行一体化？

-   **数据流驱动的执行模型**
    
    -   基于全局部存储的数据流执行范式：数据到达即触发计算，结果直接从网络端口发出
        
    -   Prefill 阶段的批量数据流调度（高吞吐、规整）
        
    -   Decode 阶段的令牌流调度（低延迟、稀疏）
        
    -   SNN 模式下的脉冲流调度（事件驱动、异步）
        
    -   计算-通信的重叠执行机制：计算与数据传输流水化
        
-   **算网融合指令集定义**
    
    -   指令集分层架构：
        
        -   拓扑配置级指令：阶段拓扑激活、切换、挂起
            
        -   算网融合级指令：远端数据访问 + 本地计算 + 远端发送的一体化指令
            
        -   PE 计算级指令：传统计算指令 + 本地端口操作
            
    -   指令编码方案：操作码域 + 本地操作数域 + 远端源/目的域 + 路由控制域
        
    -   对动态拓扑的原生支持：指令可携带拓扑语义，随拓扑切换自动调整路由路径
        
-   **架构设计空间探索方法**
    
    -   多维度设计空间：芯粒数量、拓扑维度、PE 粒度、局部存储容量、网络带宽、三范式资源配比
        
    -   基于强化学习 / 多智能体的多目标优化算法
        
    -   目标函数：能效比、端到端延迟、吞吐量、面积开销
        
    -   面向 Prefill/Decode/SNN 多场景的 Pareto 最优架构选型
        

---

#### （5）拓扑运行时系统与工具链

**核心问题**：系统运行时如何感知任务阶段、选择最优拓扑、完成动态切换，让物理连接结构与上层任务流图实时匹配？

-   **运行时系统架构**
    
    -   向上接口：类 NCCL 集合通信 API + 拓扑管理 API，对上层框架屏蔽底层拓扑细节
        
    -   中间编排层：任务流图解析 → 通信特征提取 → 拓扑匹配/生成 → 映射优化 → 切换决策
        
    -   向下执行层：拓扑配置下发、重构执行、状态监控、故障恢复
        
-   **拓扑感知的任务映射与流图匹配**
    
    -   任务计算图 + 通信图到物理拓扑的映射优化
        
    -   映射原则：通信密集的算子映射到物理邻近的计算单元，最小化数据移动总距离
        
    -   阶段切换时的拓扑-映射联合重配置机制
        
-   **动态拓扑切换的运行时管理**
    
    -   切换时机的智能决策：基于阶段识别、性能监控、能耗模型的综合判断
        
    -   切换流程的编排：预配置、同步点、状态翻转、验证、恢复
        
    -   多优先级切换策略：紧急切换（故障）/ 阶段切换（规划内）/ 优化切换（渐进式）
        
-   **运行时工具链开发**
    
    -   拓扑配置工具：可视化拓扑编辑、配置生成与预下发
        
    -   性能监控工具：网络利用率、延迟分布、计算单元利用率、拓扑适配度的实时采集
        
    -   拓扑优化工具：基于运行时数据的拓扑库自动调优与新拓扑生成

### 2.1.2 关键科学问题与技术难点

1.  **多阶段通信结构与固定互连的适配问题**：不同任务阶段的通信结构差异巨大，单一固定拓扑必然在多数阶段存在结构性低效，如何通过动态拓扑重构实现阶段级精准适配？
    
2.  **三范式混合通信的统一架构问题**：电路交换、虚电路、分组交换三种范式在资源共享、语义协同、优先级调度上的统一架构设计与高效实现。
    
3.  **算网融合的指令抽象问题**：如何定义合适的指令抽象层次，既消除计算与通信的边界，又不导致指令集膨胀与实现复杂度失控。
    
4.  **动态拓扑切换的低开销与一致性问题**：如何在微秒级完成拓扑重构，同时保证数据一致性、不丢失、不错序。

| 拓扑能力 | 拓扑适配度提升 | 相对固定拓扑平均提升 ≥ 40% |
| 能效  | 系统能效比 | ≥ XX TFLOPS/W（或 TSOPs/W） |
| 运行时 | 集合通信 API 兼容性 | 兼容 NCCL 核心接口语义 |
| 工具链 | 拓扑配置与监控工具 | 完整可用 |
