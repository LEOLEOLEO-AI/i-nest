## 二、报告简介（约500字）

当前AI产业正经历一场深刻的结构性迁移：智能化不再局限于云端数据中心，而是沿着"云—边—端"三级阶梯持续下沉，抵近千行百业的物理现场。这一进程与计算产业从大型机到服务器、从PC到智能手机的历史演进高度同构——每一次计算范式的下沉，都催生了量级更大的产业机会与全新的生态格局。

端边侧AI装备的核心需求是在线推理与实时决策，即具备完整OODA（感知—认知—决策—执行）闭环的具身智能系统。然而，端边场景的异构协议碎片化、系统级集成门槛高、装备迭代周期长等痛点，正在成为AI规模化落地的主要瓶颈。从Hot Chips 2026到谷歌TPU v8、华为昇腾950PR，全球产业界传递的共识清晰而一致：AI系统的性能瓶颈已从单纯算力转向数据搬运与系统互联，网络通信正在成为智能体算力供给的关键变量。

在此背景下，井芯微提出从"卖芯片"向"端边侧AI装备网络互连解决方案"的战略升级：一方面提供异构协议互联芯片与交换芯片的底层供给，另一方面通过网算网存加速与软硬件协同，打造端边侧智能体装备集成的基础网络环境，并依托软件定义架构构建可扩展的产业生态。

本报告将从产业规律、技术趋势、全球案例三个维度系统论证这一方向的必然性，结合井芯微在软件定义晶上系统、晶圆级集成、多模态交换等领域的战略储备，阐释端边侧AI网络互连这一新赛道的产业价值与商业潜力。

### 第一章 趋势判断：AI 正在下沉（4页，10分钟）

**P1 封面**
- 标题：从算力竞赛到互连革命——端边侧AI装备网络互连的新赛道
- 副标题：井芯微战略升级的产业逻辑与实践路径
- 署名：刘勤让 / 国家数字交换系统工程技术研究中心副主任 / 井芯微首席科学家

**P2 核心判断：智能化是一个智能不断下沉的过程**
- 三级阶梯模型：云侧 → 边侧 → 端侧
- **云侧**：大算力Token服务器、云化服务、AI训练与云智能体供给（大厂主导，格局已定）
- **边侧**：区域/园区/工厂级智能中枢，承接云端模型、赋能终端设备（增量主战场）
- **端侧**：传感器、机器人、穿戴设备、物联网终端，AI最终的物理载体（海量节点）
- 历史类比：大型机 → 服务器 → PC → 智能手机 → 物联网/机器人
- *核心论点：AI不会只在云端，它必然走向物理世界的每一个角落*

**P3 为什么是端边侧？——需求侧的三个刚性驱动**
- **实时性刚需**：工业控制（毫秒级）、自动驾驶（百微秒级）、机器人（微秒级）——云端往返时延不可接受
- **数据隐私与主权**：行业数据不出域、不上云——制造、能源、医疗、政务等强监管领域
- **成本结构约束**：海量终端全量回传云端的带宽与算力成本呈指数增长——边缘计算是经济性必然选择
- 小结：端边侧不是云的补充，而是AI产业的下一个增量主阵地

**P4 从"云智能"到"具身智能"——AI的第二增长曲线**
- 第一曲线：云端大模型——参数竞赛、Token经济、云服务模式
- 第二曲线：端边侧具身智能——感知-决策-执行闭环、物理世界交互、装备智能化
- 市场规模预判：端边侧AI装备数量将是云端服务器的百倍量级
- 梅特卡夫定律的视角：节点数N的平方级价值增长

### 第二章 需求锚点：端边侧 AI 的 OODA 闭环与互连瓶颈（5页，10分钟）

**P5 端边侧AI的本质：具身智能的OODA循环**
- OODA定义：Observe（感知）→ Orient（认知）→ Decide（决策）→ Act（执行）
- 云端AI是"脑"，端边侧AI是"完整的智能体"——有感知器官、有神经传导、有决策中枢、有执行机构
- 应用场景图谱：
  - 工业制造：工业机器人、质检装备、智能产线
  - 交通物流：自动驾驶、智能网联、无人配送
  - 能源电力：智能巡检、电网调控、储能管理
  - 低空经济：无人机、eVTOL、低空安防
  - 医疗健康：手术机器人、智能诊断设备
  - 安防应急：智能摄像头、排爆机器人、消防装备

**P6 两大核心问题：做出来 & 迭代快**
- **问题一：如何做这些设备？**
  - 异构协议碎片化：感知用以太网/TSN、计算用PCIe/CXL、控制用RapidIO/FC、存储用NVMe
  - 系统集成门槛高：多芯片、多协议、多厂商，联调周期长
  - 可靠性要求苛刻：工业级/车规级/军品级，远高于消费级
- **问题二：如何迅速迭代升级，成为刚需？**
  - 传统装备研制周期：18-24个月（需求→设计→流片→板级→系统→验证）
  - AI算法迭代速度：周级甚至天级
  - 硬件迭代速度与软件迭代速度的错配，是端边侧AI落地的最大矛盾
- 两个问题的交集：互连网络——既是系统集成的骨架，也是软件定义的抓手

**P7 系统级性能的瓶颈：不在算力，在互连**
- AI工作负载的演变：从计算密集型 → 数据搬运密集型
  - 大模型训练：集合通信（AllReduce/AllGather）占比可达40%-60%
  - 大模型推理：KV Cache访问 + 专家路由（MoE）成为新瓶颈
  - 端边侧推理：多传感器融合 + 实时决策，数据搬运路径更长
- 行业共识：AI系统的性能约束正在从"算不动"转向"搬不动"
- Hot Chips 2026核心议题：从算力热点转向系统互联热点 

**P8 云侧已经验证：网络决定集群效率上限**
- 英伟达的护城河不止CUDA，还有NVLink + NVSwitch + Spectrum-X的完整互连体系
- 万卡级集群的算力利用率：网络质量好的集群可达50%+，差的可能只有20%-30%
- 华为昇腾950PR：互联带宽从784GB/s跃升至2TB/s，新增专门的集合通信DIE 
  - 这不是常规迭代，而是架构层面的范式转变——网络通信正在从"外设"变为"一等公民"

**P9 端边侧的互连挑战：比云侧更复杂**
- 协议生态：云侧以以太网/InfiniBand为主，相对统一；端边侧RapidIO/PCIe/TSN/FC/CAN/LIN异构并存
- 时延要求：云侧微秒级；端边侧百纳秒~微秒级（确定性要求更高）
- 拓扑结构：云侧胖树/Clos，规模大但结构规整；端边侧多样化，嵌入式，规模不等
- 集成形态：云侧板级/机架级；端边侧芯片级/模组级/装备级
- 功耗约束：云侧有数据中心供电；端边侧电池供电/工业环境，功耗预算极紧
- 小结：端边侧的互连问题不是云侧方案的缩小版，而是全新的技术命题

### 第三章 产业佐证：全球巨头的同向布局（8页，20分钟）

**P10 本章导览：从芯片到集群，网络创新无处不在**
- 芯片级：片上网络（NoC）、Die-to-Die互连、集合通信加速
- 板级/机架级：NVLink、CXL、UCIe、板间光互联
- 集群级：InfiniBand、RoCE、3D Torus、OCS光交换
- 端边级：异构协议桥接、时间敏感网络、工业以太网
- *一条主线：互连正在从"连接功能"升级为"系统架构的核心"*

**P11 谷歌TPU v8：训练与推理的双架构与双网络革命**
- 双芯片架构：TPU 8t（训练）+ TPU 8i（推理），首次架构分叉
- **训练侧（8t）**：3D Torus + OCS光交换，最大9600芯片Pod，DCN带宽4倍提升 
  - 每芯片6条ICI链路，组成4×4×4 Cube基础单元
  - OCS光电路交换：MEMS微镜动态重构光路，无需光-电-光转换 
- **推理侧（8i）**：Boardfly拓扑创新 + OCS全互联
  - 针对MoE模型的专家路由特性，从"邻居串门"升级为"全员直连"
  - 最多7跳到达任意芯片，传输效率提升一倍 
  - 推理芯片首次全面部署OCS光交换，推动产业链空间翻倍
- 信号意义：网络拓扑不再是通用设计，而是与工作负载深度协同的架构变量

**P12 谷歌TPU v9：6D Torus架构的极限扩展**
- 从3D Torus到6D Torus：机架内3维 + 机架间3维
- 每芯片ICI链路从6条翻倍至12条，新增6条全部采用光互联
- 最坏通信路径从24跳压缩至12跳，二分带宽提升4倍 
- 光模块配比从1:1.5跃升至1:3，光互联需求翻倍
- 启示：当算力规模突破万卡级，光互联从"可选"变为"必需"

**P13 谷歌的网络协议创新：Aquila + Falcon + Virgo**
- **Aquila协议**：为千节点级紧密耦合集群提供类InfiniBand低延迟
  - 配套TiN（Top-of-rack Network Interface）芯片，蜻蜓式全连接拓扑 
- **Falcon协议**：与英特尔合作，为分布式处理器（DPU）设计低延迟网络接口传输协议
- **Virgo架构**：横向扩展数据中心级以太网架构，连接TPU Pod及各类设备机架
- 启示：谷歌不只是在做AI芯片，而是在做从芯片到数据中心的完整网络体系

**P14 华为昇腾950PR：集合通信DIE的信号意义**
- 架构升级：新增专门的集合通信DIE
- 片间互联带宽从784GB/s提升至2TB/s 
- Atlas 950 SuperPoD：最大可扩展至8192张昇腾卡高速互联 
- 为什么重要？
  - 集合通信（AllReduce/AllGather/ReduceScatter）是大模型训练的性能瓶颈
  - 把集合通信从软件协议栈卸载到专用硬件DIE，是架构层面的重大跃迁
  - 国产算力从"跟跑"到"并跑"的标志性进展
- 信号意义：网络通信正在从"计算的附属"变为"芯片架构的一等公民"

**P15 国产算力集群的网络创新：曙光 + 阿里 + 华为**

**P16 Tenstorrent：Jim Keller的以太网网状互联路线**

  - 每芯片集成以太网端口，芯片间直接以太网互联，无需外部交换芯片

- 对端边侧的启示：如果连云端AI芯片都在走以太网网状互联，端边侧异构协议的统一更需要灵活的桥接与交换方案

### 第四章 赛道定义：端边侧 AI 装备网络互连解决方案（5页，15分钟）

**P18 端边侧的清晰定义与边界**
- **定义**：端边侧是指部署在数据中心之外、靠近物理世界数据源和执行机构的AI计算与通信系统，覆盖从区域级边缘节点到设备级终端的完整谱系。
- **三层边界划分**：
  - **边缘层（Edge）**：园区/工厂/城市级智能中枢，单节点算力从几十卡到几百卡，相当于"缩小版数据中心"
  - **设备层（Device）**：单台智能装备内部的计算与互连系统，如机器人控制器、自动驾驶域控制器、工业PLC
  - **终端层（End）**：传感器、执行器、微控制器等最末端节点，算力有限但数量巨大
- **与云侧的本质区别**：
  - 云侧：算力集中、协议统一、规模效应、以训练和批量推理为主
  - 端边侧：算力分散、协议异构、场景碎片化、以实时推理和闭环控制为主
- **为什么端边侧需要专门的互连方案？**
  - 云侧方案（InfiniBand/RoCE）成本高、功耗大、协议栈复杂，不适合嵌入式场景
  - 端边侧需要的是：低时延、高可靠、低功耗、多协议兼容、小型化的互连底座

**P19 井芯微战略升级：从卖芯片到卖解决方案**
- **旧模式**：芯片供应商——交换芯片、桥接芯片，产品型销售
- **新模式**：端边侧AI装备网络互连解决方案提供商
- 战略跃迁的三个层次：
  - 产品层：从单一芯片到芯片组 + 参考设计
  - 系统层：从硬件到软硬件协同的完整互连方案
  - 生态层：从供应商到生态组织者
- 本质：从"卖零件"到"搭骨架"，从单一产品价值到系统级价值

**P20 解决方案架构：两层供给 + 一个生态**
- **底层硬件供给——互连底座芯片组**：
  - 异构协议互联芯片：RapidIO/PCIe/TSN/FC等多协议桥接与交换
  - 网算网存加速芯片：计算、存储、网络在芯片级融合
  - 时间敏感网络（TSN）交换芯片：工业级确定性时延
- **中层系统能力——装备级集成环境**：
  - 软硬件协同的端边侧智能体装备集成框架
  - 软件定义互连（SDI）架构：硬件资源全维可定义、动态重构
  - 统一编程模型：屏蔽异构协议差异，降低应用开发门槛
- **上层生态构建——类扩大生态**：
  - 依托软件栈和标准接口，聚合联盟成员与客户资源
  - 联合定义未来端边侧AI装备的互连标准与生态
  - 客户越多、生态越厚、转换成本越高

**P21 为什么这是一个新赛道？——与云侧网络的本质区别**

| 维度 | 云侧数据中心网络 | 端边侧AI装备网络 |
|---|---|---|
| 主导协议 | 以太网、InfiniBand，相对统一 | RapidIO/PCIe/TSN/FC/CAN异构并存 |
| 时延要求 | 微秒级（1-10μs） | 百纳秒~微秒级（确定性要求更高） |
| 拓扑结构 | 胖树/Clos，规模大但规整 | 多样化，嵌入式，规模不等 |
| 集成形态 | 板级/机架级 | 芯片级/模组级/装备级 |
| 功耗预算 | 数据中心供电，相对充裕 | 电池/工业供电，功耗约束极紧 |
| 生态格局 | 博通/Marvell/NVIDIA垄断 | 尚无绝对主导者，国产替代窗口 |
| 价值分配 | 网络设备占集群成本10-15% | 互连是装备核心骨架，价值占比更高 |

**P22 竞争护城河的三个层次**
- **第一层：芯片技术壁垒**
  - 高速SerDes、低时延交换、多协议兼容、工业级可靠性
  - 国内少数具备自主高端交换芯片设计能力的团队
- **第二层：系统集成能力**
  - 网算存融合架构、软硬件协同设计、装备级验证能力
  - 从芯片到系统的全栈能力，客户粘性远高于纯芯片销售
- **第三层：生态粘性**
  - 软件定义框架 + 联盟生态 + 标准主导权
  - 客户越多、生态越厚、转换成本越高——网络效应
- *三层叠加，形成从技术到生态的递进式护城河*

**P27 敏捷迭代优势：晶上系统 + 软件定义 = 装备研制周期压缩一倍以上**
- **传统模式**：需求定义 → 芯片设计 → 流片 → 板级设计 → 系统集成 → 软件适配 → 验证迭代
  - 周期：18-24个月，流片一次失败成本极高
- **晶上 + SDI模式**：
  - 芯粒预制件模块化复用，减少重复流片——硬件迭代从年级降到月级
  - 软件定义互连架构，硬件功能动态重构——功能迭代从天级降到小时级
  - 装备研制与迭代周期敏捷化，压缩一倍以上
- **商业意义**：
  - 更快响应客户需求——从"客户提需求→18个月交付"到"客户提需求→6个月交付"
  - 更低迭代成本——软件定义减少硬件改版次数
  - 更高客户粘性——快速迭代能力本身就是核心竞争力

**P30 商业模式升级：从ToB芯片销售到生态型平台**
- **第一阶段（当前）：ToB解决方案**
  - 形态：芯片 + 板卡 + 参考设计 + 技术支持
  - 客户：装备厂商、系统集成商、行业客户
  - 收入：芯片销售 + 方案授权 + 技术服务
  - 增长模式：线性增长，随客户数量和订单规模增长
- **第二阶段（中期）：联盟生态运营**
  - 形态：标准接口 + 软件栈 + 认证体系 + 联合开发
  - 参与者：联盟成员、客户、合作伙伴
  - 收入：IP授权 + 软件订阅 + 生态服务费 + 联合项目分成
  - 增长模式：阶梯增长，每进入一个新行业上一个台阶
- **第三阶段（长期）：生态型平台**
  - 形态：端边侧AI装备的互连标准与基础软件平台
  - 参与者：全产业链——芯片厂、设备厂、软件商、云厂商
  - 收入：平台分成 + 生态税 + 数据价值
  - 增长模式：指数增长，网络效应驱动
- *价值曲线：从卖芯片的线性增长，到卖方案的阶梯增长，再到生态平台的指数增长*
