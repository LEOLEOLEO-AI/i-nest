## Original Note

华为昇腾950系列芯片全栈技术解析：面向大模型时代的系统性算力解决方案

### 📌 大模型时代的算力三重困局

AI算力需求正以超越摩尔定律的速度爆发，过去五年全球年新增数据量从64ZB飙升至近500ZB，大模型参数规模从十亿级迈向万亿级，传统硬件架构遭遇不可逾越的三堵墙：
1.  **算力墙**：LLM推理算力需求增速远超硬件迭代速度，低精度数据格式成为行业必选项
2.  **内存墙**：AI Agent超长上下文需求爆发，KV Cache存储需求指数级增长，单芯片内存已无法支撑
3.  **通信墙**：大模型训练中大量All-to-All数据交换，单次迭代通信量较小模型提升近百倍，传统互联带宽彻底无法承载
针对这三大核心挑战，华为推出昇腾950系列芯片，并非单点规格迭代，而是从底层架构出发的全链路系统性解决方案。

### 📊 双产品精准覆盖差异化场景

昇腾950系列采用共架构设计，推出两款定位明确的核心产品，在成本与性能之间实现精准匹配：

| 规格参数 | 昇腾950PR | 昇腾950DT |
| --- | --- | --- |
| 核心定位 | 高性能推荐 + Prefill阶段推理 | 大模型全生命周期训练推理 |
| 最大内存容量 | 128GB | 144GB |
| 内存带宽 | 1.6TB/s | 4TB/s |
| Cube Core配置 | 32/28个 | 36/32/28个 |
| MXFP4总算力 | 1784/1561 TFLOPS | 2007/1784/1561 TFLOPS |
| BF16总算力 | 486/425 TFLOPS | 547/486/425 TFLOPS |
- 950PR主打极致吞吐，针对推荐系统和大模型Prefill场景优化，适配低带宽需求的高并发任务
- 950DT主打全场景全能，2.5倍于PR的内存带宽可从容覆盖大模型训练、Decode推理全流程，支撑持续高速数据读写

### 🔍 第三代达芬奇架构：算力跃迁的核心引擎

昇腾950的核心是华为自研第三代达芬奇架构，单颗芯片最多集成36个AI子系统，每个子系统包含1个Cube Core+2个Vector Core，实现从底层计算单元到编程接口的全面重塑：
1.  **Cube Core低精度算力4倍跃升**
    新增MXFP8、HiF8、MXFP4等低精度格式原生支持，相同频率下MXFP4算力可达FP16的4倍，MXFP8/FP8/HiF8算力可达FP16的2倍，满配950DT的MXFP4算力突破2007 TFLOPS。同时微架构层面完成三大优化：更大的L0C Buffer提升数据复用率、随路量化消除格式转换额外指令开销、面向GEMM/FlashAttention优化缓存复用策略。
2.  **自研HiF8 8比特浮点格式**
    采用变长前缀码编码的创新设计，综合阶码范围达到[-22,15]共38个阶码值，接近FP16的40个阶码，无需额外缩放因子、零额外存储开销，通过锥形精度设计实现数值靠近1时精度最高，远离1时精度渐降，不存在精度跳变，在8比特极低开销下兼顾了神经网络精度需求与足够动态范围。
3.  **Vector Core算力翻倍+混合编程模式**
    FP16/FP32单核算力较上一代提升100%，彻底消除FlashAttention等融合算子的向量计算短板。创新推出SIMD/SIMT混合编程模式：以SIMD为主保障常规计算的高算力利用率，以SIMT为辅降低离散访存、复杂分支场景的开发难度，两种模式支持快速切换，在性能、可编程性、可移植性之间找到最优平衡点。
4.  **多项微架构创新降低开发门槛**
    - NDDMA指令硬化5维数据重排逻辑，单条指令即可完成数据搬运+转置，大幅提升内存访问效率
    - 打通Cube L1 Buffer与Vector Unified Buffer直连通道，融合算子无需经过L2 Cache即可完成数据交互，端到端延迟大幅降低
    - 推出BufferID同步机制替代传统set_flag/wait_flag模式，类似互斥锁的设计大幅降低多流水线并行算子的同步复杂度

### 💾 存储体系：突破内存墙的两大核心能力
1.  **超大容量+超高带宽片上内存**
    950DT提供最高144GB片上内存与4TB/s带宽，每秒可读取约500GB数据，完全覆盖大模型KV Cache读写、梯度更新的高带宽需求；全链路支持RAS特性，实现Online ECC、故障点自动巡检隔离、预留行动态替换，用户无感知保障运行可靠性。
2.  **128MB精细化管理L2 Cache**
    并非单纯扩容，而是提供算子可控的Cache Hint管理能力：支持Non-allocate策略避免无效数据占用缓存、128B Sector访问优化小数据读写效率、完整CMO操作集支持预取/预写回/无效化/冲刷，同时硬件自动维护跨Die的Cache一致性，软件完全无感。

### 🌐 灵衢总线2.0：打通通信墙的关键设计

灵衢（Unified Bus）2.0互联总线是昇腾950最具战略价值的设计之一，整芯片集成72 Lane HiLink SerDes，对外IO带宽峰值达到2TB/s，提供三类差异化通信语义：

| 通信语义 | 核心特性 | 适配场景 |
| --- | --- | --- |
| URMA | 异步内存拷贝，基于Jetty队列 | 大体积数据批量搬运 |
| UB Memory | 同步Load/Store/Atomic操作 | 低延迟细粒度数据访问 |
| CCU | 硬件卸载集合通信任务 | AllReduce/All2All等集群通信场景 |

同时创新实现三大能力：单IO Die内9个x4端口流量本地转发，无需占用计算Die资源与DRAM带宽；支持UBoE（UB over Ethernet），提供2×400Gbps以太网链路，可直接复用现有以太网交换机组网，大幅降低数据中心部署运维成本。

### 🚀 超大规模集群能力跃升

昇腾950的超节点规模从上一代384卡跃升至8192卡，整体集群支持规模突破128K卡，依托灵衢总线支持Full Mesh、Clos、nD-Mesh等多种组网拓扑，同时提供三类弹性扩展模式：
1.  超大内存池：通过UB端口直接访问128TB共享CPU内存池，高带宽低延迟
2.  超大存储池：通过UB端口直接访问存储资源池，无中间协议转换开销
3.  以太互通：通过UB Switch或UBoE无缝接入现有以太网环境
构建起覆盖计算、内存、存储、网络的全栈互联生态，而非仅实现芯片间Scale-up互联。

### ⚙️ 全链路配套能力补全
1.  **Linx816 AI CPU**：基于ARMv8-A架构，全芯片集成8核心，承担系统侧控制任务（页表管理、算子编译、IO调度）与非矩阵类通用计算任务，与AI Core共享统一内存池，硬件缓存一致性消除跨单元数据拷贝开销。
2.  **STARS2.0硬件调度器**：全芯片任务资源调度中枢，通过独立HSCB高速控制总线实现ns级调度延迟，支持2048条任务流下沉、多维度并发调度、算力资源切分隔离，为多租户场景提供底层支撑，同时内置实时Profiling能力为系统调优提供全链路数据。
3.  **DVPP视觉加速子系统**：集成4组VPC、8组JPEGD、4组JPEGE硬件单元，覆盖主流视觉预处理与编解码场景，完全消除多模态场景下图像处理环节的性能瓶颈。
4.  **全开源CANN软件栈**：分层架构覆盖高性能加速库、算子编程体系、编译器、运行系统全链路，全面开放底层能力，支持开发者深度定制，避免生态封闭锁定。
5.  **2+2+8 Chiplet UMA封装**：合封2个AI Die+2个IO Die+多组片上内存模块，通过高速D2D互联实现统一内存访问，硬件自动维护跨Die一致性，兼顾先进制程受限下的芯片良率与大算力集成需求。

### 🔎 核心洞察

昇腾950系列并非单一芯片规格的迭代升级，而是面向大模型时代算力、内存、通信三重挑战的全栈系统性回应：从计算单元微架构创新，到存储体系精细化设计，再到互联总线与大规模组网的全链路协同，标志着AI芯片竞争已经从单点算力比拼，进入系统级架构能力的新阶段。
