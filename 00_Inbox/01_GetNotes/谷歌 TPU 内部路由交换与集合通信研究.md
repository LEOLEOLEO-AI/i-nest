# 谷歌 TPU 内部路由交换与集合通信研究

## 一、TPU 互连架构概述

### 1.1 TPU 世代演进

谷歌张量处理单元（TPU）是专为深度学习训练和推理设计的专用芯片，其互连架构经历了从简单到复杂的演进：

| 世代 | 发布时间 | 核心架构 | 互连方式 |
|------|----------|----------|----------|
| TPU v1 | 2016 | 脉动阵列推理芯片 | 无片间互连（独立工作） |
| TPU v2 | 2017 | 训练芯片，2 个核 | ICI 2D Torus，每芯片 2 个方向 |
| TPU v3 | 2018 | 性能提升 2 倍 | ICI 2D Torus，每芯片 2 个方向 |
| TPU v4 | 2021 | 性能大幅提升 | ICI 3D Torus，每芯片 3 个方向 |
| TPU v5 | 2023 | 优化效率 | ICI 3D Torus，更高带宽 |

### 1.2 核心设计哲学

TPU 的互连设计有一个与 GPU 截然不同的核心理念：

**没有独立的交换芯片——每个 TPU 芯片本身就是网络节点，既是计算单元，又是路由节点。**

这与英伟达的"GPU + NVSwitch + 网卡"多芯片分工模式形成鲜明对比。TPU 走的是一条"计算与通信深度融合"的路线，这正是拓扑中心计算的早期形态。

## 二、ICI 互连与 3D Torus 拓扑

### 2.1 ICI（Inter-Chip Interconnect）接口

ICI 是 TPU 芯片内置的高速互连接口，类似于 NVLink，但集成度更高：

- **功能**：TPU 芯片之间直接互连，不需要独立的网卡或交换芯片
- **带宽**：每代持续提升，v4 代每个方向数百 GB/s
- **延迟**：极低，芯片间延迟在亚微秒级
- **集成度**：直接做在 TPU 芯片上，不占额外的芯片面积（相对独立网卡而言）

**关键特征**：ICI 不只是一个数据接口，它内置了路由功能。每个 TPU 芯片都可以把从一个方向收到的数据，转发到另一个方向。

### 2.2 3D Torus 拓扑结构

从 TPU v4 开始，TPU Pod 采用 **三维环面（3D Torus）** 拓扑：

- TPU 芯片排列成三维网格
- 每个芯片有 6 个 ICI 连接方向：前后、左右、上下（x, y, z 三轴）
- 每个轴的两端首尾相连，形成环面（Torus）

```
       z 轴（上下）
        ↑
        │
        │   ←─── y 轴（左右）
       /
      /
     x 轴（前后）
```

**为什么选 3D Torus？**

1. **对称的拓扑结构**：每个节点的度数相同（6），设计简单
2. **良好的扩展性**：可以在三个维度上扩展规模
3. **直径小**：N 个节点的 3D Torus，直径约为 3·N^(1/3)，比 2D Mesh 的 2·√N 小
4. **天然适合 3D 堆叠和多板布局**：x-y 平面在板上，z 轴通过板间连接

### 2.3 与其他拓扑的对比

| 拓扑 | 直径（N 节点） | 每节点度数 | 对分带宽 | 适用场景 |
|------|---------------|-----------|----------|----------|
| 全互连 | 1 | N-1 | 最高 | 小规模（如 NVLink 全互连） |
| 胖树 | 2 | d | 高 | 数据中心网络 |
| 2D Mesh/Torus | ~2√N | 4 | 中 | 片上网络（WSE） |
| 3D Torus | ~3·N^(1/3) | 6 | 中高 | TPU Pod 级互连 |
| 超立方体 | log₂N | log₂N | 中 | HPC 传统拓扑 |

**谷歌的选择逻辑**：3D Torus 在"每节点端口数"和"直径"之间取得了很好的平衡，而且与三维物理布局天然匹配。每个芯片 6 个高速接口，在工程上是可控的。

## 三、TPU 内部的路由机制

### 3.1 维度序路由（Dimension-Order Routing）

3D Torus 上最常用的路由算法是**维度序路由**（也叫 X-Y-Z 路由）：

**规则**：
1. 先在 x 方向路由，到达目标 x 坐标
2. 再在 y 方向路由，到达目标 y 坐标
3. 最后在 z 方向路由，到达目标 z 坐标

**优点**：
- 算法简单，硬件实现容易
- 保证无死锁（只要每个维度的虚通道数足够）
- 延迟确定

**缺点**：
- 不是所有路径都是最短路径（Torus 的环绕方向可能更短，但维度序不绕）
- 某些流量模式下会出现热点

### 3.2 虚通道（Virtual Channel）

为了解决死锁问题和支持 QoS，TPU 的 ICI 链路支持虚通道：

- 每条物理链路上划分多个虚通道
- 不同类型的流量使用不同的虚通道
- 虚通道之间相互独立，避免队头阻塞

**虚通道的作用**：
1. **死锁避免**：通过虚通道打破循环依赖
2. **流量隔离**：不同优先级的流量互不干扰
3. **提高利用率**：一条物理链路可以同时承载多个逻辑流

### 3.3 自适应路由

除了维度序路由，TPU 可能还支持一定程度的自适应路由：

- 当某个方向拥塞时，可以选择其他路径
- 利用 Torus 的多路径特性分散流量
- 提高网络的吞吐量和容错能力

## 四、TPU 中的集合通信实现

### 4.1 All-Reduce：环算法 + 多维分解

在 3D Torus 上，All-Reduce 通常采用**多维环算法**：

**基本思想**：把 All-Reduce 分解到三个维度上分别执行。

**步骤**：
1. **x 方向**：在每一条 x 方向的环上，执行 Ring All-Reduce
2. **y 方向**：在每一条 y 方向的环上，执行 Ring All-Reduce
3. **z 方向**：在每一条 z 方向的环上，执行 Ring All-Reduce

经过三个维度的规约，最终每个节点都得到完整的规约结果。

**复杂度分析**：
- 延迟：O(3·(N_x + N_y + N_z)) ≈ O(N^(1/3))
- 带宽：每个方向的链路都被充分利用
- 计算与通信重叠：规约计算可以在数据流过每个节点时就地完成

### 4.2 All-to-All：多维置换

All-to-All 在 3D Torus 上的实现采用**三维置换算法**：

**步骤**：
1. 按 x 目标地址排序，在 x 方向做置换
2. 按 y 目标地址排序，在 y 方向做置换
3. 按 z 目标地址排序，在 z 方向做置换

经过三轮置换，每个节点都能收到来自所有其他节点的数据。

这与 WSE 在 2D Mesh 上的行列置换算法思路一致，只是扩展到了三维。

### 4.3 关键特征：计算与通信的融合

TPU 集合通信的最大特点是**计算发生在数据流过的节点上**：

- 数据从一个 TPU 流向另一个 TPU
- 每个 TPU 在转发数据的同时，把自己的数据加进去（规约操作）
- 不需要把数据收集到某个中央节点再计算
- 通信和计算完全重叠

**这正是"在网络中做计算"的典型模式**——只不过 TPU 的"网络节点"就是计算节点本身。

## 五、TPU 架构与 SDI 的关系

### 5.1 TPU 是 SDI 的初级形态

从 TCC 的视角看，谷歌 TPU 的架构已经非常接近"拓扑中心计算"的理念：

| TCC 理念 | TPU 的实现程度 | 说明 |
|----------|---------------|------|
| 计算与通信融合 | ⭐⭐⭐⭐ | 每个 TPU 既是计算节点又是路由节点 |
| 拓扑即计算 | ⭐⭐⭐ | 3D Torus 拓扑固定，不能动态重构 |
| 网内计算 | ⭐⭐⭐⭐ | 集合通信在数据流动中完成 |
| 异构支持 | ⭐ | 同构 TPU 阵列，不支持异构节点 |
| 拓扑可编程 | ⭐ | 拓扑固定，只有路由是动态的 |

**结论**：TPU 已经证明了"计算节点内嵌交换功能"的架构是可行的、高效的。但它还是同构的、固定拓扑的。SDI 要做的是把这个思路推向极致——异构的、液态拓扑的、完全以拓扑为中心的。

### 5.2 SDI 对 TPU 的超越方向

1. **从同构到异构**：TPU 只能连 TPU，SDI 可以连接 CPU、GPU、NPU、HBM 等各种节点
2. **从固定拓扑到液态拓扑**：TPU 的 3D Torus 是固定的，SDI 拓扑可以根据任务动态重构
3. **从内嵌路由到拓扑变换**：TPU 只有路由功能，SDI 有完整的拓扑变换能力（电路交换、虚电路、分组交换三层）
4. **从专用到通用**：TPU 是为深度学习优化的专用芯片，SDI 是通用的拓扑基础设施

### 5.3 TPU 留给 SDI 的开放问题

TPU 的成功证明了方向，但也留下了很多 SDI 需要回答的问题：

1. **异构节点间的集合通信如何高效实现？** TPU 是同构的，SDI 需要处理不同计算能力、不同接口带宽的异构节点
2. **动态拓扑下的集合通信算法如何设计？** TPU 拓扑固定，算法可以高度优化；SDI 拓扑可变，需要自适应的算法
3. **编程模型如何设计？** TPU 有专门的编译器（XLA），SDI 需要一套面向拓扑中心计算的编程抽象

## 七、终极形态的启示

谷歌 TPU 的架构演进，指向了一个清晰的方向：

> **当互连足够重要时，交换功能会从独立的芯片，逐步内嵌到计算芯片中。最终，计算节点和网络节点合二为一。**

英伟达走的是"多芯片分工"路线（GPU + NVSwitch + ConnectX + BlueField），谷歌走的是"单芯片融合"路线（TPU 内嵌 ICI 路由）。

SDI 要走的是第三条路——**不是把交换功能内嵌到计算芯片里，而是把拓扑变换做成独立的、可编程的基础设施，让所有计算节点都能接入一个液态的拓扑网络。**

这就像从"专用集成电路"到"现场可编程门阵列"的跃迁——TPU 是拓扑层面的"专用集成电路"（固定 3D Torus），SDI 是拓扑层面的"现场可编程门阵列"（液态可重构拓扑）。
