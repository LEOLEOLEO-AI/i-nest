## 一、项目定位

本项目面向后摩尔时代智能计算架构变革，提出并验证“拓扑即计算”的拓扑中心计算，TCC，范式，探索以液态拓扑织构，LTF，Liquid Topology Fabric，为核心的新型计算路线。

项目拟形成TCC产品族“拓涌场 TopoSurge Fabric”。拓涌场不是GPU、NPU、TPU、LPU或FPGA的延伸，而是以拓扑态为第一可编程对象的新型液态硬件范式。

项目保留TCC-AI和TCC-RF两个技术代号。其中，TCC-AI产品方向命名为“拓涌智场”，面向端侧训推一体AI；TCC-RF产品方向命名为“拓涌波场”，面向DBF、FFT、宽带数字阵列、通感一体和射频智算。

本项目最终服务于iNEST“智涌脑”的工程实现，形成从液态拓扑硬件到网络时空复杂度涌现智能的技术底座。

核心表达为：

[  
\text{拓涌场} \rightarrow \text{拓涌晶圆} \rightarrow \text{智涌脑}  
]

即：

**拓涌成场，智涌成脑。**

## 三、总体目标

本项目以“拓扑即计算”为理论核心，以“拓扑态可编程”为工程抓手，构建可运行、可测量、可复现的液态拓扑生成式计算原型。

项目总体目标包括：

1．提出TCC拓扑中心计算理论框架，建立Route-Transform完备性定理和FFT-AllReduce-DBF同构映射方法。

2．构建R类路由原语和T类变换原语体系，形成从4R＋3T到6R＋6T的可扩展原语库。

3．设计基于元拓扑、SDI化合键、TopoColor μRouter、Topology Page和Epoch Commit的液态拓扑机制。

4．在FPGA平台验证Gemma E4B INT4推理、片上AllReduce、FFT＋DBF双模处理、LoRA训推闭环四类典型场景。

5．形成TCC-AI拓涌智场和TCC-RF拓涌波场两条ASIC产品路线。

6．为后续拓涌晶圆和iNEST智涌脑提供液态硬件底座。

## 四、技术范式差异

现有主流智能芯片大多仍以处理器、算子或矩阵乘为中心。TCC的根本差异在于：它不是第N个PU，而是把“拓扑态”提升为第一可编程对象。


| 类型     | 中心对象      | 主要可编程对象           |
| ------ | --------- | ----------------- |
| GPU    | 通用并行处理器   | Kernel            |
| NPU    | 神经网络算子    | Tensor算子          |
| TPU    | 矩阵数据流     | Systolic Dataflow |
| LPU    | 语言模型推理流   | LLM数据流            |
| FPGA   | LUT和可编程逻辑 | 逻辑电路              |
| TCC拓涌场 | 液态拓扑织构    | 拓扑态＋R／T原语＋SDI化合键  |


因此，TCC的对外定义应为：

**GPU编程Kernel，NPU编程Tensor，FPGA编程逻辑，拓涌场编程拓扑态。**

## 五、核心理论框架

### 5.1 拓扑即计算

TCC的核心命题是：

[  
Topology\ is\ Computation  
]

即拓扑结构的生成、切换、融合、广播、规约、交换和重排本身就是计算过程，而不是计算之外的通信开销。

传统范式可概括为：

[  
Computation = Matrix\ Multiply + Memory\ Access  
]

TCC范式可概括为：

[  
Computation = Route\ Primitive + Transform\ Primitive  
]

其中，R原语负责生成数据关系，T原语负责执行局部变换。

---

### 5.2 Route-Transform完备性定理

设任意有限规模线性计算可表示为：

[  
Y = AX  
]

则存在有限个路由原语 (R_i) 与变换原语 (T_i)，使得：

[  
Y = T_kR_k\cdots T_2R_2T_1R_1X  
]

该定理表明，矩阵乘、FFT、AllReduce、DBF等计算均可被分解为有限次路由与局部变换的交替复合。

---

### 5.3 FFT-AllReduce-DBF同构定理

FFT、AllReduce和DBF表面上属于不同领域，实质上共享可重构拓扑骨架，差异主要体现在局部变换函数和数据类型上。


| 算法        | R原语            | T原语          | 拓扑骨架      |
| --------- | -------------- | ------------ | --------- |
| FFT       | FLY            | MAP／FOLD     | 蝶形拓扑      |
| AllReduce | FLY／RING／CAST  | FOLD         | 蝶形／环形／树形  |
| DBF       | CAST／FUSE／FOLD | MM           | 二部图＋规约树   |
| LoRA闭环    | FUSE／CAST／MESH | MM／GRAD／FOLD | 局部融合＋广播更新 |


因此，FFT、AllReduce、DBF和LoRA不是四套孤立硬件，而是同一液态拓扑织构上的不同拓扑相。

## 七、总体技术路线

### 7.1 元拓扑＋SDI化合键

定义物理元拓扑为：

[  
G_0=(V,E_0,C,L)  
]

其中，(V)为CGRA MacroTile集合，(E_0)为物理链路集合，(C)为链路容量，(L)为链路时延。

SDI化合键定义为：

[  
b_i=(u,v,type,path,vc,rate,op,epoch,color)  
]

其中，(type)对应R原语，(op)对应T原语，(epoch)表示拓扑版本，(color)表示拓扑流颜色。

有效拓扑定义为：

[  
G_{\pi,e}=(V,{b_i\mid primitive(b_i)=\pi,epoch(b_i)=e})  
]

容量约束为：

[  
\forall e\in E_0,\quad \sum_{b_i:e\in path(b_i)}rate_i\leq C_e  
]

工程含义是：**不改变物理连线，而是在固定元拓扑上通过化合键、虚通道、时隙和拓扑页生成当前算法需要的有效拓扑。**

---

### 7.2 TopoColor μRouter

TCC借鉴公开架构中二维Mesh、Color Routing和静态数据流调度思想，提出TopoColor μRouter机制。

μRouter查表键为：

[  
key=(epoch,color,in_port)  
]

查表结果为：

[  
value=(out_mask,vc,local_action,t_op,next_color,qos)  
]


| 字段           | 含义                                       |
| ------------ | ---------------------------------------- |
| epoch        | 拓扑版本                                     |
| color        | 数据流颜色／拓扑分子编号                             |
| in_port      | 输入方向                                     |
| out_mask     | 输出端口掩码，支持多播                              |
| vc           | 虚通道                                      |
| local_action | 本地消费、复制、规约或旁路                            |
| t_op         | [触发T.MM](http://触发T.MM)、T.FOLD、T.GRAD等操作 |
| next_color   | 下一阶段颜色                                   |
| qos          | 优先级和带宽配额                                 |


TopoColor的本质是：

[  
Color\ Routing + Epoch + T\ Primitive  
]

即把数据流颜色从“路由标签”升级为“拓扑计算标签”。

---

### 7.3 CGRA MacroTile路线

本项目采用大颗粒CGRA MacroTile，而非大量细粒度小Tile。其目的在于缩小液态拓扑定义边界，降低路由复杂度，提高片上数据复用率。

若将 (g) 个小Tile融合为一个MacroTile，则：

[  
N_{macro}=\frac{N_{small}}{g}  
]

拓扑页规模近似下降为：

[  
S_{page}^{macro}\approx\frac{1}{g}S_{page}^{small}  
]

对于近似全连接通信需求，复杂度可由：

[  
O(N^2)  
]

下降为：

[  
O\left(\frac{N^2}{g^2}\right)  
]

因此，本项目采用的基本架构原则是：

**MacroTile内部做DSA／CGRA数据流，MacroTile之间做液态拓扑。**

## 九、SDI-Lite FPGA原型方案

FPGA阶段采用ALINX AXVU13F平台，核心芯片为Xilinx VU13P。SDI功能以内化的SDI-Lite IP核实现，不依赖外部SDI4820开发板。

SDI-Lite原型由以下模块组成：

```text
tcc_sdi_lite_top
 ├── sdi_ctrl_plane
 ├── topo_page_sram
 ├── epoch_manager
 ├── topocolor_mu_router
 ├── cgra_macrotile_network
 ├── global_time_slot_gen
 ├── perf_counter_bank
 └── axi_lite_cfg_if
```

关键工程原则是：

**FPGA Partial Reconfiguration不作为τ≤1µs的主路径。**

PR可用于功能区域装载，但液态拓扑切换必须依靠拓扑页翻转、局部微码补丁、虚通道切换和epoch提交实现。

## 十、液态四率考核指标


| 指标    | 符号            | 定义                      | 目标   |
| ----- | ------------- | ----------------------- | ---- |
| 算力纯度  | (\eta_{pipe}) | R／T原语流水有效周期／原语执行周期      | ≥80％ |
| 通信折叠率 | (\kappa)      | 传统GPU集合通信延迟／TCC片上集合通信延迟 | ≥25× |
| 拓扑液化度 | (\tau)        | Hot／Patch拓扑切换ready时间    | ≤1µs |
| 模态切换比 | (\sigma)      | 训推切换时间／单token时间         | ≤5％  |


其中：

[  
\eta_{pipe}=\frac{有效原语流水周期}{原语总执行周期}  
]

[  
\kappa=\frac{Latency_{GPU\ Collective}}{Latency_{TCC\ Collective}}  
]

[  
\tau=t_{\text{ready}}(G_{e+1})-t_{\text{commit}}  
]

[  
\sigma=\frac{t_{\text{train}\leftrightarrow \text{infer}}}{t_{\text{token}}}  
]

特别说明：(\eta_{pipe})是原语流水纯度，不等同于LLM batch＝1 decode场景下的全芯片峰值利用率。LLM Token/s需采用内存带宽Roofline模型评估。

## 十二、场景一：TCC-AI拓涌智场

TCC-AI拓涌智场面向端侧训推一体AI，重点验证低功耗Token/J、液态拓扑切换和LoRA闭环适应能力。

FPGA阶段目标是验证TCC原语链路、拓扑页机制和算力纯度，不以绝对Token/s对标GPU。Gemma E4B INT4推理指标设为≥3 tok/s，属于原型验证指标。

LLM decode阶段Token/s采用如下模型：

[  
D_{token}\approx Pq_{eff}+D_{KV}+D_{misc}  
]

[  
TPS\leq\frac{BW_{eff}}{D_{token}}  
]

其中，(P)为参数量，(q_{eff})为INT4权重含scale、metadata和对齐后的等效字节数，通常可按0.55—0.70 Byte／parameter估算。

4B级INT4模型单token数据量可估计为：

[  
D_{token}\approx2.6GB\sim3.5GB  
]

因此，拓涌智场不应只看POPS，而应重点关注片上SRAM、外部带宽、KV调度、量化解码和数据流效率。

## 十五、场景二：片上AllReduce验证

AllReduce用于多路视频特征融合和片上多MacroTile协同计算。其原语分解为：

[  
AllReduce=[R.FLY](http://R.FLY)+T.FOLD+R.CAST  
]

本项目将AllReduce考核消息规模限定为4KB—16KB，以保证κ指标可复现、可比较。


| 指标          | 目标                 |
| ----------- | ------------------ |
| 消息规模        | 4KB—16KB           |
| MacroTile规模 | 16—64等效节点          |
| TCC延迟       | ≤2µs               |
| GPU基线       | 约50µs量级，最终以同平台复测为准 |
| 通信折叠率       | ≥25×               |
| 验证方式        | 硬件计数器＋主机侧时间戳双测量    |


该场景的核心不是大包带宽，而是小中粒度集合通信低延迟折叠。

## 十六、场景三：TCC-RF拓涌波场

TCC-RF拓涌波场面向DBF、FFT、宽带数字阵列、星载相控阵、通感一体、数字雷达和晶上DRBE。

FFT＋DBF同芯片支持的核心需求来自宽带阵列信号处理，其天然包含两个维度：

[  
时间／频率维：FFT  
]

[  
空间／阵元维：DBF  
]

典型链路包括：

```text
宽带接收：
ADC IQ → DDC → FFT信道化 → 分频点DBF → 波束输出

雷达处理：
ADC IQ → DBF → Range FFT → Doppler FFT → 目标特征
```

因此，FFT＋DBF同芯片不是两个IP的简单堆叠，而是TCC液态拓扑在射频智算中的典型证明场景。

---

## 十七、DBF计算模型与指标

64阵元、16波束DBF定义为：

[  
Y_b(t)=\sum_{n=1}^{64}W_{b,n}X_n(t),\quad b=1,\dots,16  
]

矩阵形式为：

[  
Y(t)=WX(t)  
]

其中：

[  
W\in \mathbb{C}^{16\times64},\quad X(t)\in \mathbb{C}^{64\times1}  
]

64阵元、16波束、100MSps对应主计算量为：

[  
R_{DBF}=64\times16\times100M=102.4G\ complex\text{-}MAC/s  
]

若每路IQ为16bit I＋16bit Q，则输入带宽为：

[  
BW_{in}=64\times100M\times32bit=204.8Gbps=25.6GB/s  
]

拓涌波场FPGA验证目标为：


| 指标        | FPGA目标                 |
| --------- | ---------------------- |
| 阵元数       | 64                     |
| 波束数       | 16                     |
| 采样率       | 100MSps                |
| DBF主计算量   | ≥102.4G complex-MAC/s  |
| 推荐复数MAC余量 | 192—256G complex-MAC/s |
| 输入带宽      | ≥25.6GB/s等效            |
| 片上Fold带宽  | ≥150GB/s，挑战≥250GB/s    |
| 拓扑切换      | FFT Page↔DBF Page≤1µs  |
| DBF流水延迟   | 目标≤1µs                 |

## 十八、FFT延迟边界

FFT固有帧时间为：

[  
T_{frame}=\frac{N}{F_s}  
]


| FFT点数 | (F_s=100MHz)时固有帧时间 |
| ----- | ------------------ |
| 64点   | 0.64µs             |
| 256点  | 2.56µs             |
| 1024点 | 10.24µs            |


因此，(\tau≤1µs)表示FFT Page与DBF Page之间的拓扑切换时间，不表示1024点FFT的完整端到端算法时间。

项目测试必须分别报告：

1．拓扑页切换时间 (\tau)。

2．FFT固有帧采集时间 (N/F_s)。

3．FFT流水计算延迟。

4．DBF流水处理延迟。

## 二十、场景四：LoRA训推闭环验证

LoRA训推闭环用于验证TCC在端侧模型持续适应中的能力。其原语分解为：

[  
LoRA=R.FUSE+[T.MM](http://T.MM)+T.GRAD+T.FOLD+R.CAST  
]

执行流程为：

```text
推理拓扑页
  ↓ Epoch Commit
LoRA微调拓扑页
  ↓ T.GRAD更新低秩参数
  ↓ R.CAST广播更新
  ↓ Epoch Commit
推理拓扑页
```


| 指标     | 目标                  |
| ------ | ------------------- |
| 训推切换比  | (\sigma≤5％)         |
| 微调方式   | LoRA／Adapter        |
| Loss下降 | ≥30％                |
| 切换机制   | 推理页与训练页常驻，epoch提交切换 |
| 权重管理   | 双权重页／低秩参数页          |
| 主要意义   | 端侧感知—适应—再推理闭环       |
