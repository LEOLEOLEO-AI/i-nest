# 晶上十五五 KJW

主题：面向“十五五”装备发展趋势与现实迫切需求，精准布局“软件定义晶上系统（二期）”项目  
定位：本材料用于会晤汇报“立项必要性—关键问题—二期项目布局—预期产出与抓手”。  
口径：对外/对上汇报口径——讲需求、问题、体系路线、可验证指标与组织机制；不披露未公开实现细节与敏感参数。

1. 一页总述（开场 60 秒）  
核心判断：后摩尔时代，装备智能化能力上限不再由单芯片峰值决定，而由“体系化协同能力（计算×互联×软件运行时×安全可靠）”决定。  
核心矛盾：在“训练中心 + 无人平台”两大场景下，传统 Chiplet 只能解决“拼装与产能/良率”，难以解决“端到端任务指标、确定性与可治理、跨尺度协同与智能涌现”。  
核心抓手：以“软件定义晶上系统（SDSoW）”为平台形态，以“拓扑中心计算（TCC）范式”为系统机制，以“复杂度涌现智能”为能力目标，形成二期工程化落地与示范。
2. 会晤目标与需领导决策点  
1.1 会晤目标  
对齐“十五五”装备发展趋势：智能化、体系化、网络化、可重构、可靠安全、跨域协同。  
说明“SDSoW 二期”为什么必须在“十五五”窗口期立项：形成体系能力底座、牵引标准/评测/生态，避免长期受制于外部算力与网络体系。  
1.2 需领导支持/决策的关键点（建议明确三项）  
立项级别与牵头单位：是否按“体系级能力平台”立项，而非单一芯片/单点技术课题。  
示范场景与应用牵引：优先锁定“训练中心+无人平台”两大示范，形成可验收指标与可复现评测。  
协同机制：跨“芯片—互联—编译/运行时—模型—系统集成—安全可靠”的联合攻关组织方式与资源保障。
3. 背景：十五五装备智能化的迫切需求（问题从哪里来）  
2.1 装备发展趋势（十五五）  
装备智能化从“单点算法”走向“智能体系统”：持续感知、持续决策、持续行动，强调闭环与自适应。  
作战样式从“平台中心”走向“体系中心”：多平台多域协同，强依赖网络与算力的确定性与韧性。  
技术路线从“堆性能”走向“抓有效性”：以端到端任务完成效率（时间、能耗、可靠性、安全）为核心。  
2.2 现实痛点（可复核表达）  
“算力有了，但效率上不去”：端到端延迟/能耗/稳定性受通信、同步、调度、故障等系统摩擦牵制。  
“平台能做，但难以规模化”：多芯并存导致 M×N（模型×芯片）适配爆炸，迁移成本高、可复现性差。  
“能跑起来，但跑不稳”：超大规模训练与分布式推理对 P99、抖动、容错恢复、回滚提出硬要求。
4. 为什么 Chiplet 解决不了或解决不好（汇报需要“明确边界”）  
Chiplet 的价值：提升良率、降低成本、提升产能与异构集成灵活性——解决“怎么拼”。  
SDSoW 二期要解决：端到端任务指标、体系协同、可治理、可演化、安全可靠——解决“怎么协同、怎么涌现、怎么可控”。

3.1 三个“Chiplet 解决不好”的关键问题  
体系协同问题：Chiplet 关注封装级拼接，但难以给出“计算—通信—存储—运行时”一体化的协同机制与可验证指标。  
确定性与可治理问题：装备场景强调 P99/抖动/故障恢复/回滚与隔离，Chiplet 本身不提供系统级治理闭环。  
跨尺度重构问题：训练中心与无人平台需要跨任务、跨拓扑、跨域动态重构与资源编排；仅靠硬拼接难以适配工作负载快速演化。  
4. 二期项目的“核心两大场景”与突出问题（面向需求立项）  
场景 1：训练中心（“晶圆机芯片/晶上系统”支撑大模型训练的迫切要求）  
4.1 场景描述  
面向千亿/万亿参数大模型训练与多模态训练，训练系统呈现“通信密集 + 同步敏感 + 故障常态化”特征。  
关键不只是峰值算力，而是规模化效率（scaling efficiency）与有效产出（goodput）。  
4.2 训练中心的突出问题（可用于会晤的“问题清单”）  
集合通信成为第一性工作负载：AllReduce/ReduceScatter/AllToAll 等决定训练迭代时间。  
通信与计算隐藏（overlap）成为决定性机制：能否把通信代价搬到计算空隙里，直接决定端到端效率。  
可观测、可治理、可恢复：拥塞/抖动/故障导致回滚与停摆，必须具备可观测与快速恢复机制。  
国产生态与迁移成本：多芯并存导致 M×N 适配爆炸，适配成本高于单点性能收益。  
4.3 SDSoW 二期的对应能力（“我们能解决什么”）  
“系统级互联+集合通信+运行时”的协同机制：把集合通信从“成本”变成“能力”。  
以 TCC 范式组织训练系统：把拓扑/路由/调度与训练工作负载协同起来，提升 goodput。  
形成可复核指标体系：TTS（Time-to-Solution）、J/task、P99、扩展效率曲线、故障恢复时间等。  
场景 2：无人平台（超低轨卫星/无人机等）OODA 一体化智能体平台  
4.4 场景描述  
端侧/在轨/在空：强约束（功耗、重量、算力、可靠性、抗毁）、强实时、强不确定环境。  
需求从“跑一个模型”升级到“支撑智能体服务”：感知—认知—决策—行动（OODA）闭环、在线学习/更新、任务动态变化。  
4.5 无人平台的突出问题  
OODA 端到端时延与确定性：不是平均值，而是 P99 与抖动；要“可预测”。  
异构任务融合与一致集成：多传感器、多任务、多模型协同，不能靠堆叠多个独立加速器。  
韧性与回滚：智能体试错需要可回滚、可隔离、可审计；故障下要“降级可用”。  
通信—计算动态耦合：任务/拓扑变化大，通信与计算需要运行时编排与可重构支撑。  
4.6 SDSoW 二期的对应能力  
以“软件定义架构 + 一致集成”支撑智能体服务：把能力做成平台服务而非单点模型。  
以“网络时空协同复杂度（CST）→ 智能涌现”为方法论：在高阶耦合中形成更强的体系协同能力（强调可观察、可验证、可控）。  
面向装备的安全可靠：隔离、可信、可审计、可恢复（按装备要求组织指标与验收）。  
5. 二期项目总体目标与定位（怎么立项才“精准”）  
5.1 总体目标（一句话）  
建设“软件定义晶上系统（SDSoW）二期”体系化平台：面向训练中心与无人平台两大场景，形成可验证、可治理、可演化的协同计算底座，实现端到端任务指标的可持续提升。

5.2 项目定位（建议对上汇报的三层结构）  
平台层：SDSoW 作为可重构、一致集成的平台形态（面向不同装备与训练中心可裁剪）。  
机制层：TCC（拓扑中心计算）作为“系统协同机制”，解决集合通信、调度、通信隐藏与治理。  
能力层：面向智能涌现的生成能力（强调“可观察/可验证/可控”的工程化表达）。  
6. 二期项目建议布局（“干什么、怎么干、验收什么”）  
建议按“1个平台 + 2个示范 + 3类共性能力 + 1套评测标准”组织。

6.1 1个平台：SDSoW 二期平台能力包  
统一的“计算—互联—运行时”协同框架（对外不展开实现细节）  
可观测与治理：端到端性能与稳定性观测、调度策略、拥塞/故障处理闭环  
安全可靠：隔离、可信、审计、回滚/恢复机制（按装备要求定义）  
6.2 2个示范：场景牵引（建议各给一套可验收任务）  
训练中心示范：以典型训练工作负载为牵引（AllReduce/AllToAll 显著）验证 TTS/J/task/扩展效率提升。  
无人平台示范：以 OODA 闭环任务为牵引验证 P99、功耗、韧性、降级可用与回滚能力。  
6.3 3类共性能力（建议写进任务书/指标）  
通信—计算隐藏能力：overlap 与流水化（体现为端到端时延下降）  
集合通信能力：以系统原语方式提供 collectives（体现为扩展效率曲线改善）  
M×N 适配降本能力：用统一抽象/统一口径/统一验证降低迁移成本（体现为适配周期缩短、可复现性提升）  
6.4 1套评测标准（强烈建议纳入二期）  
指标：TTS、J/task、P50/P99、抖动、扩展效率曲线、恢复时间、可用性  
工具：基准套件（训练/推理/无人平台任务）、证据链记录（页码/版本/可复核链接）  
7. 阶段路线与里程碑（十五五对齐）  
这里给“结构”，后续可根据领导偏好再细化为时间表。

阶段 I：0–12 个月（立项后快速出样）  
完成：平台能力包 V1（关键原语 + 观测闭环 + 基准口径）  
形成：训练中心示范 V1（可复核指标 + 可复现实验）  
阶段 II：12–24 个月（规模化与可靠性）  
完成：无人平台 OODA 示范 V1（P99/功耗/韧性/回滚）  
完成：跨拓扑/跨任务动态重构能力验证  
阶段 III：24–36 个月（体系化推广与标准牵引）  
形成：标准/评测/生态共建机制，推广到更多装备与训练中心任务  
8. 风险与对策（对上汇报必备）  
生态碎片化与迁移成本 → 用统一抽象与统一验证口径，把迁移成本从“工程项目”降到“配置与验证”。  
超大规模不确定性（拥塞/故障） → 强化可观测与治理闭环，建立可恢复/可降级机制。  
对外披露边界 → 分层输出：对外版讲指标与机制，内部版讲实现与参数；材料按 #公开/#受限/#内部 管理。  
9. 结束语（收束 30 秒）  
“十五五”窗口期的关键不是再造一颗更强芯片，而是建成可持续演化的体系能力平台。  
SDSoW 二期以训练中心与无人平台两大迫切场景牵引，以 TCC 范式把集合通信与系统治理做成能力，以智能涌现为能力目标，形成 Chiplet 单靠拼装难以实现的端到端指标跃升与体系化优势。
