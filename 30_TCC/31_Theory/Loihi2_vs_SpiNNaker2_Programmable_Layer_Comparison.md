# 一、先把回路搭好：一张图能改"什么"？

对任何神经形态（或类神经网络硬件）芯片，"图"这个词其实有三层，从底向上分别是：

|层次|一句话解释|谁动了|
|---|---|---|
|L1 **物理画布**|芯片里实际的导线怎么走、走几条、连到哪个物理端口|**任何厂商都不会改**（光罩刻死了）|
|L2 **逻辑通信模式**|一次信号在这张画布上被允许走哪条路、复制给哪些人|**路由表 / 多播规则**——SpiNNaker 在这层|
|L3 **图的实例层**|这张图实际"画了"哪些笔道、笔道粗细（突触权值）|**突触连接表**——Loihi 在这层|

注意上表里 Loihi 与 SpiNNaker 都在 L2 与 L3 之间的"某层"可改，但**不是同一层**，这是他俩最容易混淆的地方。下一段逐家拆开讲。

---

# 二、Loihi 2 —— 可改的是 L3（突触连接表）

## 2.1 物理底座（不能改的部分）

Loihi 2 是 Intel 在 2021 年发布的第二代神经形态芯片，制程 Intel 4。芯片上有：

- **128 个神经核**（叫 neurocore），排成一个 2D mesh
- **每个核有约 1000 个 LIF（漏电积分发放）神经元**：模拟生物神经元的"积累电位 → 超过阈值 → 发放一次脉冲"
- **核心存储 = 突触表**：每个核配备一片片上 SRAM，里面放着"哪两个神经元相连、连在哪个突触上、权重多大"的明细账
- **片间通讯**：每核留 6 个端口给片间 mesh，物理上是一个小的 3D mesh

这些**全在光罩里就钉死了**，每次换 wafer 才能改。

## 2.2 Loihi 把"图"理解成什么？

关键一句话：**在 Loihi 的世界观里，"图 = 突触表"**。一张图不再是一个几何拓扑，而是实打实一张明细账：

```
Copy突触表第 4711 行：
  源神经元 = core3.neuron134  （指 mesh 第三个核第 134 个神经元）
  目标神经元 = core17.neuron98
  突触类型 = 兴奋性 / 抑制性
  权重 = 7 (压缩到 4 bit)
  标签 = 学习索引（用于 eligibility trace）
```

把这一行加上或删除 = 在图里"接上一根线"或"拆掉一根线"；改权重 = 调整线的粗细。**图的拓扑连接在 Loihi 里其实就是这张表的行数**。

## 2.3 谁来改这张表？—— 微码（microcode）

Loihi 怪的地方在：让这张表改动的不是 CPU 指令、不是 OS、而是**每核内的微码引擎**。它相当于每核装了一个微型"机器人"，按预设的规则自动改表。

Loihi 2 有 **14 条神经元微指令**，构成几类可塑性样式：

|微指令族|一句话作用|
|---|---|
|pair-based Hebbian（含 anti-Hebbian 反向）|经典"一起发放就连得更紧"|
|三因子可塑性（Three-factor）|在 Hebbian 之上叠加一个**全局信号**——比如模拟多巴胺的 neuromodulator|
|脉冲时序依赖可塑性 STDP|突触前后脉冲时间差决定权重增减|
|eligibility-trace（资格迹）|"刚才发生过某模式"的痕迹，暂时持有，让 backup 实测信号来了再决定改不改|

**三因子规则的全局信号是 Loihi 2 的命门**：整片芯片可以向所有 128 核同时广播一个 neuromodulator，让所有微码机器人"同时动手"——这相当于全局学习脉冲。

## 2.4 时间常数是 ms 级

为什么上一轮汇报图里把 Loihi 放在"ms 级"？

微码每条规则在一个 spike 周期内执行，但**全局学习周期**受 batch 调度影响——例如 1000 次发放 / 突触改写操作大约就是几 ms。所以"图像级别的图重写"是 ms 级别的。

**但** Loihi 改图可以**异步、低开销、持续**——它不像 CPU 那样需要 download 整张新图再 upload，它就是微码在背后悄悄改。

## 2.5 等价说法（科普版）

把 Loihi 2 想象成一个**点菜单**：每道菜（突触）写在菜单里，后厨（微码）看见客人点单（spike + 调制信号）自动加减菜 + 改口味（权重 + 连通性）。换菜单内容 = 改图，但不能把后厨搬到另一家店——物理店面不能换。

# 三、SpiNNaker 2 —— 可改的是 L2（多播路由表）

## 3.1 物理底座（不能改的部分）

SpiNNaker 是曼彻斯特大学 Steve Furber 教授牵头的开源神经形态硬件，1 代是 130nm CMOS 18 核 ARM968，**2 代改成 22nm FDSOI 全数字 SRAM 嵌入式**，每片 152 个 PE（处理元素）。板级可堆到千万核，是真正的"拟脑超算"。

- PE = ARM M4F CPU + 单独 SRAM + 路由引擎
- 片上 6 条链路连邻居，构成 2D mesh

## 3.2 SpiNNaker 把"图"理解成什么？

完全不一样。SpiNNaker 不靠突触表，靠**神经脉冲包**（small fixed-width packet，叫 SpiNNaker packet）：

```
Copy脉冲包格式：
  [header | 32-bit routing-key | payload (8-bit)]
```

每个脉冲包带一个**路由键**（32-bit），流的逻辑是：**进入本芯片的多播路由器 → 查"路由键前缀" → 匹配哪几条路由表项 → 把这包复制并广播到该路由项指定的 (出端口集合, 本地核集合)**。

所以在 SpiNNaker 的世界观里：

- **图 = 多个数据包 + 多播路由表**
- 不同路由表项定义不同的 multicast tree（多播树）：哪些源打到哪些目的、用什么路径走
- 路由表项的 prefix pattern 决定了图的**通信模式**

## 3.3 谁来改路由表？—— 软件层（sPyNNaker + SpiNNaker OS）

SpiNNaker 所有的"图重配"都在软件层完成：

|软件组件|作用|
|---|---|
|**sPyNNaker**|用 Python 写网络描述，然后编译 → 生成每片路由表|
|**SpiNNaker OS**|在每片上接收 route-table-load 命令，把路由表项写进对应核的 SRAM|
|**多播路由器硬件**|之后跑起来时只看路由表转发，不再需要 CPU 介入|

也就是说：**网络结构在编译期(model description)画好，运行时只需要发"上电 → 路由表写入 → 跑起来"的命令**。

## 3.4 时间常数也是 ms 级

SpiNNaker 的路由表发布是 **ms 级**——由软件控制做"新表替换旧表"的原子操作。SpiNNaker 2 把它做得更精细：

- 路由表容量增长（**每片最多 1024 个多播条目**，原作 544）
- 支持**层次化多播**（一棵路由树下嵌套更细的子路由表）
- 改的时候不需要停整个 mesh，"分区切换"

## 3.5 优势与天花板

优势：

- **完全开源**：从 ARM 核、操作系统、Python 描述、到编译工具链全部 SW，因此可被第三方研究定制化
- **天然支持 event-driven**：单次 spike 多播费时约 1µs，但聚合任务需要数 ms
- **路由表项匹配是 O(1) 硬件查表**，转发极快

天花板：

- mesh 物理拓扑不能换 → 路由表也只在 mesh 之上定义 multicast tree，没有并行多图
- 无 QoS / 无带宽分层 → 想分清 Prefill 和 KV 迁移流量就走不了
- 运行期路由表替换会有 spike in-flight 丢失的窗口期（毫秒级）

## 3.6 等价说法（科普版）

把 SpiNNaker 2 想象成一个**电话总机+邮电网络**：

- 每条"电报"等于一个脉冲包，头上写着目的地邮编（路由键）
- **总机（多播路由器）的转接表（路由表）由站长（软件）按时刻表更新**，几 ms 一次
- 但**铁路线（mesh 物理结构）修好就定型了**，电报只能沿铁路走、不能凭空飞

# 四、Loihi 2 vs SpiNNaker 2 —— 一图三事对比

|维度|Loihi 2|SpiNNaker 2|
|---|---|---|
|改的层|**L3（图实例，突触表）**|**L2（路由，多播表）**|
|改的颗粒度|一条突触（细到每对神经元的连接项）|一条多播路由 prefix（细到多播树的一个分叉）|
|谁触发|**自发学习**（spike 到来 + neuromodulator 信号触发微码）|**人为操作系统**（软件层静态注入）|
|时间常数|ms（实际是细粒度、异步）|ms（原子性，路由表替换短暂盲区）|
|改的灵活度|高（可塑非常细）|中（路由 tree 可任意重画，但 mesh 不动）|
|并行图共存|**= 1**（始终只有一张表在生效）|**= 1**（多播表是同一份）|
|学习|**在线 STDP-lite（hub：三因子）**|无（需要外置训练）|
|开源程度|部分 SDK 开源（NxSDK）|**高度开源**（硬件 + OS + Python 全栈）|

**关键差异**：Loihi 改的是"**笔道**"，SpiNNaker 改的是"**信号流向往哪儿**"。两者都未触到"在同一张物理 mesh 上并行活跃多张逻辑图"那一层，所以上一轮我那张定位图里他俩都是"并存图数 = 1"。

# 五、回答最初那个问题：为什么他俩改的不是同一件事？

把上一段**用一个比喻串起来**：

> 把一张图纸想成一颗城市的地铁规划图。
> 
> - **物理画布**：可以理解为地铁隧道本身，西边的隧道、河道、桥就是 mesh 物理拓扑。两家都不能重建地铁隧道（光罩刻死）。
> - **Loihi 2** 在改的是**"哪些街道口之间允许开共享单车"** —— 即突触表 —— 一条一条地拉通或拆除，权重就是车速准许有多
> - **SpiNNaker 2** 在改的是**"信号灯怎么配时、哪些路口的车流允许左转"** —— 即多播路由表项 —— 整张骑车网络结构不变，但骑车时被允许走的路线集变了
> - **TCC 想再加一层**：在还不拆路的情况下，能同时给共享单车、电动车、送货车、外卖无人机画**多张不同路径规划的透明层**，并能在一个时钟周期内把当前的"哪张图层"翻到下一张

这层"**多张图层共存**"才是上轮定位图中 Loihi 2、SpiNNaker 2 与 Cerabras 的差距所在——Cerebras 把这个多图层做到了 24 张但冻在编译期，Loihi 与 SpiNNaker 还停在"只有一张图层"。

# 六、写在最后：为什么这道细节值得讲清

直接回答汇报里可能踩的坑：

1. **"ms 级重构" 在 Loihi 是异步渐变**，在 SpiNNaker 是原子替换——前者改起来很细、后者改起来很整齐，但都不是"切换一整张逻辑图集"。
2. **Loihi 的"学习"是真正的在线学习**，这是个独特卖点（其他厂商都没有类似机制在线改图的）。
3. **SpiNNaker 的可改层不深于通信模式**——如果类比成数据库，SpiNNaker 只能调整"索引的 lookup 表"，不能新增/删列。
4. **两家在"并存图数=1"上是一致的**，这就是为什么在汇报矩阵里他俩落在"单图区"竖列的中间位置，并不和 Cerabras 的"24 色多图并存"竞争进度条。

把这条线讲清楚后，"Cerebras 的多图还不够快（限定编译期）"这一句的用意就能落实——这是汇报中"唯一交叉点无人占领"的核心证据之一。
