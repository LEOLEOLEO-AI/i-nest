## 三、项目背景必须覆盖的内容

背景要围绕“为什么必须从处理器中心走向拓扑中心”展开。

必须写清楚：

1. 传统冯·诺依曼体系存在数据搬移墙和通信墙。可引用 Horowitz, ISSCC 2014：32 位浮点乘约 3.7 pJ，片外 DRAM 访问约 1.3-2.6 nJ，数据搬移能耗约为计算能耗的 350-700 倍。
2. GPU、TPU、NPU、Cerebras、SambaNova、Graphcore、FPGA 等路线都在网络互连、片上网络、芯粒互连、数据流调度上持续创新，但本质上仍以算子、矩阵、Kernel、逻辑或阵列为主要可编程对象。
3. AI 大模型训练、推理、视频特征分析、多智能体、多传感器融合、FFT、DBF、实时 RF 仿真等任务对多样化拓扑有迫切需求。
4. 训推一体化需求显著增强。现有主流体系通常将训练芯片和推理芯片分化设计，而 TCC 希望通过液态拓扑实现推理拓扑态与轻量训练拓扑态的快速切换。
5. 无人平台、车辆、无人机、卫星等场景需要在单一端侧硬件上同时支持 AI 推理、轻量训练、RF 感知、存储、通信与计算，形成端到端感知-存储-计算智能。
6. 可将 Enfrace/Enfabrica 类网络接口与内部交换增强公司作为行业趋势佐证：AI 基础设施正在把网络能力从外部交换网络下沉到节点、板卡和芯粒互连层。但 TCC 更进一步，把拓扑态、路由原语、变换原语和 TCC-Link 作为第一可编程对象。
7. 可写“类 DRBE 的 RT-HPC+RF 融合需求”作为数字 RF 战场仿真方向，但不要写特定 WSE 或合同案例。

## 四、核心范式

TCC，Topology-Centric Computing，拓扑中心计算。

核心命题：拓扑即计算。

TCC 不把计算仅理解为节点内的矩阵乘、算子执行或逻辑组合，而是把网络拓扑、数据路由、通信原语、变换原语、时隙调度和 Epoch 切换统一视为计算过程的一部分。

TCC 的基本表达为：  
计算任务 = Route 原语 + Transform 原语 + Topology Page + Epoch Commit。

其中 Route 原语负责数据在拓扑中的流动、复制、聚合、交换与组织；Transform 原语负责在数据流经网络和 MacroTile 时发生矩阵、映射、规约、扫描、查表和梯度更新等变换。

## 五、6R+6T 原语体系

### 6R 路由原语

1. FUSE：融合、聚合、局部合并。
2. CAST：广播、组播、权重分发、特征分发。
3. SWAP：成对交换、重排、专家路由、FFT 交换。
4. FLY：蝶形路由、FFT、AllReduce 树形规约。
5. RING：环形流水、梯度聚合、流式传输。
6. MESH：邻域通信、视频特征融合、局部注意力、空间感知网络。

### 6T 变换原语

1. FOLD：规约、累加、求和、聚合。
2. SCAN：前缀扫描、流式状态传播。
3. MAP：逐元素映射、激活、归一化、量化。
4. MM：矩阵乘、线性层、DBF 复数乘累加。
5. LUT：查表、非线性映射、校准补偿。
6. GRAD：梯度、LoRA/Adapter 轻量训练更新。

### 2 年 MVP 实现范围

硬件实现 4R+3T+GRAD-lite：  
R.CAST、[R.FLY](http://R.FLY)、R.RING、R.MESH；  
[T.MM](http://T.MM)、[T.MAP](http://T.MAP)、T.FOLD；  
预留 R.FUSE、R.SWAP、T.SCAN、T.LUT、T.GRAD 完整接口；  
实现 GRAD-lite 支持 LoRA/Adapter 轻量训练闭环。

## 六、元拓扑与高阶拓扑生成

元拓扑只包括：

1. Mesh
2. Ring
3. Butterfly
4. Cast Tree

Chiplet 和 Wafer 不是元拓扑，而是部署尺度、封装尺度或系统集成尺度。

6R 与元拓扑对应关系：

1. R.MESH 对应 Mesh。
2. R.RING 对应 Ring。
3. [R.FLY](http://R.FLY) 对应 Butterfly。
4. R.CAST 对应 Cast Tree。
5. R.FUSE 是在 Mesh、Ring、Butterfly、Cast Tree 上叠加的融合规约逻辑。
6. R.SWAP 是在 Mesh 或 Butterfly 上形成的成对交换逻辑。

技术路线为：  
元拓扑 + SDI 化合键 = 高阶可编程拓扑。

SDI 化合键可抽象为：  
b = (u, v, type, path, vc, rate, op, epoch)。

其中 u 和 v 为端点，type 为原语类型，path 为路径，vc 为虚通道，rate 为带宽配额，op 为绑定的变换操作，epoch 为拓扑版本。

通过 Topology Page SRAM、TopoColor μRouter、虚通道、时隙调度和 Epoch Commit，可以在固定物理元拓扑上快速显现不同高阶网络拓扑。

不同高阶拓扑在推理与训练中的功能：

1. 推理态：CAST 权重广播，MESH 局部特征融合，FOLD 局部规约，MM 完成 INT4/INT8 前向计算。
2. 轻量训练态：GRAD-lite 计算 LoRA 梯度，RING/FLY/FUSE 完成梯度聚合，CAST 回写低秩参数。
3. 视频特征态：MESH 进行多路特征邻域融合，FOLD 进行特征压缩。
4. FFT 态：FLY 显现蝶形网络，支持 64-1024 点流式 FFT。
5. DBF 态：CAST 分发阵元数据或权重，MM 完成复数乘累加，FOLD 完成波束求和。
6. RT-HPC+RF 态：通过仿真平台模拟大规模 MacroTile 上 RF 信号处理与实时 HPC 耦合。

## 七、TCC-Link 0.5 与 UCIe 的关系

TCC-Link 0.5 不是简单替代 UCIe，而是在兼容芯粒互连发展趋势的基础上，向上增加 TCC 所需的拓扑语义层。

论证重点：

1. UCIe 面向 Die-to-Die 物理层与链路层互连标准化，是芯粒互连的重要基础。
2. TCC-Link 0.5 可以借鉴 UCIe 的 PHY、封装、链路可靠性和 Die-to-Die 生态，但不局限于点到点数据搬运。
3. TCC-Link 在网络层和控制层增加 Topology Page、TopoColor、虚通道、Epoch Commit、R/T 原语描述、性能计数器和拓扑切换语义。
4. TCC-Link 的意义在于把芯粒互连从“数据通路”提升为“可编程拓扑计算通路”。
5. 2 年项目中形成 TCC-Link 0.5 草案，为后续 TCC 路由与变换芯粒、TCC-AI、TCC-RF 和 Wafer 级系统打基础。

## 八、FPGA MVP 平台

正文中必须写入：  
FPGA 验证平台采用 ALINX AXVU13F，核心器件为 Xilinx Virtex UltraScale+ VU13P。

主线演示：训推一体液态拓扑 MVP。

技术方案：

1. 基座模型权重冻结。
2. 推理侧采用 INT4/INT8 前向计算。
3. 训练侧仅支持 LoRA/Adapter 低秩参数更新。
4. 通过 GRAD-lite 实现最小梯度链路。
5. 推理页和训练页常驻 FPGA 片上 SRAM。
6. 通过 Topology Page 和 Epoch Commit 实现推理拓扑态与训练拓扑态切换。
7. 验证不重启运行时的训推闭环。

最小演示流程：  
输入任务 -> INT4 推理 -> 产生误差或 loss -> 切换至 LoRA 训练态 -> GRAD-lite 更新低秩参数 -> loss 下降 >=30% -> 切换回推理态 -> 输出改善结果。

MVP 顶层模块建议：

1. tcc_mvp_13p_top
2. tcc_link_ctrl
3. topology_page_sram
4. epoch_manager
5. topocolor_mu_router
6. cgra_macrotile_4x4
7. int4_infer_engine
8. grad_lite_lora_engine
9. video_feature_trace_engine
10. fft_dbf_trace_engine

## 九、液态拓扑仿真平台

仿真平台是本项目的关键成果之一。

场景数量要求：不少于 3 类。

建议至少覆盖：

1. 训推一体场景：推理拓扑态与 LoRA 训练拓扑态切换。
2. AI 推理与视频特征分析场景：多路视频特征融合、特征折叠、网络内聚合。
3. RF 感知场景：FFT、DBF、RT-HPC+RF 类数字 RF 仿真。

仿真规模：支持 16-4096 个 MacroTile 的规模扩展。

仿真输出指标：η、κ、τ、σ、Φ_RT、带宽利用率、链路拥塞、拓扑切换开销、存储访问量、能耗估计、端到端延迟。

仿真平台要形成《TCC 架构综合优势报告》，用于说明 TCC 在训推一体、智能体、RF 感知、端侧感存算一体中的换道超车价值。

## 十、关键考核指标

统一使用以下符号：η、κ、τ、σ、Φ_RT。

### 一级指标

1. 算力纯度 η  
目标：>=70%，挑战 >=80%。  
定义：原语流水有效计算周期占总执行周期比例。
2. 通信折叠率 κ  
目标：>=5x，挑战 >=10x。  
定义：传统 CPU/GPU/固定互连链路延迟与 TCC 网络内折叠链路延迟的比值。
3. 拓扑液化度 τ  
目标：<=1 us，挑战 <=500 ns。  
定义：从拓扑切换提交到新拓扑可用的时间。
4. 模态切换比 σ  
目标：<=10%，挑战 <=5%。  
定义：训推模态切换时间占一个任务窗口或单轮更新窗口的比例。
5. 原语实现度 Φ_RT  
目标：硬件完成 4R+3T+GRAD-lite，接口覆盖 6R+6T。

### 场景指标

1. 训推一体 MVP：LoRA/Adapter 轻量训练后 loss 下降 >=30%。
2. 拓扑切换：推理态与训练态切换 τ <=1 us。
3. 视频特征分析：特征融合链路 κ >=5x，挑战 >=10x。
4. FFT/DBF：仿真平台必选，硬件可选增强；支持 64-1024 点 FFT 和缩比 DBF Trace。
5. RTL 规模：>=8000 行，挑战 >=10000 行。
6. 仿真平台：支持 >=3 类场景。
7. 专利：>=5 项。
8. 论文：>=2 篇。
9. 标准草案：TCC-Link 0.5。
10. 报告：TCC 架构综合优势报告、芯粒适配验证报告、产业化论证报告。

## 十一、DBF 与 FFT 的定位

在 2 年、10 人、1000 万元财政经费的约束下，主验收应聚焦训推一体液态拓扑 MVP。

FFT/DBF 的定位为：

1. 仿真平台必选场景。
2. FPGA 硬件可选增强。
3. 如果资源允许，可实现缩比演示，例如 8/16 阵元 x 4 波束，10-25 MSps，256 点 FFT Trace 流。
4. 不要求 2 年内完成全规格高速 ADC 接入与完整 DBF 硬件链路。

这样既能保留 TCC 面向 RF 感知与 RT-HPC+RF 的战略价值，又避免 DBF 工程复杂度拖累主线验收。

## 十六、战略价值

TCC 的战略意义在于：

1. 从 GPU/NPU/TPU 以算子和矩阵为中心的路线，切换到以拓扑态和网络复杂度为中心的路线。
2. 为训推一体芯片提供新路径，通过液态拓扑实现推理态与轻量训练态快速切换。
3. 为多功能智能体提供感知、存储、计算、通信一体化底座。
4. 为类 DRBE 的 RT-HPC+RF 融合场景提供数字 RF 仿真和信号处理一体化能力。
5. 为后续 TCC-AI、TCC-RF、TCC-Link、TCC-Sim、TCC-Edge 形成工程化路线。
6. 为 iNEST 智涌脑奠定液态硬件与网络时空协同复杂度的技术基础。
