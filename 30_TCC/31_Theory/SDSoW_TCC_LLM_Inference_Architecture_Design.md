# SDSoW+TCC赋能LLM推理关键问题答复

# SDSoW + TCC 赋能 LLM 推理关键问题答复

---

## 一、控制平面实现机制

### 1. 总体架构

控制平面采用**"全局决策 + 局部执行"的分层架构**，将语义决策与执行动作分离，兼顾全局最优与响应速度。

**硬件构成：**
- **全局控制器**：集中式控制节点，部署在晶圆外的主控服务器上，负责全局资源视图、拓扑规划与故障协调
- **分布式代理**：部署在每个 SDI 交换节点内的轻量级控制逻辑，负责本地状态采集、配置执行与链路级故障检测
- **带外管理通道**：SDI Mesh 中独立的控制平面通路，与数据平面逻辑隔离，确保控制流量不被数据流量阻塞

**软件构成（三大模块）：**
- **TCC 控制平面**：拓扑管理、故障检测、资源调度、拓扑页库维护、多任务冲突仲裁
- **拓扑编辑器**：可编程的拓扑配置工具，生成拓扑页候选
- **运行时管理器**：阶段切换触发、负载均衡、热更新、故障恢复

### 2. 工作流程

系统从上电到任务执行的完整流程如下：

1. **上电初始化**：晶圆基板电源管理单元（PMU）上电，SDI 交换节点逐行启动自检
2. **拓扑发现**：控制平面扫描所有可用算力芯粒、存储芯粒和 SDI 节点，构建全局资源拓扑图
3. **故障检测与冗余映射**：识别缺陷节点，通过冗余路径和备用芯粒自动重映射，保障系统可用
4. **拓扑页预加载**：编译器生成的拓扑页（推理页、训练页等）预加载到 SDI 影子配置寄存器
5. **任务启动**：主控下发任务，激活初始拓扑页，算力芯粒开始计算
6. **阶段切换**：任务运行到阶段边界时，SDI 在微秒级时间内原子切换到下一个拓扑页
7. **运行时动态调整**：控制平面根据负载和故障情况，热更新拓扑页，实现动态演化

### 3. 上位机与主控 CPU

**存在上位机，主控 CPU 部署在晶圆外的服务器上，不在晶上。**

这一设计的考量是：将复杂的拓扑优化、任务调度、编译分析放在算力充足的上位机完成，晶圆专注于计算与互连执行。长期演进方向是将部分关键运行时逻辑下沉到 SDI 节点内置的轻量处理器核，实现更快的本地切换响应，但全局控制仍由上位机承担。

### 4. 电源、时钟与 DFT 管理

采用**分层管理**模式，主控 CPU 制定策略，底层硬件执行，各芯粒自主管理局部细节：

| 管理功能 | 主控服务器 | 晶圆基板/SDI | 各芯粒自身 |
|---------|-----------|-------------|-----------|
| 全局策略制定 | ✅ | — | — |
| 电源域开关 | 下发指令 | 执行配置 | 本地门控 |
| 时钟配置 | 域规划 | 分发网络 | 本地分频 |
| 复位序列 | 全局触发 | 逐域分发 | 本地复位树 |
| DFT 测试调度 | 计划与分析 | 晶圆级测试 | 芯粒内自测 |
| 运行时监测 | 全局汇总 | 区域采集 | 本地计数器 |

**电源管理**：晶圆基板配备独立 PMU，支持分区域电源门控，可按拓扑激活区域精细供电——未激活的 SDI 节点和算力芯粒可进入低功耗状态。

**时钟复位管理**：全局时钟由基板 PLL 分发，SDI 节点支持独立时钟域配置和动态频率切换。复位采用分层串行方式，避免同时上电产生电流浪涌。

**DFT 测试**：采用三层测试策略——晶圆级探针测试 → 键合后中间测试 → 最终系统测试。功能芯粒键合前先做 Known-Good-Die（KGD）筛选，SDI 节点内置自测试（BIST）。

### 5. 芯粒工作状态与全局状态寄存器

采用**"分布式采集 + 集中汇总"**模式：

- 每个 SDI 交换节点和算力芯粒均配置一组状态寄存器，记录链路状态、端口占用、队列深度、温度、功耗、错误计数等
- 控制平面通过带外管理通道周期性轮询或事件触发采集，构建全局系统状态视图
- 状态信息不仅用于监控，更作为运行时管理器的输入，用于动态调整拓扑选择和负载分配

对于 LLM 推理场景，关键状态指标包括：各算力芯粒利用率、Token 队列深度、KV Cache 命中率、链路带宽利用率、拓扑页驻留命中率等。

### 6. 中断上报机制

采用**分层上报 + 语义聚合**：

- **链路级中断**：SDI 节点检测到链路故障、误码率超阈值、缓冲区溢出等，产生本地中断，通过带外通道上报
- **芯粒级中断**：算力芯粒通过侧带信号或专用中断引脚上报异常（计算错误、温度告警、ECC 错误等）
- **中断聚合**：SDI 交换阵列中的中断聚合节点，将分布式中断按优先级和类型聚合后上报主控 CPU
- **同步机制**：通过阶段边界同步原语和逻辑时钟原语，保障跨节点的阶段切换一致性

### 7. 全局内存管理

SDSoW 的内存管理与传统架构有本质区别——**存储芯粒是系统的一等公民，而非外设**：

- **拓扑可编程存储**：HBM/存储芯粒均匀分布在算力芯粒周围，通过 SDI 直连，存储与计算的连接拓扑可根据访存模式动态调整
- **全局地址映射**：控制平面维护全局内存映射表，将各存储芯粒地址空间统一编址。但这不是传统共享内存模型，而是"拓扑感知的分布式内存"——数据路径由拓扑页决定
- **数据驻留优化**：LLM 推理的 KV Cache 可分布式驻留在各算力芯粒本地存储中，通过 All-to-All 拓扑实现 Token 级调度，避免全局内存搬移
- **一致性保障**：以显式数据移动 + 阶段边界同步保证一致性，不依赖硬件缓存一致性协议——一致性由拓扑结构本身保障

## 二、协议栈分层与晶上系统软件部署

### 1. 协议栈分层架构

从应用层到芯粒物理层，整体分为六层：

| 层级 | 名称 | 核心功能 |
|-----|------|---------|
| L6 | **应用层** | 模型框架（PyTorch/TF）、任务调度、用户接口 |
| L5 | **TCC 编译层** | 阶段划分、兼容性检测、拓扑页生成、原语映射 |
| L4 | **控制层** | 拓扑页运行时管理、资源调度、冲突仲裁、故障恢复 |
| L3 | **拓扑语义层** | R/T/C 原语、拓扑页抽象、TCC-Link 协议 |
| L2 | **网络/链路层** | UCIe 链路层、流控、CRC 校验、重传机制 |
| L1 | **物理层** | UCIe PHY、SerDes、RDL 互连、混合键合 |

**关键特点：**

- **底层兼容行业标准**：物理层和链路层与 UCIe 标准完全兼容，确保生态互通，第三方芯粒可直接接入
- **上层扩展拓扑语义**：在标准协议之上增加路由/变换/控制原语和拓扑页抽象，这是 SDSoW 的核心增值层
- **三种接入模式**：新设计芯粒推荐集成 TCC-Link 接口 IP 以获得最佳性能；已有芯粒通过标准 UCIe 直接接入；其他接口（PCIe/CXL/Ethernet 等）通过协议转换桥接接入

### 2. 晶上系统软件部署位置

**系统软件主体部署在晶圆外的主控服务器上，不运行在晶上。** 具体分布如下：

- **TCC 控制平面 + 编译器**：运行在晶圆外的主控 CPU/服务器
- **运行时管理器**：核心逻辑在上位机，部分关键路径（如拓扑切换触发、本地故障处理）下沉到 SDI 节点内置处理器，实现微秒级本地响应
- **SDI 驱动/配置工具**：成熟量产级，提供 SDK + API，运行在主控 CPU 上
- **拓扑页配置表**：预加载到 SDI 节点的影子配置寄存器（双缓冲），运行时只需"选通"操作

SDSoW 没有传统意义上"运行在晶上的操作系统"，而是采用**"上位机全局管控 + 晶上分布式执行"**的混合架构。晶圆定位为执行载体而非自治计算系统。

## 三、TCC 编译器编程模型

### 1. 核心定位

TCC 编译器采用**拓扑数据流编程模型**。与传统编程范式的区别在于：

- CPU 编程定义的是"指令流"——每条指令做什么运算
- GPU 编程定义的是"线程流"——每个线程执行什么任务
- TCC 编程定义的是"连接流"——节点之间怎么连、拓扑结构是什么

编程对象从"计算什么"转向"如何连接"，连接结构本身就是计算的承载者。

### 2. 三层抽象体系

| 抽象层级 | 表示形式 | 编程对象 | 生成时机 | 生效代价 |
|---------|---------|---------|---------|---------|
| 顶层 | 计算图/数据流图 | 算子、张量、依赖边 | 编译输入 | — |
| 中间层 | 拓扑页 + 原语序列 | 连接拓扑、变换算子、阶段边界 | 离线编译 | 微秒级页面提交 |
| 底层 | 拓扑页配置镜像 | SDI 寄存器配置、交叉开关状态 | 运行前预载 | 亚微秒级原子切换 |

### 3. 原语体系

TCC 定义了路由（R）、变换（T）、控制（C）三类共 16 条原语，构成编程模型的"指令集"：

- **路由原语（6 条）**：塑造数据依赖图，包括全归约、全收集、广播、全交换、流水归约散射、邻域交换
- **变换原语（6 条）**：端点或链路局部计算，包括矩阵乘加、向量归约、逐元素映射、前缀扫描、查表、特殊函数
- **控制原语（4 条）**：阶段边界与同步，包括拓扑配置与页面提交、逻辑时钟/因果序、边界同步、DMA 数据搬运

每条原语对应一种不可被其他原语低代价替代的结构角色，均可从数据流图中识别并映射为拓扑控制器可执行的状态，且在拓扑不兼容时可退化为传统通信或局部计算。

### 4. 编译流程

编译器输入为张量程序或计算图，输出为原语序列与拓扑上下文序列，共分七步：

1. **阶段划分**：将完整计算图切分为"局部计算阶段 + 跨端点通信阶段"的交替序列
2. **数据流图标注**：对每个通信阶段构造带标签数据流图，标注边类型、张量形状、数据类型、顺序要求、带宽需求和数值约束
3. **兼容性检测**：在拓扑库中寻找与数据流图精确匹配或低失真嵌入的拓扑结构
4. **原语选择**：将匹配阶段映射为对应的原语组合
5. **残余通信生成**：对无法拓扑原生实现的边，生成 fallback 通信路径
6. **代价模型判断**：比较拓扑中心执行与传统执行的总代价，收益不足则回退
7. **拓扑上下文发射**：输出逻辑拓扑配置表、端点算子配置、缓冲区映射和执行顺序

### 5. LLM 推理场景下的体现

以 Transformer 推理为例，TCC 编译器将模型计算图自动映射为：

- **注意力层**：All-to-All 拓扑用于 KV 交换 + 矩阵乘加 + 分数规约
- **前馈层**：Mesh 拓扑 + 两次矩阵乘 + 激活函数
- **Token 调度**：全交换拓扑用于 Token 分发（稀疏专家场景下支持剪枝）
- **层间同步**：边界同步 + 因果序维护

**当前成熟度**：标准 Transformer 类模型已实现半自动排布（编译器生成 + 人工微调）；长期目标为完全自动化，用户上传模型即可自动完成拓扑优化和部署调度。

## 总结

SDSoW + TCC 赋能 LLM 推理的核心逻辑是：**将大模型各阶段的数据流拓扑，从"在固定互连上来回搬运数据"转变为"让互连拓扑跟着数据流走"**。通过上位机编译规划、晶上硬件快速切换拓扑页，使推理的每个计算阶段都匹配最优连接结构，从而大幅提升算力利用率。

这一架构的差异化优势体现在三个层面：
- **架构层面**：拓扑从固定设施变为可编程的一等对象，连接结构本身承载计算语义
- **性能层面**：算力利用率从传统固定拓扑系统的 30%-50% 提升至 90% 以上
- **工程层面**：用成熟工艺通过系统级集成实现超越单一先进工艺芯片的性能，全链条自主可控
