# Groq TSP 张量流处理器深度解析：把确定性写进硬件的深度学习加速架构

### 🏆 这篇论文讲了什么核心成果？

Groq 第一代 TSP 用**功能切片式架构**替代传统多核，在 **14nm、25×29 mm** 芯片上实现 batch=1 下 **20.4K images/s** 的 ResNet50 推理吞吐，单图延迟 **49 μs**，计算密度超 **1 TeraOp/s/mm²**。
- **论文信息**：Dennis Abts 等，Groq, Inc.，ISCA 2020，DOI 10.1109/ISCA45697.2020.00023
- **核心突破**：去掉仲裁器与缓存，执行时间和功耗**逐周期可预测**

### 🧩 为什么要重新设计多核架构？

传统 CPU/GPU 的反应式机制**无法界定最坏性能**，数据中心算力与散热规划难以落地。
- **传统架构痛点**：缓存、分支预测、预取器提升了平均性能，但运行时停顿来源不可控
- **TSP 思路**：以 tensor 抽象为中心，用空间换确定性，重新组织多核形态

### 🔧 什么是功能切片？和传统多核有什么不一样？

把"局部异构、全局同构"的传统多核**完全反过来**，变成局部同构、全局异构。

| 维度 | 传统多核（CMP） | TSP 功能切片 |
| :--- | :--- | :--- |
| tile 功能 | 每个核功能齐备、同构 | 每个 tile 只做一类功能 |
| 全局结构 | 二维 mesh 核阵列 | 同类功能纵向堆叠成"切片" |
| 指令流方向 | 每个核内部独立流水 | 指令垂直（南北）流动 |
| 数据流方向 | 核间通过片上网络交换 | 数据水平（东西）横穿切片 |
- **superlane 定义**：二维 mesh 的每一行 = 所有功能切片的一个横截面，是最小计算粒度
- **ICU 面积占比**：指令控制与派发单元仅占芯片面积**不到 3%**
- **向量流水线**：每个功能切片实现 20 级向量流水，每个 tile 负责 320 元素向量中的 16 个

### 🚰 生产者-消费者流是怎么工作的？

功能切片固定不动，数据像传送带一样**流过处理单元**，中间结果无需写回内存。
- **经典对比**：
  - RISC：LOAD → LOAD → ADD → STORE，操作数在 GPR 与主存间来回搬运
  - TSP：Read → Read → Add → Write，结果直接在流寄存器间传递
- **流寄存器堆（SR）**：全芯片范围、架构可见，编译器可精确计算数据位置
- **流编址规则**：
  - 每 lane 共 **64 条逻辑流** = 32 条向东 + 32 条向西
  - 每个流元素 1 字节，int16 用 2 条流、int32/fp32 用 4 条流
  - 多字节类型按自然流对齐，由编译器完成

### ⏱️ 确定性是怎么实现的？

删掉仲裁器和缓存，把**时序信息直接做进指令集**，编译器做时空二维调度。
- **两个关键时序参数**：
  - `dfunc`（功能延迟）：指令产出结果到流上需要的周期数
  - `dskew`（指令-操作数偏斜）：指令派发与操作数到位的时间关系
- **执行时间公式**：T = N（切片 tile 数） + dfunc + δ(j,i)（流寄存器间传输延迟）
- **交错执行**：320 元素 SIMD 指令沿切片垂直流水，相邻 superlane 数据错开 1 个周期
- **同步机制**：
  - 整芯片屏障同步仅需 **35 个时钟周期**
  - 复位后只需一次全局同步，后续通过流寄存器无同步传递结果
  - 切片内用 repeat-NOP 协调时序，高阶同步用 Sync/Notify 原语
  - 编译器维护逻辑程序时间，跟踪 **144 条独立指令队列**状态

### 📐 TSP 芯片的完整规格是什么？

14nm 工艺下集成 268 亿晶体管，峰值算力 820 TeraOps/s（1 GHz）。

| 项目 | 数值 |
| :--- | :--- |
| 工艺/面积 | 14 nm，25 × 29 mm |
| 标称时钟 | 900 MHz（推算按 1 GHz） |
| 晶体管 | 26.8 B |
| 峰值算力 | 820 TeraOps/s |
| 片上 SRAM | 220 MiB（88 切片 × 2.5 MiB） |
| 向量粒度 | minVL=16，maxVL=320 元素 |
| 独立指令队列 | 144 个 ICU |
| 向量 ALU | 5,120 个（320 lane × 16 个/lane） |
| 矩阵阵列 | 4 × (320 × 320) MACC |
| 片间带宽 | 3.84 Tb/s |
- **芯片布局**：分东西两个半球，各 44 个 MEM 切片，MEM₀ 靠近 VXM、MEM₄₃ 靠近 SXM

### 💾 内存系统怎么设计的？

用 88 个内存切片提供 **176 路并发**，带宽余量充足。
- **内存抽象**：分区全局地址空间（PGAS），地址均匀分布在 88 个切片上
- **并发机制**：伪双端口 SRAM + bank 位暴露给软件，编译器显式管理底层 SRAM
- **寻址模式**：直接寻址（Read/Write）+ 间接寻址（Gather/Scatter）
- **带宽账本**（1 GHz）：
  - 流寄存器带宽：20 TiB/s
  - SRAM 总带宽：55 TiB/s（每半球 27.5 TiB/s）
  - 指令取指最大占 2.25 TiB/s，剩余 25 TiB/s 服务 20 TiB/s 流带宽
- **ECC 设计**：
  - SECDED 编码（单错纠正、双错检测），9 位校验 + 128 位数据
  - 只在生产者端生成校验位，消费者端检查，覆盖 SRAM 和流数据通路
  - 软错误自动纠正并记录到 CSR，可作为芯片老化的早期指标

### ⛓️ 功能切片能怎么组合？

不同切片可**链式串联**，中间结果不写回内存，实现数据流局部性。
- **链式组合形式**：F(x,y,z) = MEM(x) → SXM(y) → MXM(z)
- **方向可控**：每个切片可选择结果流方向，实现流的"掉头"
- **能量比例性**：向量长度 16–320 元素可调，未使用的 superlane 可真正断电

### 📋 指令集包含哪些功能？

跨五大功能领域，每条指令都暴露时序信息。

| 功能模块 | 核心指令 |
| :--- | :--- |
| ICU | NOP、Ifetch、Sync、Notify、Config、Repeat |
| MEM | Read、Write、Gather、Scatter |
| VXM | 一元/二元运算、类型转换、ReLU、TanH、Exp、RSqrt |
| MXM | LW（加载权重）、IW（安装权重）、ABC、ACC（累加） |
| SXM | Shift、Permute、Distribute、Rotate、Transpose |
| C2C | Deskew、Send、Receive |
- **VXM 细节**：每 lane 16 个向量 ALU，无状态标志位，提供饱和/取模两种算术变体，支持 lane 内 ALU 链式串联
- **MXM 细节**：
  - 4 个独立 320×320 乘累加平面，每个由 20 个 16×16 supercell 构成
  - 支持 int8 和 fp16 输入，结果累加到 int32/fp32，最后一次舍入
  - 不到 40 周期可装完全部 409,600 个权重，装好后每周期生成一个新点积
- **SXM 细节**：
  - 南北向 lane 移位 + 选择模式，实现张量 reshape
  - Permute 重映射 320 lane，Distribute 重排 superlane 内 16 lane
  - Transpose 支持 16×16 二维转置，共 2 个 SXM 实例，最多 4 个转置同时进行
- **C2C 细节**：16 条 link × 4 lane × 30 Gbps × 2 方向 = 3.84 Tb/s，含 PCIe Gen4 主机接口

### 🧪 ResNet50 实战效果如何？

硅片回片 5 个月即完成验证，优化后延迟降低约 5,500 周期。
- **背景**：2019 年 7 月硅片回片，距 ISCA 截稿仅 5 个月，在全新工具链上实现 ResNet50
- **内存优化**：并发流操作数分配到不同 MEM 切片，bank 交错实现读写并行
- **流水线重叠优化**：调整内存分配模式，上一 pipeline 未写完即可启动下一 pipeline，整体延迟降约 5,500 周期
- **量化策略**：后训练逐层对称 int8 量化，MXM 累加至 int32/fp32 再 requantize，量化损失仅 **0.5%**
- **通道深度优化**：
  - 标准 ResNet50 通道为 2 的幂，与 320×320 MXM 错配导致利用率浪费
  - 训练通道深度撑满 320 的变体，Top-1 从 75.6% 升至 **77.2%**，Top-5 从 92.8% 升至 **93.6%**
- **确定性推算**：从 ResNet50 实测可精确推算 ResNet101（14.3K IPS）、ResNet152（10.7K IPS）性能

### 📊 性能、功耗与对比表现如何？

计算密度约为 Volta 100 的 5 倍，batch=1 推理延迟约为 Habana GOYA 的 1/5。
- **Roofline 模型**：
  - 倾斜区：内存带宽受限（权重装载阶段）
  - 峰值区：算术单元饱和，受计算能力限制
- **功耗特征**：功耗尖峰对应 4 个 conv2d 同时执行、算术吞吐打满的周期
- **关键对比**：

| 指标 | TSP | 对比对象 |
| :--- | :--- | :--- |
| ResNet50 batch=1 吞吐 | 20.4K images/s | 约为 Google TPU v3 大 batch 的 2.5× |
| 单图推理延迟 | 49 μs | 约为 Intel/Habana GOYA 的 1/5 |
| 计算密度（Ops/晶体管） | 30K DL Ops/s/晶体管 | 约为 Volta 100（6.2K）的 5× |

### 🔍 和其他架构有什么本质区别？

核心差异在于**完全放弃动态机制，把不确定性全部交给编译器静态解决**。
- **片上网络**：不做 packet routing，每周期流值推进一个 hop，无路由表、无仲裁、无流控
- **与 GraphCore IPU 对比**：IPU 用 bulk-synchronous 通信，TSP 除启动外无需显式同步
- **与 CGRA 对比**：CGRA 面向高度规则图像变换，TSP 用统一流模型覆盖通用张量操作
- **与 Stanford Imagine 对比**：Imagine 有本地寄存器堆和通信 FIFO，TSP 只有全芯片一套流寄存器
- **设计立场**：主动放弃稀疏剪枝、数据压缩等优化，以保持执行时间与功耗的严格确定性
  说白了，TSP 不是追求"尽量少算"，而是追求"每算一次都精确知道要多久、耗多少电"。

### 💡 这篇论文最核心的启发是什么？

重新定义了硬件与编译器的边界，把**性能从运行时统计量变成编译期确定量**。
- **三个反直觉决策**：
  1. 把同构核拆成异构切片，牺牲通用性换公共逻辑精简与数据流天然结构
  2. 确定性不是副产品，是主动放弃缓存、分支预测等功能换来的
  3. 性能可以在编译期精确交付，对数据中心容量规划价值不亚于峰值性能
- **深层意义**：传统架构默认硬件自己处理不确定性，TSP 把不确定性全部转移给编译器，换来逐周期可预测的硬件行为
