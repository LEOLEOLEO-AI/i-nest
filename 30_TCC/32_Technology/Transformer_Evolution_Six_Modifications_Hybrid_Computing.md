# Transformer 九年演进史：从标准架构到混合计算系统的六次改装

### 🔍 现在的大模型，还能用 2017 年的经典框图解释吗？

**不能**，今天的大模型已经换掉了一半核心组件。
- **最新案例**：
  - **Qwen3.6-27B**：64 层中仅 **16 层全注意力**，其余 48 层用 Gated DeltaNet（固定状态压缩历史）
  - **Kimi K3**：93 层中 **69 层 KDA + 24 层 MLA**，全注意力占比约 1/4
- **核心变化**：丢编码器 → 换归一化/位置编码/激活函数 → FFN 拆稀疏专家 → KV Cache 共享/压缩 → 不再层层全注意力
- **演进逻辑**：九年演进 = 六次针对瓶颈的改装，不是简单的代际替换

### 🏗️ 2017 年的标准 Transformer 是什么样的？

**编码器+解码器**结构，核心是**取消循环、并行计算**。
- **基本组成**：编码器读取完整输入，解码器生成时查看编码器输出 + 已生成 token；每层 = 多头注意力 + 前馈网络 + 残差连接 + LayerNorm
- **核心突破**：取消 RNN 串行主干 → 训练时 token 并行计算 + 任意位置直接建立关系
- **固有代价**：全注意力计算量随序列长度**二次增长**（N→2N，矩阵元素 N²→4N²）
- **本质矛盾**：哪些能力必须保留全局寻址，哪些可以换成更便宜的局部/稀疏/递归状态

### 🔀 第一次改装：为什么 Transformer 分成了三条路线？

按**任务用途分叉**，没有严格的代际淘汰。
- **三条分支**：
  - **Encoder-only（BERT 类）**：每个 token 看左右上下文 → 适合理解、分类、抽取
  - **Decoder-only（GPT 类）**：因果掩码，只看前文 → 适合生成式任务
  - **Encoder-Decoder（T5 类）**：输入先编码再生成 → 适合翻译、转写等边界清晰任务
- **现状**：大语言模型主流走 decoder-only 路线（可统一问答/写作/代码/规划为"预测下一个 token"），但另外两条仍在各自领域广泛使用

### ⚙️ 第二次改装：经典模块没换，内部换了哪些零件？

三个核心零件**渐进替换**，解决训练稳定与表达能力问题。

| 组件 | 原版（经典块） | 现代版（现代块） | 解决的问题 |
| :--- | :--- | :--- | :--- |
| 归一化 | Post-LN（残差后归一化） | Pre-Norm / RMSNorm | 深层网络训练不稳定 |
| 位置编码 | 固定正弦位置向量 | RoPE（旋转位置编码） | 相对位置信息表达 |
| 前馈网络 | 两层线性 + ReLU | SwiGLU（门控线性单元） | FFN 表达能力不足 |
- **关键结论**：Transformer 是可替换部件的框架，不是固定不变的框图；这些是长期工程累积，不是整齐划一的"某一代"

### 🧩 第三次改装：MoE 为什么能让模型参数变大却不慢？

把**总参数和激活参数分离**，用存储换容量。
- **核心机制**：稠密 FFN → 多个专家 + 路由器，每个 token 只调用少数专家
- **代表模型**：Llama 4、gpt-oss、DeepSeek V4、Kimi K3
- **代价与边界**：
  - 专家权重仍需全部存储
  - 训练/推理需跨卡通信，路由偏斜会导致设备过载
  - 只解决 FFN 容量轴，不直接解决长序列注意力成本

### 💾 第四次改装：KV Cache 是怎么被一步步压缩的？

从**每头一份**到**共享/低秩压缩**，减少解码带宽。
- **标准 MHA**：每个 Query 头对应独立 K/V 头 → 表达最充分，缓存最大
- **MQA**：所有 Query 头共享一组 K/V → 大幅减少显存读取
- **GQA**：Query 头分组共享 K/V → 质量与缓存的折中（常见配置：32 注意力头 / 8 KV 头）
- **MLA（DeepSeek-V2 引入）**：K/V 联合压进低秩潜变量 → 缓存潜变量，计算时恢复
- **澄清**：FlashAttention 是 IO 优化（分块+调度减少数据搬运），算出的仍是精确全注意力，没有改变架构

### 📏 第五次改装：为什么全注意力不再层层出现？

长上下文放大了**计算和缓存成本**，混合结构成为主流。
- **早期探索**：Transformer-XL（分段递归）、Longformer（局部窗口+全局位置）、Mamba（选择性状态空间完全替代注意力）
- **2026 年主流方案**：
  - **Qwen3.6-27B**：48 层 Gated DeltaNet（固定状态）+ 16 层 Gated Attention（全局交互）
  - **Kimi K3**：69 层 KDA（固定递归状态）+ 24 层 MLA（全局内容匹配）
  - **DeepSeek V4**：CSA + HCA（稀疏选择+压缩降本）
  - **gpt-oss**：稠密注意力 + 局部带状稀疏注意力 + GQA + MoE
- **分工逻辑**：便宜层（状态/稀疏）负责连续传递、局部混合 → 少量全局层负责精确内容检索
- **为什么不删光全注意力**：固定状态压缩历史便宜，但精确找回原文/变量名/工具返回值更难（Zoology 研究证实关联回忆是主要差距）
  说白了，状态层像工作记忆，全注意力层像档案检索——一个省钱，一个准。

### 🎲 第六次改装：生成方式为什么开始和骨干架构分离？

**自回归不再是唯一选择**，扩散等并行生成方式兴起。
- **传统自回归**：一次预测一个 token → 支持变长输出、流式、工具调用，但步骤串行
- **扩散语言模型**：一次处理一块文本，多轮并行修正 → 代表：DiffusionGemma、LLaDA
- **关键区分**：
  - Transformer 回答"内部怎样计算 token 关系"
  - 自回归/扩散回答"输出怎样被生成"
  - 两个维度独立，扩散模型骨干仍可能是 Transformer
- **待验证问题**：变长输出分配、流式展示、工具返回后局部修改、多轮去噪总延迟

### 🔮 Transformer 会消失吗？

**狭义标准 Transformer 正在消失，广义家族不会**。
- **狭义标准（2017 全套）**：编码器-解码器 + 每层全注意力 + 正弦位置 + Post-LN + ReLU 稠密 FFN → 前沿模型几乎不再原样采用
- **广义家族**：token 表示 + 残差流 + 可并行层堆叠 + 内容寻址注意力 → 核心能力（按内容找相关 token）最难被替代
- **作者预测**：
  - **2029 年**：新旗舰长上下文模型中，层层全注意力成少数，混合序列层更常见
  - **2031 年**：多数旗舰仍保留全局内容寻址层，纯无注意力骨干不会成绝对主流
  - 自回归不再垄断生成，扩散/多 token 并行进入更多产品，但未必换骨干
- **预测失败条件**：
  - 全注意力层比例持续提高 / 新算法硬件让全注意力成本追平混合模型
  - 出现两个 100B+ 纯无注意力旗舰，在检索/代码/工具/通用质量上成主流
  - 扩散模型长期解决不好变长、流式、工具循环

### 📋 六次改装总览：每次都有收益，也都有代价

| 主要变化 | 解决的瓶颈 | 新代价或边界 |
| :--- | :--- | :--- |
| Encoder / Decoder 分叉 | 同一骨架适配理解与生成 | 架构不再有统一代际 |
| Pre-Norm/RMSNorm/RoPE/SwiGLU | 深层训练、位置表示、FFN 表达 | 组合更多，外推与实现更复杂 |
| 稠密 FFN → MoE | 扩大总参数，控制激活计算 | 专家存储、路由、跨卡通信 |
| MHA → MQA/GQA/MLA | 压缩 KV Cache 和解码带宽 | 共享或低秩压缩可能损失表达 |
| 全注意力 → 稀疏/状态/混合 | 降低长上下文计算与缓存增长 | 固定状态的精确回忆更难 |
| 自回归 → 扩散/多 token | 减少逐 token 串行步骤 | 变长、流式和工具调用仍待验证 |

### 💡 关键洞察
- 未来真正消失的不是 Transformer 这个名字，而是"所有 token、所有层、所有时刻都用同一种全注意力"的默认假设
- 最终架构更像一套**混合计算系统**：大部分层便宜维持状态 + 少数层昂贵精确检索 + 专家网络扩充容量 + 生成器按任务选择输出方式
