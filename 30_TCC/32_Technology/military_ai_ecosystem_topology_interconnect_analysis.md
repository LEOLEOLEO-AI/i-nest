# 关于承接军事智能生态基座网络方向任务的汇报

# 关于承接军事智能生态基座网络方向任务的汇报

---

## 一、背景与机遇

### 1.1 专项基本情况

"十五五"期间，国家将启动**军事智能生态基座**专项，作为军事智能领域的核心布局。目前高层高度重视，已设立专项推进，预计**2026年底以指南形式发布**，配套政策支持力度大。

该专项的核心目标是构建一套自主可控的军事智能生态体系，把芯片、操作系统、大模型、算子库、网络等各层级的能力标准化、组件化，让各类智能装备和应用能快速接入生态，避免各自为战、重复造轮子。

生态基座包含六大板块：标准、测试环境、生态兼容性测试、体系效能测试、跨域资源池、生态样板间。产业线围绕操作系统、大模型、芯片三大传统领域，以及数据、算法、模型、算子、网络等支撑维度展开。

### 1.2 现实挑战：工艺约束下的算力效能突围

当前，我国在先进制程芯片领域面临外部限制，高端工艺供给不足。与此同时，军事智能对算力的需求却呈指数级增长——大模型训练、分布式推理、多平台协同感知与决策，每一项都对计算能力和通信能力提出了极高要求。

**"工艺不够，怎么凑？"** 这是我们必须面对的现实问题。

在工艺代差客观存在的前提下，单纯靠堆芯片、堆节点来追赶算力，不仅成本高昂，而且在体积、功耗、可靠性等方面都难以满足军事应用的严苛要求。**必须在架构层面找突破，把有限的算力和存力发挥到极致**。

从计算系统的发展规律来看，当工艺进步的速度放缓后，架构创新就成为效能提升的主要驱动力。而在所有架构创新中，**互连架构的创新是见效最快、潜力最大的方向之一**——因为当前AI系统的瓶颈，很大程度上不在计算单元本身，而在"数据搬不动、搬不快、搬得贵"。

### 1.3 核心判断：拓扑与集合通信决定系统效能

为什么说互连拓扑和集合通信是关键？

**第一，算力的有效发挥，取决于数据能不能及时送到计算单元。**

一个AI芯片里，计算单元（PE）可能有几千上万个，但它们之间的数据交换靠的是互连网络。如果网络拓扑不匹配计算模式，大量计算单元就会在等数据——空转、发热、不出活。就像工厂里机器很多，但物料送不上去，产能还是上不去。

据统计，当前大模型训练系统中，**通信开销占总运行时间的比例可达40%-60%**。也就是说，一半左右的时间算力在"等数据"。如果能把通信效率提上去，相当于同等硬件条件下算力翻了近一倍。

**第二，体系协同能力，取决于集合通信的效率。**

军事智能不是单平台的事，是多平台、多节点、多装备的体系对抗。体系级的协同感知、协同决策、协同打击，本质上都是**数据和指令在体系内的高效流转与聚合**。AllReduce、AllGather、Reduce-Scatter这些集合通信原语，是体系协同的"毛细血管"。

集合通信的效率，直接决定了体系的反应速度、决策时延和打击节奏。在强对抗环境下，**慢一秒，可能就是生与死的差别**。

**第三，拓扑变换，是提升通信效率的架构级手段。**

传统的固定拓扑，就像一条只有一条车道的公路——不管是高峰还是平峰，不管是货车还是小车，都只能在这一条道上跑。而动态拓扑变换，就像有了一条可以随时改变车道数量和方向的智能公路——什么场景配什么拓扑，按需切换。

不同的计算任务、不同的任务阶段，对网络拓扑的需求是完全不同的：

- 大模型训练的AllReduce阶段，需要全带宽的多对多通信
- 推理的流水线并行，需要单向高带宽的链式通信
- 图计算的消息传递，需要不规则的点对点通信

**没有任何一种固定拓扑能在所有场景下最优。** 动态拓扑变换，就是要让网络结构跟着计算需求走，从而把每一分带宽、每一瓦功耗都用在刀刃上。

### 1.4 发展趋势：拓扑与互连正成为AI算力突围的核心支撑技术

从模型到系统再到芯片，整个AI技术栈正在经历一场深刻的转向——**算力的竞争焦点，正在从计算单元转向互连网络**。谁能在互连和拓扑上取得突破，谁就能在同等工艺条件下，释放出更强的系统算力。

**从模型层面看**：大模型的参数量和训练数据量持续增长，但单芯片的算力增长受制于工艺和功耗瓶颈。模型越大、层数越多，层间和节点间的数据交换量就越大，通信逐渐成为制约训练效率的主要矛盾。据行业测算，当前大模型训练系统中，**集合通信（AllReduce、AlltoAll等）已占据训练总时长的40%-70%**——也就是说，近一半甚至更多的时间算力在"等数据"。如果能把通信效率提上去，相当于同等硬件条件下算力翻了近一倍。

**从系统层面看**：AI集群的扩展方式正在从"堆机器"转向"优连接"。传统的GPU集群靠PCIe、NVLink、InfiniBand把机器连起来，但这些互连技术都是"固定管道"式的——拓扑一旦部署就不能变，只能靠路由算法在固定拓扑上绕路。而集合通信是AI分布式训练的核心操作，其效率直接取决于底层网络拓扑与通信模式的匹配程度。**没有任何一种固定拓扑能在所有通信模式下最优**——AllReduce适合蝶形拓扑，AlltoAll需要全连接拓扑，FFT适合蝶形级联，CFAR需要线性链。固定拓扑只能在所有场景之间取折中，由此产生的"拓扑-原语失配税"，白白浪费了大量带宽和功耗。

**从芯片层面看**：晶圆级计算正在成为突破摩尔定律的重要方向。Cerebras最新发布的第三代晶圆级引擎（WSE-3），将一整块300mm晶圆做成单一计算系统，集成了**4万亿晶体管、90万个AI优化核心、44GB片上SRAM**，峰值AI算力达到**125 PFLOPS**。其核心优势就在于**晶圆级的超高带宽互连**——片上fabric总带宽高达**220 Pb/s**，聚合带宽**27 PB/s**，计算单元之间的通信延迟从板级的纳秒级甚至微秒级，降到了晶圆内的皮秒级，带宽密度提升了几个数量级。 

Cerebras之所以能在大模型训练上实现数倍于GPU集群的能效比，关键不在于单计算单元更强，而在于**互连更密、数据搬得更快、功耗更低**——它把"数据搬移墙"的问题，在物理层面用晶圆级集成消灭了。

但必须看到，Cerebras的晶圆级互连有一个**根本性的结构性缺陷**：它的片上网络是**固定的2D Mesh拓扑**，运行时不可切换。  这意味着，当计算任务的通信模式不是邻居通信（比如MoE的AlltoAll）时，数据需要多跳绕行，效率急剧下降。Cerebras的24条颜色通路由编译期静态分配，运行时无法动态调整——这在面对多样化的AI工作负载时，依然存在"拓扑-原语失配"的问题。

不仅Cerebras如此，当前所有商用AI加速方案都卡在同一个瓶颈上：


| 厂商/产品           | 拓扑类型         | 网内计算能力            | 拓扑灵活性             |
| --------------- | ------------ | ----------------- | ----------------- |
| NVIDIA NVLink   | 全连接（固定）      | SHARP（仅AllReduce） | 无                 |
| Google TPU ICI  | 3D Torus（固定） | 无                 | 无                 |
| Cerebras WSE-3  | 2D Mesh（固定）  | 无（片上）             | 编译期静态分配，运行时不可变    |
| SambaNova       | 可重构数据流       | 有（数据流）            | 编译时可配置，运行时不可变     |
| Lightmatter OCS | 光互连          | 无                 | ms级切换（比微秒级慢3个数量级） |


**一个关键发现：带宽越高的方案，拓扑灵活性越低。** Cerebras片上带宽高达220 Pb/s，但采用固定拓扑；真正能做运行时拓扑重构的方案，带宽又上不去。这反映了一个根本性的工程权衡——固定拓扑可通过物理优化最大化带宽，而可重构性引入的开关级联会增加路径延迟和面积开销。

**这正是我们的突破口。**

如果能在晶圆级尺度上，既保持高带宽互连，又实现微秒级甚至纳秒级的动态拓扑切换，就等于同时拿到了Cerebras的带宽优势和可重构拓扑的灵活性优势。这将是**超越当前所有商用方案的下一代晶圆级计算架构**。

从国际前沿看，可重构拓扑已经成为公认的发展方向：

- Google TPU v4采用Palomar光交换实现毫秒级3D Torus重构
- Microsoft Sirius实现纳秒级光开关，但切换的是波长通道，拓扑结构未变
- RotorNet/Opera达到微秒级，但为无差别轮转匹配，不按任务语义选择
- Intel Loihi 2具备突触级可编程路径，但面向神经形态计算，规模有限

这些工作都指向同一个方向——**动态拓扑是下一代AI互连的必争之地**。但目前还没有任何一家能在晶圆级尺度上，实现高带宽 + 微秒级动态切换 + 任务语义感知的完整方案。

**从国内现状看**：我们在先进制程上面临外部限制，高端工艺供给不足。如果走"靠工艺堆算力"的老路，差距只会越拉越大。但互连和拓扑是架构层面的创新，**不依赖最先进的工艺，靠架构设计就能带来数倍的能效提升**——这恰恰是我们可以弯道超车的方向。

把拓扑和互连做好了，就是在现有工艺条件下，把算力和存力发挥到极致的最有效途径。从这个意义上说，**动态拓扑与高效互连，已经不再是系统的"附属部件"，而是决定AI算力水平的核心支撑技术之一**，直接关系到中国AI算力能不能在工艺受限的条件下实现突围。

DARPA的DRBE（数字射频战场仿真器）项目，已经采用晶圆级计算技术来构建实时高性能计算（RT-HPC）架构，Cerebras + Ranovus正在推进晶圆级共封装光互连。  美军把晶圆级计算作为下一代电子战技术的催化剂，看中的正是其在互连效率上的代际优势。国内方面，之江实验室与信息工程大学已完成晶圆级8 Tbps软件定义互连网络样机，国内已形成SDSoW方法探索——但在晶圆级动态拓扑加速这个方向上，还是空白。

**未来的AI系统，比的不只是单芯片算力，更是体系级的互连效率和拓扑适配能力。** 谁能在动态拓扑、网算一体上取得突破，谁就能在同等工艺条件下，拿出更强的系统能力。

对我们而言，这既是挑战，也是机遇——工艺上的差距，恰恰倒逼我们在架构创新上找出路。**晶圆级动态拓扑加速，就是我们在工艺受限条件下，把算力和存力发挥到极致的一条关键路径，也是我们有机会走在国际前沿的战略方向。**

### 1.5 我们的机遇

对方明确邀请我们承接网络方向的相关任务。我们在软件定义晶上系统、软件定义互连方向有长期积累，有条件也有能力在网算一体这个关键方向上，为专项提供原创技术供给和标准支撑。

**时间窗口**：年底指南发布前，需拿出方案 → 双方沟通确认 → 争取高层会面 → 确定任务分工 → 指南发布后正式立项。现在距年底约4个月，是方案博弈的关键期。

## 二、总体思路

### 2.1 任务定位

面向军事智能生态基座对**网算一体**的核心需求，依托软件定义晶上系统平台，攻克晶圆级动态拓扑变换的关键技术，验证动态拓扑对典型智能计算任务的加速效果，制定相关标准规范，为专项提供**晶上网算加速的物理验证、量化依据和标准支撑**。

**一句话定位**：在晶圆上把"网络拓扑动态切换"做出来、测清楚、立标准。

### 2.2 技术路线

以**晶上系统平台**为基础，从硬件到软件逐层突破：

1. **硬件层**：研制晶圆级动态拓扑互连阵列，实现多模式拓扑的微秒级快速切换
2. **控制层**：建立拓扑快速加载与无损切换控制机制
3. **软件层**：开发拓扑智能调度工具，实现计算任务与网络拓扑的自动匹配
4. **验证层**：在三类典型智能计算场景上，完成加速效果的量化验证
5. **输出层**：把技术成果转化为专项标准和测试规范

### 2.3 核心指标

- 支持 **4种以上** 拓扑模式动态切换
- 拓扑切换时间 **≤5微秒**
- 典型场景通信效率提升 **30%以上**
- 系统能效提升 **25%以上**

## 三、核心研究内容

### 研究方向一：晶上动态拓扑互连架构设计

**目标**：解决"晶圆上怎么实现拓扑动态变换"的硬件问题。

**具体内容**：

1. **多模式拓扑互连阵列设计**
  - 设计支持多种拓扑模式的互连开关阵列
  - 支持的拓扑模式包括：Ring（环形）、Tree（树形）、Mesh（网格形）、All-to-All（全连接）、Butterfly（蝶形）等
  - 每种模式都有独立的配置通路和控制逻辑
2. **快速切换控制机制**
  - 设计拓扑配置的快速加载机制（类似"拓扑页表"）
  - 实现微秒级拓扑切换（目标：≤5μs）
  - 支持切换过程中的数据无损传输（不丢包、不阻塞）
3. **粗/细粒度两级变换**
  - 粗粒度：整网拓扑模式切换（如从Ring切到All-to-All）
  - 细粒度：局部链路动态调整（如针对特定流量模式优化部分链路）
  - 两级变换协同，兼顾切换速度和优化粒度

**技术难点**：

- 晶圆级尺度下的时钟同步与信号完整性
- 多拓扑模式的资源复用与面积开销控制
- 切换过程的无损性与低延迟保证

---

### 研究方向二：典型智能计算场景的拓扑加速验证

**目标**：用实测数据回答"动态拓扑到底能加速多少"。

**具体内容**：

1. **场景一：大模型分布式训练加速**
  - 聚焦AllReduce、Reduce-Scatter等集合通信算子
  - 对比测试：固定Ring拓扑 vs 动态拓扑切换（训练不同阶段用不同拓扑）
  - 测试指标：端到端训练吞吐率、通信占比、能效比
  - 目标：训练吞吐率提升 **25%-35%**
2. **场景二：大模型推理加速**
  - 聚焦张量并行、流水线并行下的推理通信模式
  - 对比测试：固定拓扑 vs 动态拓扑（不同batch size、不同序列长度自适应）
  - 测试指标：推理延迟、吞吐量、单位token能耗
  - 目标：推理能效提升 **20%-30%**
3. **场景三：图神经网络计算加速**
  - 聚焦消息传递（Message Passing）阶段的不规则通信
  - 对比测试：固定Mesh拓扑 vs 动态拓扑（根据图结构和聚合模式自适应调整）
  - 测试指标：单轮迭代时间、带宽利用率、能效
  - 目标：图计算性能提升 **30%-40%**
4. **综合测试基准**
  - 构建一套"动态拓扑加速测试基准"，包含上述三个场景
  - 形成标准化的测试流程和评估方法
  - 为后续其他团队的验证和对比提供基准

**技术难点**：

- 晶上原型与实际计算任务的对接与适配
- 通信模式的精确提取与拓扑匹配
- 测试结果的准确性与可复现性保证

---

### 研究方向三：拓扑智能调度方法与工具

**目标**：解决"怎么知道什么时候切什么拓扑"的软件问题。

**具体内容**：

1. **计算任务通信特征分析方法**
  - 研究如何从计算图/算子序列中提取通信特征
  - 建立"通信特征签名"——描述任务各阶段的通信模式、流量分布、延迟敏感度
  - 支持静态分析（编译期）和动态监测（运行时）两种方式
2. **拓扑匹配与优化算法**
  - 研究通信特征与拓扑模式的匹配机制
  - 建立"任务-拓扑"适配的代价模型（考虑切换开销、性能增益、能耗等）
  - 开发拓扑序列优化算法——为一个完整任务生成最优的拓扑切换序列
3. **拓扑调度工具原型**
  - 开发一套拓扑智能调度工具，对接主流深度学习框架
  - 功能：自动分析任务 → 生成拓扑策略 → 下发到晶上互连控制器执行
  - 提供编程接口，支持开发者手动指定拓扑策略

**技术难点**：

- 通信特征的在线快速提取（开销不能太大）
- 切换开销与性能增益的精确权衡
- 与现有编程框架的无缝集成

### 研究方向四：标准规范制定与测试验证体系

**目标**：把技术成果转化为专项的标准和测试规范，掌握话语权。

**具体内容**：

**标准一：网算一体拓扑描述与接口规范**

- **拓扑描述标准**：定义网络拓扑的标准化描述语言/格式，包括拓扑结构、链路参数、切换模式等
- **拓扑请求接口**：定义计算任务向网络层请求拓扑资源的标准接口（API）
- **拓扑能力描述**：定义网络设备的拓扑能力描述格式（支持哪些模式、切换速度、粒度等）
- 对接专项：**标准板块** + **生态兼容性测试板块**

**标准二：晶上互连性能测试规范**

- **测试指标体系**：定义晶上互连系统的关键性能指标（带宽、延迟、功耗、切换时间、加速比等）
- **测试方法与流程**：定义各项指标的标准化测试方法和测试流程
- **测试基准程序**：提供标准化的测试基准程序，确保不同平台测试结果可比
- 对接专项：**测试环境板块** + **生态兼容性测试板块**

**标准推进路径**：

- 第一年：形成标准草案，在内部验证
- 第二年：提交专项标准组讨论，形成征求意见稿
- 第三年：完成标准评审，正式发布
- 第四-五年：标准推广与迭代更新

## 七、我们的优势

### 优势一：晶上系统平台优势

我们有国内为数不多的软件定义晶上系统研发平台，具备从架构设计、芯片实现到晶圆级测试的全流程能力。晶圆级动态拓扑的验证，必须在晶上系统上做——板级系统互连密度不够、延迟太高，做不出有说服力的结果。

### 优势二：软件定义互连技术积累

我们在软件定义互连方向有长期的技术积累，从协议层到物理层都有深入研究。动态拓扑变换本质上就是软件定义互连在晶圆尺度上的延伸和深化，我们有扎实的技术底子。

### 优势三：体系化的研究能力

我们有跨学科的研究团队，覆盖芯片架构、互连网络、编译调度、AI算法等多个方向。这个任务需要硬件、软件、算法全链条打通，纯做硬件或纯做算法的团队都做不了，我们有这个综合能力。

## 八、结论

军事智能生态基座是"十五五"军事智能领域的核心专项，规格高、投入大、影响远。

当前，AI算力的竞争焦点正在从计算单元转向互连网络。从模型到系统到芯片，全行业都面临同一个瓶颈——**固定拓扑与多样化通信模式的结构性失配**。Cerebras用晶圆级集成把互连带宽做到了极致（220 Pb/s片上带宽、90万核心），但它的2D Mesh固定拓扑依然是结构性缺陷；Google、NVIDIA、微软都在探索可重构拓扑，但要么切换太慢、要么规模不够、要么不承载计算语义。

**在工艺受限的现实条件下，动态拓扑与高效互连是把有限算力存力发挥到极致的核心支撑技术，也是中国AI算力实现突围的战略方向。** 谁能在晶圆级尺度上率先实现"高带宽 + 微秒级动态切换 + 任务语义感知"，谁就能走在下一代AI计算架构的最前沿。

我们有国内为数不多的软件定义晶上系统研发平台，有长期的软件定义互连技术积累，有跨学科的全链条研究能力。以晶圆级动态拓扑加速为核心方向参与军事智能生态基座专项，我们有条件、有能力做出有国际影响力的原创成果，为专项提供关键技术供给和标准支撑。

建议抓住年底指南发布前的窗口期，快速推进方案对接和高层沟通，争取在专项中占据有利位置。
