# SDI 节点产品定义与产业落地路径

# SDI 节点产品定义与产业落地路径

## 一、SDI 的产品定位

### 1.1 SDI 是什么

SDI（Software-Defined Interconnect，软件定义互连）节点是拓扑中心计算（TCC）范式的核心硬件载体。

它不是传统意义上的交换机，也不是传统意义上的计算芯片，而是一个全新的物种：

> **SDI 节点 = 拓扑变换枢纽 + 网内计算引擎 + 异构集成粘合剂**

- **拓扑变换枢纽**：支持电路交换、虚电路、分组交换三层模式，软件定义互连拓扑
- **网内计算引擎**：内置集合通信加速、流式计算、数据聚合等功能，数据流过即计算
- **异构集成粘合剂**：连接 CPU、GPU、NPU、HBM 等不同类型节点，统一拓扑抽象

### 1.2 SDI 不是什么

- 不是"更快的交换机"——交换机只做转发，SDI 做拓扑变换 + 计算
- 不是"另一个 DPU"——DPU 是网卡增强，SDI 是系统级拓扑基础设施
- 不是"另一个 NVSwitch"——NVSwitch 只连 GPU、固定全互连，SDI 连一切、拓扑液态

### 1.3 核心价值主张

| 维度 | 传统方案 | SDI 方案 | 价值提升 |
|------|----------|----------|----------|
| 集合通信性能 | GPU 内计算 + 网络传输 | 网内计算 + 流式传输 | 2-5 倍 |
| 系统利用率 | 30-40%（通信等待） | 70-90%（计算通信融合） | 2 倍+ |
| 拓扑灵活性 | 固定 Fat-Tree | 液态可重构 | 质的飞跃 |
| 异构集成难度 | 每种互联单独设计 | 统一 SDI 拓扑抽象 | 大幅降低 |

## 二、SDI 产品矩阵

建议定义**三类核心产品**，形成从"切入点"到"终极形态"的完整产品家族。

### 2.1 SDI-Accel 系列（第一代：切入点）

**产品形态**：PCIe / CXL 接口的加速卡

**核心定位**：插在现有 GPU/AI 集群中，解决集合通信瓶颈

**核心规格**：
- 形态：半高半长或全高全长 PCIe 5.0/6.0 卡
- 网络接口：8-16 个 400G/800G 端口，支持 InfiniBand / RoCE
- 主机接口：PCIe 5.0 x16 或 CXL 3.0
- 核心芯片：SDI 交换 + 加速引擎
- 功耗：150-300W

**核心功能**：
1. **集合通信硬件加速**：
   - All-Reduce / All-Gather / Reduce-Scatter / All-to-All 全硬件加速
   - 支持 FP8 / FP16 / FP32 / INT8 等多种数据格式
   - 兼容 NCCL / MPI 等标准接口

2. **网内计算引擎**：
   - 数据聚合、排序、规约
   - 数据格式转换、预处理
   - 流式计算（数据流过时完成计算）

3. **三层交换架构**：
   - 电路交换层（大流量静态通路）
   - 虚电路层（中流量动态通路）
   - 分组交换层（小流量尽力而为）
   - 虚通道（100-200 条/物理链路）

4. **拓扑感知调度**：
   - 根据任务通信模式自动优化拓扑配置
   - 动态负载均衡
   - 拥塞避免与快速恢复

**目标客户**：
- 大模型训练公司（集合通信是主要瓶颈）
- 超算中心（MPI 集合通信加速）
- AI 云服务商（提升集群利用率）

**价值主张**：
> 插卡即用，集合通信性能提升 2-5 倍，训练吞吐提升 30-50%。不需要改系统架构，不需要改代码。

### 2.2 SDI-Fabric 系列（第二代：核心产品）

**产品形态**：Chiplet 形式的互连芯片，通过先进封装与计算芯片集成

**核心定位**：异构计算芯片的"互连标准件"

**核心规格**：
- 形态：Chiplet（约 50-100 mm²）
- 封装：CoWoS / InFO 等 2.5D/3D 封装
- 接口：UCIe / BoW 等 Chiplet 互连标准
- 每芯片端口数：8-16 个高速 SerDes
- 每端口速率：224G / 448G PAM4

**核心功能**：
1. **高带宽低延迟晶上互连**
   - Chiplet 间互连延迟 < 1ns
   - 互连密度远高于板级

2. **拓扑可编程**
   - 软件定义互连拓扑
   - 支持 Mesh / Torus / Fat-Tree / 自定义拓扑
   - 运行时动态重构

3. **内嵌流式计算单元**
   - 数据流过时完成规约、聚合、变换
   - 支持简单的 ALU 操作
   - 与计算 Chiplet 协同工作

4. **颜色路由机制**
   - 多虚通道并行传输
   - 编译时规划 + 运行时配置
   - 无冲突调度

**目标客户**：
- 国内 GPU / NPU / AI 芯片厂商（降低互连设计门槛）
- 先进封装厂商（作为封装内互连标准件）
- 系统集成商（快速搭建异构计算系统）

**价值主张**：
> 不用自己做复杂的互连设计，用 SDI Fabric 快速获得"拓扑中心计算"能力。专注你的计算核心，互连交给我们。

### 2.3 SDI-Compute 系列（第三代：终极形态）

**产品形态**：晶圆级 / 面板级异构计算系统

**核心定位**：完整的拓扑中心计算平台

**核心规格**：
- 形态：晶圆级 / 面板级系统
- 节点类型：SDI 节点 + GPU/NPU 节点 + CPU 节点 + HBM 节点 + IO 节点
- 拓扑：全液态可重构
- 制程：随工艺节点演进

**核心功能**：
1. **完整的拓扑中心计算平台**
   - 计算、存储、通信深度融合
   - 利用率目标 90%+

2. **全系统液态拓扑**
   - 从晶内到晶间到板间，统一拓扑抽象
   - 全局拓扑编排与优化

3. **拓扑中心编程模型**
   - 程序员面向"计算图 + 拓扑约束"编程
   - 编译器自动映射到物理拓扑
   - 运行时自适应优化

**目标客户**：
- 国家级超算中心
- 头部大模型公司
- 科研机构（前沿科学计算）

**价值主张**：
> 不是更快的 GPU 集群，而是一种全新的计算范式。在同样的硬件成本下，获得一个数量级的有效算力提升。

## 四、产业落地路径

### 4.1 第一步：痛点切入（SDI-Accel）

**策略**：从最痛的点切入，快速证明价值，建立口碑

**具体动作**：
1. **选 2-3 家头部客户做联合验证**
   - 客户类型：大模型公司 / 超算中心 / AI 云
   - 合作模式：免费提供样卡 + 联合调优 + 案例共建
   - 目标：跑出明确的性能数据（2-5 倍集合通信加速）

2. **兼容现有生态**
   - 兼容 NCCL / MPI 接口，用户代码几乎不用改
   - 支持 InfiniBand / RoCE 等标准网络协议
   - 即插即用，不改变现有系统架构

3. **打造标杆案例**
   - 与 1-2 家头部客户联合发布 benchmark 结果
   - 用真实数据说话，建立技术可信度

**关键里程碑**：
- 首款 SDI-Accel 样卡回片
- 首个客户联合验证通过（性能达标）
- 首批商业化订单

### 4.2 第二步：生态绑定（SDI-Fabric）

**策略**：成为国内异构计算芯片的"互连标准件"，绑定生态

**具体动作**：
1. **与国内 GPU/NPU 厂商深度合作**
   - 把 SDI Fabric 集成到他们的多 Chiplet 架构中
   - 提供参考设计 + 技术支持
   - 联合开发、联合推广

2. **建立 SDI 标准**
   - 发起或参与国内互连标准制定
   - 定义 SDI 接口规范
   - 建立"SDI 就绪"认证体系

3. **构建工具链生态**
   - SDI 编译器：把计算图映射到 SDI 拓扑
   - SDI SDK：软件开发工具包
   - 开源社区：吸引开发者

**关键里程碑**：
- 3 家以上主流芯片厂商采用 SDI Fabric
- SDI 接口规范发布 v1.0
- 开发者社区达到一定规模

### 4.3 第三步：平台化（SDI-Compute）

**策略**：从"部件"升级为"平台"，定义新计算范式

**具体动作**：
1. **晶圆级系统原型验证**
   - 与先进封装厂商合作
   - 打造晶圆级异构计算原型系统
   - 验证拓扑中心计算的终极性能

2. **定义拓扑中心编程模型**
   - 从硬件创新上升到编程范式创新
   - 建立 TCC 编程模型标准
   - 打造完整的软件栈

3. **行业应用拓展**
   - 从 AI 训练扩展到科学计算、药物研发、气候模拟等领域
   - 建立各行业的 TCC 解决方案
   - 推动产业生态成熟

**关键里程碑**：
- 晶圆级原型系统点亮
- TCC 编程模型 v1.0 发布
- 多个行业标杆应用落地

## 五、套刻约束下的工程实现策略

### 5.1 当前约束条件

- **2×2 光刻版图拼接**（4 个光照尺寸）
- 每个光照尺寸内布线自由
- 光照尺寸之间必须复制（相同版图图案）
- 未来演进到 3×3 → 全自由

### 5.2 应对策略：同构硬件 + 异构配置

**核心思路**：物理版图必须对称，但功能可以软件定义。

**具体方案**：

1. **每个光照象限内的固定结构**：
   - 1 个 SDI 枢纽节点（内置交换 + 计算加速 + 控制）
   - 4 个计算/存储槽位（可以填充不同类型的 IP）
   - 4 个方向的边界接口（上下左右）

2. **象限间的对称互连**：
   - 因为 A=B=C=D（版图复制），所以接口天然对称
   - SDI 枢纽之间形成 2×2 Mesh/Torus
   - 天然支持扩展到 3×3、N×N

3. **异构性的实现**：
   - 每个槽位的硬件结构相同（套刻约束）
   - 但通过软件配置，可以实现不同功能：
     - 配置为 GPU 计算模式
     - 配置为 NPU 计算模式
     - 配置为 CPU 控制模式
     - 配置为 HBM 存储模式
     - 配置为纯 SDI 交换模式
   - 类似于 FPGA 的 LUT——硬件结构相同，配置不同，功能不同

### 5.3 演进路径

| 阶段 | 套刻能力 | 拓扑自由度 | SDI 架构 |
|------|----------|-----------|----------|
| 1 | 2×2 | 4 象限对称 | SDI 四枢纽架构，同构硬件异构配置 |
| 2 | 3×3 | 9 象限对称 | SDI 九宫格枢纽，支持更复杂拓扑 |
| 3 | 全晶圆自由 | 完全自由 | 任意拓扑的 SDI 晶上网络 |

## 六、商业模式

### 6.1 SDI-Accel：卖卡模式

- 直接销售加速卡
- 按性能分级（不同端口数、不同加速能力）
- 配套软件授权
- 服务与支持

### 6.2 SDI-Fabric：IP + Chiplet 模式

- **IP 授权**：SDI 互连 IP 授权给芯片厂商
- **Chiplet 销售**：直接提供 SDI Fabric Chiplet
- **NRE + Royalty**：定制开发费 + 量产版税
- 参考设计与技术服务

### 6.3 SDI-Compute：系统 + 云服务模式

- **系统销售**：整机柜 / 整集群系统
- **算力服务**：基于 SDI-Compute 的云算力服务
- **解决方案**：面向特定行业的完整解决方案

## 八、总结：SDI 的战略意义

SDI 不只是一个新产品，它代表了一种新的计算范式——**拓扑中心计算**。

从产业格局看：
- 英伟达走的是"计算中心"路线，用 GPU 统治计算，用 NVSwitch/BlueField 辅助通信
- 谷歌走的是"计算通信融合"路线，TPU 内嵌路由，但固定拓扑、同构
- SDI 走的是"拓扑中心"路线，把拓扑从"附属"提升为"核心"，液态可重构，全异构支持

SDI 的终极愿景：

> **让计算像液体一样，流动在拓扑的血管中。哪里需要计算，算力就流向哪里。互连不再是瓶颈，互连本身就是计算的发动机。**
