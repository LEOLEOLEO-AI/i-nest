# 军事智能生态基座-拓扑中心计算网络底座项目指南建议（3年期·修订版）

# 军事智能生态基座专项
## 拓扑中心计算网络底座关键技术研究与验证
### 项目指南建议（3年期·修订版）

---

## 一、项目名称

**拓扑中心计算网络底座关键技术研究与验证**

## 二、项目定位

面向军事智能生态基座对网算一体的核心需求，针对当前智能计算系统"算力有了但跑不起来"的结构性瓶颈，以拓扑中心计算（TCC）为核心范式，开展液态拓扑生成、拓扑-路由协同控制、拓扑编译与调度、典型军事智能场景适配等关键技术研究。

**技术路径**：采用**FPGA原型验证 + 仿真验证**相结合的方式，构建支持液态拓扑的五大技术平台——FPGA原型验证平台、拓扑与网络仿真平台、拓扑编译与调度平台、数据+AI算法设计与验证平台、P4语言扩展与验证平台。通过理论建模、仿真分析与原型实测，系统验证拓扑中心计算对军事智能算力效能的提升作用。

**三大产出**：输出**技术白皮书、系列验证报告、标准规范草案**，为军事智能生态基座的网络底座提供理论依据、技术路径与标准支撑。

**一句话定位**：不做具体工程建设，为军事智能生态基座定义拓扑中心计算的网络底座——既是当前算力有效发挥的底座，也是未来军事智能新范式的发展底座。

---

## 三、立项依据

### 3.1 现实需求：算力效能释放的结构性瓶颈

军事智能生态基座汇聚了芯片、操作系统、大模型、算子库等大量算力资源，但当前智能计算系统的通信开销占总运行时间的比例可达40%-70%——近一半的时间算力在"等数据"。固定拓扑与多样化通信模式的结构性失配，导致大量算力资源被白白浪费。

在先进制程受限的现实条件下，单纯靠堆芯片、堆节点追赶算力，成本高、周期长、军事适用性差。**必须在架构层面找突破，通过拓扑创新把有限的算力和存力发挥到极致。**

### 3.2 国际趋势：互连拓扑成为AI算力突围的核心方向

从模型到系统再到芯片，AI技术栈正在经历深刻转向——算力的竞争焦点从计算单元转向互连网络：

- **Google TPU v8**：训练/推理双芯分叉，训练端采用3D Torus拓扑（9600芯片超Pod），推理端采用Boardfly拓扑（1152芯片，7跳直径），拓扑已成为架构差异的核心标志
- **Cerebras WSE-3**：片上fabric带宽高达220 Pb/s，但固定2D Mesh拓扑仍是结构性缺陷——MoE的AlltoAll通信需要多跳绕行，效率急剧下降
- **SambaNova**：可重构数据流架构，编译时可配置拓扑，但运行时不可变，仍属静态调度范畴
- **Lightmatter OCS**：光互连方案支持拓扑重构，但切换速度为ms级，比微秒级慢3个数量级

**带宽越高的方案，拓扑灵活性越低**——这是当前所有商用方案面临的共同工程权衡。谁能突破这一权衡，谁就掌握了下一代AI计算架构的主动权。

### 3.3 工具链现状：国际上四个方向的发展态势

**（1）拓扑表征方向**：当前主流的拓扑描述方法仍以图论邻接矩阵为主，缺乏面向计算任务语义的拓扑表征框架。最新研究如新加坡国立大学提出的Mesh-of-Trees（MoT）层级NoC设计框架，已开始探索拓扑-映射协同设计的表征方法，但尚未形成统一的、可计算的拓扑表征语言。P4语言作为数据平面可编程的事实标准，已在工业界广泛应用，但其能力局限于数据包处理流水线，尚未延伸到拓扑结构层面的可编程。

**（2）业务映射方向**：HPC领域的PTRAM等拓扑感知映射框架，已实现60%以上的映射指标提升和50%的通信时间改善；AI加速器领域的NN-Baton等工具，支持chiplet粒度的工作负载编排与通信开销分析。但这些工具均面向**固定拓扑**下的映射优化，尚未支持**动态拓扑切换**场景下的任务-拓扑联合调度。

**（3）动态编译方向**：当前深度学习编译器（TVM、XLA等）以算子优化为核心，对网络拓扑的感知能力极弱。最新的参数化互连设计框架，开始将互连参数（带宽、缓冲区、跳数）与模型级参数（延迟、吞吐、能耗）进行定量关联，但仍停留在设计空间探索阶段，未形成运行时动态编译能力。可重构NoC的动态拓扑编译研究已有初步探索，但距工程可用尚有差距。

**（4）在线评估方向**：网络仿真工具（OMNeT++/INET、NS-3、QualNet等）已相当成熟，OMNeT++ 6.4.0甚至集成了LLM辅助仿真能力；但这些工具面向通用网络场景，缺乏对AI计算通信模式的针对性建模。BookSim等片上网络仿真器专注于NoC性能评估，但不支持动态拓扑切换。基准测试方面，AI计算基准（MLPerf等）侧重端到端任务性能，缺乏专门针对互连拓扑效能的标准化评估体系。

**本项目的定位**：在上述四个方向的交叉空白地带——**面向动态拓扑的、以计算任务语义为驱动的、从表征到编译到评估的完整工具链**——开展系统性研究，填补国际空白。

### 3.4 军事特色：结构级抗毁是动态拓扑的独有价值

军事智能场景与民用最大的区别在于**强对抗、高毁伤、快变化**。固定拓扑下，抗毁靠路由绕路——延迟高、拥塞重、性能骤降；动态拓扑下，可以通过拓扑重构实现**结构级抗毁**——关键链路失效后，直接从结构上绕过故障区，而不是在受损拓扑里艰难绕路。

这是只有动态拓扑才能提供的军事差异化价值，也是军事智能网络底座区别于民用网络的关键特征。

### 3.5 我们的基础：TCC理论与SDI/SDSoW技术积累

拓扑中心计算（TCC）将连接结构从固定互连的隐含属性，提升为**可表达、可选择、可切换、可验证的一等架构对象**，已形成完整的理论体系：Topology Page抽象、R/T/C原语体系、三条可证明定理、三层工程技术栈。

软件定义互连（SDI）与软件定义晶上系统（SDSoW）为TCC提供了可落地的物理载体。本项目在此基础上，面向军事智能场景开展针对性研究与验证，为生态基座网络底座提供技术支撑。

## 四、研究目标

### 4.1 总体目标

突破液态拓扑生成、拓扑-路由协同控制、拓扑编译与调度、军事智能场景适配等关键技术，构建**五大技术平台**（FPGA原型验证平台、拓扑与网络仿真平台、拓扑编译与调度平台、数据+AI算法设计与验证平台、P4语言扩展与验证平台），完成典型军事智能场景的效能验证，形成**白皮书、验证报告、标准规范**三大类核心产出，为军事智能生态基座的网络底座提供理论依据、技术路径与标准支撑。

### 4.2 具体目标

1. **理论方法层面**：建立军事智能场景下拓扑中心计算的理论框架、拓扑表征方法与效能评估体系
2. **关键技术层面**：突破液态拓扑生成、拓扑-路由同步切换、拓扑编译调度、P4拓扑扩展等核心技术
3. **平台工具层面**：建成五大技术平台，形成从拓扑表征→编译调度→仿真验证→FPGA实测的完整工具链
4. **场景验证层面**：完成四类典型军事智能场景的验证，证明TCC对算力效能的显著提升作用
5. **标准规范层面**：形成3项专项标准规范草案，掌握网算一体拓扑方向的标准定义权

## 五、研究内容

### 研究内容一：军事智能拓扑中心计算理论与拓扑表征方法

**目标**：建立TCC理论框架与拓扑表征语言，为整个项目提供理论基础与表达手段。

**具体内容**：

1. **军事智能任务通信特征建模**
   - 分析典型军事智能任务（分布式训练、协同推理、多平台感知决策、指挥决策图计算）的通信模式与数据流特征
   - 建立军事智能任务的"通信特征签名"描述方法，刻画任务各阶段的通信模式、流量分布、延迟敏感度与抗毁需求

2. **拓扑表征语言与形式化方法**
   - 研究面向计算语义的拓扑表征方法，突破传统图论邻接矩阵仅描述"有没有连接"的局限
   - 定义**拓扑描述语言（TDL, Topology Description Language）**：支持拓扑结构、链路属性、切换时序、抗毁模式等的统一表达
   - 建立拓扑等价性、拓扑距离、拓扑复杂度等度量的形式化定义
   - 与国际前沿对标：超越现有Mesh-of-Trees等单一拓扑类的参数化表征，支持多拓扑类的统一表征与自动转换

3. **拓扑-路由层级协同理论**
   - 明确拓扑与路由的层级分工：拓扑定大形状（架构层、μs级），路由做精细调优（算法层、ns级）
   - 建立拓扑-路由协同的理论框架，证明两者的上下层协同关系而非替代关系
   - 研究拓扑页（Topology Page）与路由表的同步更新机制，建立影子页表 + 原子提交的理论模型

4. **效能评估方法与指标体系**
   - 建立军事智能场景下TCC的效能评估指标体系，包括通信效率、算力利用率、系统能效、抗毁能力等维度
   - 研究拓扑切换开销与性能增益的定量权衡方法
   - 构建可扩展的分析模型，支持不同规模、不同场景下的效能预测

### 研究内容二：液态拓扑生成与拓扑-路由协同控制技术

**目标**：突破液态拓扑生成与协同控制的关键技术，形成可实现的技术方案。

**具体内容**：

1. **液态拓扑生成机制**
   - 研究元拓扑基元 + 化合键的拓扑组合生成方法
   - 设计支持多模式拓扑的配置页（Topology Page）结构与管理机制
   - 采用**"一套配置通路 + 多套配置页 + 统一主控制器 + 模式专用微码"**的分层架构
     - 配置通路、主控状态机各一套
     - 配置存储器、模式微码各多套
   - 研究微秒级拓扑页原子提交与无损切换技术

2. **拓扑-路由同步更新机制**
   - 研究拓扑切换时路由表的同步更新方法，确保零瞬态不一致、零丢包
   - 设计影子路由表 + 原子提交机制，路由表与拓扑配置在同一个Page Commit动作中同步生效
   - 研究多拓扑模式下的快速路由收敛算法

3. **结构级抗毁拓扑重构技术**
   - 研究故障检测-拓扑决策-页切换的抗毁闭环机制
   - 设计面向军事场景的抗毁拓扑模式库：关键链路失效后的快速重构策略
   - 对比验证：路由绕路 vs 拓扑重构的抗毁性能差异（恢复时间、性能下降幅度、剩余有效算力）

### 研究内容三：拓扑编译与调度技术及工具链

**目标**：开发拓扑编译与调度工具链，实现从任务语义到物理拓扑的自动映射与动态调度。

**具体内容**：

1. **拓扑感知的编译框架设计**
   - 研究深度学习计算图与拓扑模式的联合编译方法，突破现有编译器（TVM/XLA等）仅做算子优化、不感知网络拓扑的局限
   - 设计**TCC编译栈**：前端接入主流深度学习框架 → 中间表示层提取通信特征签名 → 后端生成拓扑切换序列与路由配置
   - 与国际前沿对标：超越现有固定拓扑下的映射优化框架（PTRAM、NN-Baton等），支持动态拓扑切换场景下的任务-拓扑联合调度

2. **拓扑智能调度算法**
   - 研究军事智能任务通信特征与拓扑模式的匹配机制
   - 建立"任务-拓扑-路由"三层适配的代价模型（考虑切换开销、性能增益、能耗、抗毁性）
   - 开发拓扑序列优化算法，为完整任务生成最优的拓扑切换序列 + 路由配置序列
   - 研究在线调度与离线调度的混合策略：编译期做粗粒度规划，运行时做细粒度调整

3. **拓扑调度工具链开发**
   - 开发拓扑智能调度工具，对接主流深度学习框架与军事智能中间件
   - 功能：自动分析任务 → 生成拓扑策略 → 下发到互连控制器执行
   - 提供编程接口，支持开发者手动指定拓扑策略
   - 支持仿真平台与FPGA平台的统一调度接口

### 研究内容四：FPGA液态拓扑原型验证平台

**目标**：构建基于高端FPGA的液态拓扑原型验证平台，提供硬件实测能力。

**具体内容**：

1. **多FPGA液态拓扑原型系统设计**
   - 基于高端FPGA平台（VU13P/VU19P级），构建多节点（4~8片）FPGA原型验证系统
   - 每片FPGA内部实现可重构拓扑互连阵列，支持≥8种拓扑模式：Ring、Tree、Mesh、All-to-All、Butterfly、Fat-Tree、Torus、Hypercube
   - 板间通过高速串行接口（≥100Gbps）互连，支持跨板拓扑扩展
   - 拓扑切换时间：FPGA内≤1μs，板间≤5μs

2. **拓扑页配置与控制子系统**
   - 实现Topology Page配置存储器与页切换控制逻辑
   - 实现原子提交与无损切换控制
   - 实现拓扑状态监测与性能统计子系统

3. **原型验证平台的调试与测试能力**
   - 开发在线逻辑分析仪与拓扑状态可视化工具
   - 开发自动化测试框架：支持批量测试、数据自动采集与分析
   - 支持故障注入与抗毁测试能力

4. **与现有平台的对标验证**
   - 搭建GPU对比基线平台，用于性能对标
   - 确保测试结果的可复现性与可比性

### 研究内容五：拓扑与网络仿真验证平台

**目标**：构建大规模液态拓扑仿真平台，支持百节点至千节点级的效能仿真与设计空间探索。

**具体内容**：

1. **多尺度仿真平台架构设计**
   - 基于OMNeT++/INET框架扩展，构建支持液态拓扑的网络仿真平台
   - 支持三个仿真层级：
     - **架构级仿真**：周期精确，验证关键模块功能与时序
     - **系统级仿真**：事务级，支持百节点级系统性能评估
     - **体系级仿真**：模型级，支持千节点级扩展性分析
   - 与BookSim等NoC仿真器对标，确保仿真精度

2. **军事智能任务负载建模**
   - 构建军事智能典型任务的通信负载模型库
   - 支持训练、推理、图计算、抗毁等多类场景的负载生成
   - 支持真实AI任务trace的回放与分析

3. **设计空间探索工具**
   - 开发拓扑设计空间探索工具：自动搜索不同规模、不同负载下的最优拓扑策略
   - 支持拓扑参数（模式、切换速度、链路带宽、节点数等）的扫描与优化
   - 提供可视化的设计空间分析报告

4. **仿真与FPGA实测的对标校准**
   - 建立仿真模型与FPGA实测结果的对标校准机制
   - 确保仿真结果的可信度与可预测性
   - 形成仿真-实测联合验证方法论

### 研究内容六：数据+AI算法设计与验证平台

**目标**：构建面向军事智能场景的算法设计与验证平台，支撑拓扑加速效果的端到端验证。

**具体内容**：

1. **军事智能典型算法库**
   - 构建四类典型军事智能算法库：
     - 分布式态势认知模型训练（多源异构数据融合）
     - 多平台协同推理（张量并行、流水线并行）
     - 指挥决策图计算（态势评估、威胁排序）
     - 抗毁场景算法（故障检测、快速重构）
   - 每类算法提供标准实现与可配置参数

2. **通信特征提取与分析工具**
   - 开发自动通信特征提取工具：从AI任务运行trace中自动提取通信特征签名
   - 支持静态分析（编译期）和动态监测（运行时）两种方式
   - 提供通信特征可视化分析能力

3. **端到端验证框架**
   - 构建从算法→调度→拓扑→性能的端到端验证框架
   - 支持自动化测试：批量运行、自动采集、自动对比分析
   - 支持A/B测试：固定拓扑 vs 动态拓扑、不同拓扑策略之间的对比

4. **基准测试套件**
   - 形成军事智能拓扑加速基准测试套件（MilTec-Bench）
   - 包含标准化的测试程序、测试流程、评估指标
   - 为后续其他团队的验证和对比提供基准

### 研究内容七：P4语言拓扑扩展与验证平台

**目标**：将P4语言从数据包处理可编程扩展到拓扑结构可编程，形成TCC的标准化编程接口。

**具体内容**：

1. **P4语言拓扑扩展设计**
   - 在P4语言基础上扩展拓扑可编程能力，提出**P4-T（P4 for Topology）**扩展方案
   - 扩展内容包括：拓扑结构声明、拓扑配置页定义、拓扑切换事件与动作、拓扑状态查询原语
   - 保持与标准P4的向后兼容，数据包处理逻辑不受影响
   - 与国际前沿对标：超越现有P4仅支持数据平面流水线可编程的局限，将可编程性延伸到拓扑结构层面

2. **P4-T编译器开发**
   - 开发P4-T编译器前端：解析P4-T程序，提取拓扑定义与数据包处理逻辑
   - 开发编译器后端：将拓扑定义编译为Topology Page配置，将数据包处理逻辑编译为匹配动作表
   - 支持多目标输出：FPGA原型、仿真平台、P4软件交换机（BMv2）

3. **P4-T运行时系统**
   - 开发P4-T运行时控制平面：管理拓扑页、处理拓扑切换请求、监控拓扑状态
   - 实现P4Runtime扩展：支持拓扑配置的远程动态下发
   - 提供标准化的API接口

4. **P4-T验证与示范应用**
   - 在FPGA原型平台上验证P4-T的功能与性能
   - 开发示范用例：用P4-T程序描述典型军事场景的拓扑-数据包联合处理逻辑
   - 评估P4-T的表达能力、编程效率与性能开销

### 研究内容八：典型军事智能场景验证与标准规范制定

**目标**：完成四类场景验证，形成白皮书、验证报告与标准规范。

**具体内容**：

1. **四类典型场景验证**

   **场景一：分布式态势认知模型训练加速**
   - 聚焦多源异构数据融合训练中的AllReduce、Reduce-Scatter等集合通信
   - 对比测试：固定拓扑 vs 动态拓扑切换
   - 测试指标：训练吞吐率、通信占比、能效比
   - 目标：训练吞吐率提升≥30%

   **场景二：多平台协同推理加速**
   - 聚焦张量并行、流水线并行下的推理通信模式
   - 对比测试：固定拓扑 vs 动态拓扑（不同batch size、序列长度自适应）
   - 测试指标：推理延迟、吞吐量、单位token能耗
   - 目标：推理能效提升≥25%

   **场景三：指挥决策图计算加速**
   - 聚焦态势评估、威胁排序等图计算场景的消息传递
   - 对比测试：固定Mesh拓扑 vs 动态拓扑（根据图结构自适应调整）
   - 测试指标：单轮迭代时间、带宽利用率、能效
   - 目标：图计算性能提升≥35%

   **场景四：结构级抗毁验证**
   - 模拟关键链路/节点失效场景
   - 对比测试：路由绕路（传统方案）vs 拓扑重构（TCC方案）
   - 测试指标：恢复时间、性能下降幅度、剩余有效算力
   - 目标：拓扑重构抗毁恢复时间比路由绕路降低≥一个数量级

2. **技术白皮书编制**
   - 《军事智能拓扑中心计算网络底座技术白皮书》
   - 内容包括：TCC核心内涵、军事智能场景需求分析、技术体系、关键技术、五大平台介绍、验证结果、演进路线
   - 系统阐述拓扑中心计算作为军事智能生态基座网络底座的技术路径与价值

3. **标准规范草案制定**

   **标准一：网算一体拓扑描述与接口规范**
   - 定义TDL拓扑描述语言的标准化格式
   - 定义计算任务向网络层请求拓扑资源的标准接口
   - 定义网络设备拓扑能力描述格式
   - 对接专项：标准板块 + 生态兼容性测试板块

   **标准二：军事智能拓扑效能测试评估规范**
   - 定义军事智能场景下拓扑效能的测试指标体系
   - 定义标准化测试方法、测试流程与测试基准
   - 对接专项：测试环境板块 + 体系效能测试板块

   **标准三：军事智能网络拓扑抗毁评估规范**
   - 定义军事场景下拓扑抗毁性的评估指标与方法
   - 定义抗毁测试场景库与评估流程
   - 对接专项：体系效能测试板块

4. **系列验证报告**
   - 四类场景各形成独立的验证报告，包含测试方案、测试数据、对比分析与结论
   - 形成总体验证报告，系统总结TCC对军事智能算力效能的提升作用
   - 形成五大技术平台的技术报告与用户手册

- 效能测试与抗毁评估规范的制定，确立我们在军事智能网络效能评估领域的**技术引领地位**
- P4-T语言扩展为军事智能网络可编程提供统一的编程接口标准，带动生态向TCC路线靠拢

### 10.3 生态价值

- 为军事智能生态基座提供**网络底座的顶层设计与技术支撑**，提升整个生态的计算效率
- 五大技术平台可作为生态的**公共验证平台**，服务全生态的网络技术验证与性能评估
- MilTec-Bench基准测试套件可作为生态的**标准评测工具**，支撑体系效能测试板块
- 液态拓扑IP核与工具链可纳入跨域资源池，赋能生态伙伴

### 10.4 范式价值

- 从"计算中心"向"拓扑中心"的范式跃迁，为军事智能提供新的技术路线选择
- 拓扑作为一等架构对象，为未来军事智能从"模型驱动"向"结构驱动"演进奠定技术基础
- 本项目是底座性、奠基性工作——不仅解决当前算力释放问题，更为下一代军事智能的架构演进预留技术空间
