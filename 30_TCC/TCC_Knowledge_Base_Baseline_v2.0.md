## 一、TCC 总纲

### 1.1 全称与定位

**TCC = Topology-Centric Computing（拓扑中心计算）**

TCC 是一种新的计算范式。其核心判断是：**在通信受限计算中，拓扑的运行时选择与切换会直接影响系统性能、能效与可扩展性。**

TCC 的关键价值不在于复制既有 GPU/TPU/NPU/FPGA 路线，而在于将**拓扑页、Route 原语、Transform 原语与运行时提交机制**上升为可独立设计和验证的体系结构对象，探索由"节点中心"走向"拓扑中心"的新路径。

### 1.2 范式转换

| 维度   | 节点中心（当前主流） | 拓扑中心（TCC）    |
| ---- | ---------- | ------------ |
| 拓扑绑定 | 编译时静态确定    | 运行时微秒级液态切换   |
| 硬件底座 | 训推芯片架构割裂   | 同一底座，拓扑自适应   |
| 任务适配 | 面向单一任务优化   | 多任务液态切换      |
| 网内计算 | 有限或无       | R/T/C 原语原生支持 |

### 1.3 项目载体

**项目名称**: 拓扑中心计算范式架构研究与液态拓扑端侧 MVP 验证
**项目类型**: 自主科研课题
**参与单位**: 天津大学 + NDSC + 复旦 + 苏州实验室（联合推进）
**实施周期**: 2026年7月至2028年12月，共30个月
**核心任务**: TCC理论体系、R/T/C原语定义、TCC-Link v0.5、VU13P板级MVP、仿真平台、综合评估

## 二、R/T/C 原语体系（权威定义 v2.0）

> **来源**: TCC_项目实施方案_v30_最终版.docx（2026-07-01 提交版）三张原语场景映射表的字面转录 + v2.0 命名统一
> **命名修订依据**: v30 中 T=Transport（传输原语）→ v2.0 称 R=Route（路由/拓扑通信原语）；v30 中 R=Reduction（归约原语）→ v2.0 称 T=Transform（变换计算原语）。修订基于 Route-Transform 分解定理——Route=通信、Transform=计算 的二分法比 Transport/Reduction 更精确地反映 TCC 范式本质。

### 2.1 三类原语总览

| 类别    | 全称                | 数量  | 定义                        |
| ----- | ----------------- | :-: | ------------------------- |
| **R** | Route（路由/拓扑通信原语）  |  6  | 定义数据在 MacroTile 之间的集体通信模式 |
| **T** | Transform（变换计算原语） |  6  | 定义 MacroTile 内部执行的数学变换操作  |
| **C** | Control（控制原语）     |  4  | 定义拓扑切换、时钟同步、数据搬运的控制行为     |

**总计: 16 个原语**

### 2.2 R 类：Route 路由原语（6个）

| 原语         | 语义                      | 典型用途                             |
| ---------- | ----------------------- | -------------------------------- |
| **R.FUSE** | AllReduce（全归约）          | 梯度同步(DP)、蝶形归约(FFT/DBF)、部分和归约(TP) |
| **R.PULL** | AllGather（全收集）          | 参数分发、KV Cache汇聚、频谱聚合、特征汇聚        |
| **R.CAST** | Broadcast（广播）           | 权重广播、输入广播、窗函数广播、模型分发             |
| **R.SWAP** | AlltoAll（全交换）           | 转置(FFT)、通道交换(视频)、拓扑重排(多智能体)      |
| **R.PIPE** | ReduceScatter（流水归约散射）   | 流水段归约(TP)、流水FFT                  |
| **R.MESH** | Neighbor Exchange（邻域交换） | 邻域聚合(视频)、邻居通信(多智能体)              |

### 2.3 T 类：Transform 变换原语（6个）

| 原语         | 语义     | 典型用途                                 |
| ---------- | ------ | ------------------------------------ |
| **T.GEMM** | 矩阵乘加   | 梯度计算、QKV投影、CNN卷积、协方差                 |
| **T.FOLD** | 向量归约   | Loss归约、Softmax、能量归约(FFT)、RoI Pooling |
| **T.MAPS** | 逐元素映射  | 激活函数、LayerNorm、窗函数、NMS/ReLU          |
| **T.SCAN** | 前缀扫描   | 蝶形扫描(FFT)、特征排序、轨迹扫描                  |
| **T.LOOK** | 查表/LUT | 量化LUT、KV Cache索引、旋转因子LUT(FFT)、动作LUT  |
| **T.SPEC** | 特殊函数   | GELU/SwiGLU、RoPE、CORDIC、Softmax      |

### 2.4 C 类：Control 控制原语（4个）

| 原语         | 语义        | 典型用途                                                           |
| ---------- | --------- | -------------------------------------------------------------- |
| **C.LINK** | 拓扑配置与提交   | Butterfly拓扑Commit(DP)、All2All Commit(TP)、Butterfly→Ring切换(FFT) |
| **C.TICK** | 逻辑时钟/因果序  | 梯度版本计数、Token因果序、采样时间戳对齐(FFT)                                   |
| **C.SYNC** | Epoch边界同步 | Epoch边界同步(DP)、Layer边界同步(TP)、处理帧边界同步(FFT)                       |
| **C.MOVE** | DMA数据搬运   | 梯度→HBM写入、KV Cache搬运、ADC→计算搬运(FFT)                              |

## 三、Route-Transform 分解定理与超非线性增益

> **来源**: 07_核心定义_超非线性增益与智能视角.md

### 3.1 Route-Transform 分解定理（理论基础）

> 任意分布式计算任务的通信-计算耦合图，均可分解为 Route 原语集（6个）与 Transform 原语集（6个）的正交组合，且该分解在拓扑切换下保持封闭。

**联合原语映射**：在大模型训练、信号处理、多智能体三类典型场景中，每个计算步骤均可唯一映射到 (R.x ⊕ T.y) 原语对，三类场景覆盖 620+ 计算映射点。

### 3.2 超非线性增益定义

> **定义**: 当由简单节点组成的物理网络，其拓扑复杂度超过某一阈值时，网络整体完成特定认知任务的能力，相对于同等节点简单叠加所能达到的能力，出现不可还原的质变性提升——这种提升在**任务能耗效率（J/task）、任务多样性覆盖（D_task）和跨任务迁移适应性（V_transfer）**三个维度上同时体现，称为复杂网络的超非线性增益。

**核心约束**:
- 比较基准是完成同等任务所消耗的能量，而非原始计算吞吐量
- 节点本身保持简单，增益完全来自连接拓扑的结构性质
- 超线性不是量变（算得更快），而是质变（能做之前不能做的事）

### 3.3 三维度精确边界

| 维度   | 指标         | 精确含义                | 生物佐证                           |
| ---- | ---------- | ------------------- | ------------------------------ |
| 能耗效率 | J/task     | E_rand / E_crit > 1 | 人脑20W vs GPU集群3MW（~150,000×差距） |
| 任务覆盖 | D_task     | N个节点覆盖度超线性增长        | C. elegans 279神经元处理5+类任务流      |
| 迁移适应 | V_transfer | 新任务零/少样本适应          | 临界态网络激活不同子网络组合                 |

### 3.4 正式命题

**命题1（超非线性增益定理，⚠️ 待形式化证明）**：
> 设物理网络G的时空协同复杂度指标 RI 超过阈值 θ_c 时，G在{J/task, D_task, V_transfer}三维度上的表现，不可通过同等节点数的任意非复杂网络结构线性叠加获得。

**命题2（能耗超非线性）**：
> 存在拓扑参数组合使得 E_crit(T) < E_rand(T) / σ，即临界网络完成任务T的能耗，低于随机网络除以小世界系数后的结果。

**命题3（智能的正确度量）**：
> 智能系统的能力不应以原始算力度量，而应以三元指标{J/task, D_task, V_transfer}度量，三者共同定义"智能效率"（Intelligence Efficiency, IE）。

> **⚠️ 重要修正（v2.0）**：此前 v1.0 中 Gen1→Gen5 的 K 扇出目标表（K≈100→1,000,000）已被删除，原因：

## 五、元拓扑（Meta-Topology）

> **来源**: 11_SDI节点接口规范与化合键定义.md

### 5.1 三种基础类型

| 类型 | 类比 | 结构特征 | 特性 | 对应层级 |
|------|------|---------|------|---------|
| MT-α | 碳sp³ | 4个E-L键全部使用，三维稳定模块 | 高聚类C，稳定 | L0阵列内、稳定记忆 |
| MT-β | 碳sp² | 2E-L+1I-L+1E-S，兼顾稳定与可塑 | 半稳定，可响应新输入 | L1 Hub层、动态学习区 |
| MT-γ | 碳sp¹ | 1E-L+1E-S+2可扩展端 | 高可塑性，适合长程连接 | L2协调层、跨模块通信 |

### 5.2 与TCC的关系

元拓扑与SDI化合键用于解释高阶网络互连拓扑生成机理，是**构建任何高阶拓扑的通用生成机制**——TCC理论的深层底座。在当前工程阶段，不作为先导工程实现的强制约束。

**思考——元拓扑与SDI化合键的关系**：
> **问**: 元拓扑与SDI化合键是什么关系？
> **答**: 元拓扑是"语法"，SDI化合键是"字母"。元拓扑定义了高阶互连拓扑的通用生成机制，SDI化合键（E-L/I-L/E-S/I-S）是实现该机制的底层物理载体。就像碳原子的sp³/sp²/sp¹杂化轨道决定了分子三维结构一样，SDI化合键的类型组合决定了网络的元拓扑类型。元拓扑理论不是为了当前工程阶段使用，而是为TCC的长期演进（Gen3+）提供理论完备性。

### 12.1 超非线性增益的形式化证明

> **当前状态**: 命题1–3已在核心定义文件中提出，处于"待形式化证明"状态
> **重要性**: TCC 理论体系的数学基石，直接影响 σ 路线图的科学合法性、项目申报的可信度以及国际学术对话中的话语权
> **紧迫性**: 🔴 高——没有形式化证明，超非线性增益在学术审稿和项目评审中将被视为未证实的假说

**关键任务**:
1. 完成"超非线性增益定理"的严格数学证明（从 CST/RI 的定义出发，给出增益下界的解析推导）
2. 建立 RI（智能等级）与 CST（复杂网络时空协同指标）的定量映射关系：RI = CST / E_env > θ_c
3. 给出 σ 阈值 θ_c 的解析表达式（而非经验取值）
4. 在三元指标 {J/task, D_task, V_transfer} 上分别证明超线性标度律
5. 关联 iNEST 的跨物种相图结论（σ ~ N^0.398，SC-FC 2.3×）建立跨学科证据链

**目标期刊**: Nature Computational Science / Physical Review X / PNAS

> **目标**: 为超非线性增益、原语完备性、拓扑切换性能提供可量化的仿真验证平台
> **当前状态**: 未启动
> **紧迫性**: 🔴 高——M2 里程碑（2027.06）需要仿真数据支撑

**关键任务**:
1. 搭建基于 R/T/C 原语的 TCC 系统级仿真环境（支持多Tile、多任务、多拓扑配置）
2. 实现拓扑液态切换的性能仿真（微秒级切换延迟的量化验证）
3. 验证 J/task、D_task、V_transfer 三元指标的仿真可测性
4. 为 M2 里程碑（单场景MVP）提供仿真数据支撑
