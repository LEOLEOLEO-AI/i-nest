# SDI高阶Torus方案：虚通道×颜色电路交换×分组交换混合架构

# SDI高阶Torus方案：虚通道×颜色电路交换×分组交换混合架构

> 背景：基于 Torus 拓扑技术史的启发，将虚通道（死锁解决）、Cerebras 颜色配置（电路交换路径调度）、电路交换+分组交换混合模式，统一到 SDI（软件定义互连）框架下，实现高阶 Torus 或其他拓扑的灵活配置。

## 一、核心设计思想

SDI（Software-Defined Interconnect）的本质：**物理拓扑固定 + 逻辑拓扑可编程**。底层用高阶 Torus（或 Mesh / Hypercube）做物理布线，上层通过软件动态配置通信路径，同时支持电路交换（确定性长流）和分组交换（弹性短流）两种模式，用虚通道解决死锁和服务质量隔离。

类比 Cerebras WSE：晶圆上的 Swarm 通信网络本质上也是"物理 Mesh + 可编程路由 + 颜色分配的电路交换路径"，只是规模在晶圆级。把这个思路放大到晶上 / 多芯片系统，就是 SDI 高阶拓扑。

## 二、三层架构

### 第1层：物理层——高阶 Torus / Mesh 基底

- 物理拓扑选型：推荐 3D Torus 或 6D Mesh/Torus（参考富士通 Tofu），维度越高直径越小，但布线复杂度越高
- 晶上场景折中：2D Mesh + 环形回环（即 2D Torus），工艺成熟、布线可控
- 多芯片 2.5D/3D 堆叠场景可扩展到 3D Torus
- 每个节点物理端口数：2D Torus = 4 方向 + 本地计算端口；3D Torus = 6 方向 + 本地端口

### 第2层：链路层——虚通道 + 颜色电路交换

每条物理链路 = N 条虚通道（VC），分两类：

**电路交换虚通道（CS-VC）**
- 对应 Cerebras 的"颜色"——每条 CS-VC 代表一条端到端确定性路径
- 建立后数据直通、零排队、确定性延迟
- 颜色数量 = 可同时建立的不冲突电路交换路径数

**分组交换虚通道（PS-VC）**
- 传统存储-转发 / 虫洞路由虚通道
- 用于突发、短消息、自适应路由流量

**颜色配置机制**
- 每条 CS-VC 分配一个"颜色 ID"
- SDI 控制平面计算端到端路径，将"输入颜色→输出端口→输出颜色"映射表写入各节点路由表
- 配置完成后数据直通，无需路由计算、无需缓冲排队

**死锁解决**
- PS-VC：维度序路由 + 虚通道偏序（如 X 方向用 VC0，Y 方向用 VC1），打破环形依赖
- CS-VC：控制平面路径计算时确保不形成环路，数据面无死锁

### 第3层：控制层——SDI 软件定义控制平面

- 全局拓扑视图，类似 SDN 控制器
- 三大核心功能：
  1. 拓扑重构：将物理 Torus 配置为不同逻辑拓扑（Ring / Mesh / Fat-Tree 子树）
  2. 路径计算与颜色分配：对确定性长流计算端到端路径、分配颜色、下发路由表
  3. 流量工程：动态调整 CS-VC 和 PS-VC 比例、重路由故障链路、负载均衡

## 三、两种交换模式的分工与协同

| 维度 | 电路交换（CS-VC / 颜色路径） | 分组交换（PS-VC / 自适应路由） |
|---|---|---|
| 适用流量 | 确定性长流、大块数据、周期性同步 | 突发短消息、控制信令、随机稀疏通信 |
| 延迟 | 极低且确定（纳秒级，无排队） | 较高且有抖动（受拥塞影响） |
| 带宽利用率 | 独占通道，空闲时浪费 | 统计复用，利用率高 |
| 建立开销 | 需要预配置路径 | 无需建立，即发即走 |
| 死锁风险 | 控制平面保证无环 | 需虚通道+维度序路由防死锁 |
| 典型场景 | 大模型张量并行、流水线并行梯度同步 | MPI 点到点、控制消息、不规则集合通信 |

协同机制：同一物理链路上 CS-VC 和 PS-VC 分时 / 分频复用带宽；SDI 控制平面根据应用特征动态调整两类虚通道数量比例。

## 四、为什么选高阶 Torus 做物理基底

1. 规则性：Torus/Mesh 高度规则，物理布局布线可预测，适合晶上/晶圆级实现
2. SDI 友好：规则拓扑上路径计算、颜色分配算法复杂度低
3. 可扩展性：分布式路由天然支持规模扩展，软件可重构逻辑拓扑
4. 容错性：物理链路故障时 SDI 控制平面可快速重路由

## 五、路由表结构（每个节点的硬件实现）

### CS-Table（电路交换转发表）
- 索引：输入端口 × 输入颜色 → 输出端口 × 输出颜色
- 纯组合逻辑直通，无缓冲、无路由计算
- 8 颜色 × 6 端口 = 48 表项，面积极小

### PS-Table（分组交换路由表）
- 索引：目的节点 ID → 输出端口 × 虚通道号
- 默认维度序路由（DOR），可选自适应路由
- 按维度分 VC，从机制上杜绝环形依赖

### 端口仲裁器
- 每个输出端口一个仲裁器
- CS-VC 优先级高于 PS-VC
- PS-VC 之间轮询或 WFQ
- 虫洞路由模式，flit 级调度

## 六、颜色分配与路径计算算法

本质是 RWA（Routing and Wavelength Assignment）问题在片上网络场景的变种。

### 两阶段启发式算法
**第一阶段：路由计算**
- 对每个源-目的对，用 Dijkstra 计算 k 条候选路径（k=3~5）
- 路径代价 = 跳数 + α × 链路已用颜色数

**第二阶段：颜色分配（图着色）**
- 所有已选路径构成冲突图：共享链路的路径之间连边（不能同色）
- 贪心着色：按路径长度从大到小排序，依次分配最小可用颜色
- 颜色不够则回退换路径，或降级到 PS-VC

### 增量重配置
- 新流量到达时增量分配，不全量重算
- 周期性全局优化，整理颜色资源碎片

## 七、SDI 控制平面状态机

五种状态：Idle → Path Compute → Table Update → Running → Re-route

- **Path Compute**：运行路径计算+颜色分配算法，大规模网络下数十微秒到毫秒级
- **Table Update**：通过配置总线写入各节点 CS-Table，支持批量写入
- **Running**：数据面正常转发，监控链路利用率和故障告警
- **Re-route**：链路故障后快速切换到备用路径，目标 <1μs 检测 + <10μs 重配置

配置一致性：先建新路径、验证连通性，再切流量、最后拆旧路径，避免断流式重配置。

## 八、故障处理与容错机制

### 链路故障
- 检测：心跳 flit 超时判定
- CS-VC：控制平面 Re-route 重新分配颜色路径
- PS-VC：数据面自动绕行或控制平面更新 PS-Table

### 节点故障
- 物理层：旁路通路（bypass path），节点故障时对向链路直通
- 逻辑层：控制平面摘除故障节点，重算所有相关路径
- 降级模式：拓扑从 Torus 退化为带缺口的 Mesh

### 死锁防护
- PS-VC 层：维度序路由 + 按维度分配 VC
- CS-VC 层：控制平面环路检测
- 跨层：CS-VC 和 PS-VC 不共享缓冲，互不影响

## 九、与 Cerebras WSE 的对比

| 维度 | Cerebras WSE | 本方案（SDI 高阶 Torus） |
|---|---|---|
| 物理规模 | 晶圆级单片（~85万核） | 晶上/多芯片/多板卡可扩展 |
| 拓扑 | 2D Mesh（无回环） | 2D/3D Torus（有回环，直径更小） |
| 交换模式 | 纯电路交换（颜色路径） | 电路交换 + 分组交换 混合 |
| 可编程性 | 编译期静态调度 | SDI 运行时动态重配置 |
| 容错 | 冗余核 + 冗余链路 | 旁路 + 重路由 + 动态降级 |
| 编程模型 | 类数据流，需显式布局 | 兼容 MPI / 张量并行 / 自定义 |

## 十、关键技术挑战

1. 颜色资源分配算法：RWA 是 NP 难问题，需高效启发式算法，毫秒级完成大规模网络计算
2. 虚通道缓冲区设计：PS-VC 需要缓冲，CS-VC 不需要，面积和功耗需精细权衡
3. 重配置开销：颜色路径切换需要时间，如何做到无损切换/快速重配置
4. 编程模型适配：应用层需感知两种交换模式差异，或由编译器/运行时自动分配

## 十一、一句话总结

物理层用高阶 Torus 打底，链路层用虚通道把"颜色电路交换"和"分组交换"装进同一根物理链路，控制层用 SDI 统一调度——相当于把 Cerebras WSE 的电路交换思路从晶圆级推广到可编程的多拓扑网络，同时保留了 Torus 的规模扩展性和分组交换的灵活性。
