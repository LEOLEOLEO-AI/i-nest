# 推送行为规范 v2.0 - 杜绝自动推送

## 【核心原则】

**禁止在用户说"推送"时立即执行。必须先确认要推送的具体内容。**

---

## 【正确流程】

### ❌ 错误的做法（之前）
```
用户："推送"
我：立即执行 git push
结果：可能推送错误内容、未验证文件
```

### ✅ 正确的做法（现在）
```
用户："推送"
  ↓
我：列出当前工作区变更
  ├─ 新增文件
  ├─ 修改文件
  ├─ 删除文件
  └─ 提示大小/数量
  ↓
我：询问用户
  "确认要推送以下内容吗？"
  ↓
用户：明确确认
  "推送"、"推送新增的文件"、"跳过这个"等
  ↓
我：执行推送 + 验证
```

---

## 【推送前检查清单】

**我必须做**：

1️⃣ **列出当前工作区的所有变更**
```
git status --short
显示：
  M  = 已修改
  A  = 新增
  D  = 已删除
  ?? = 未追踪
```

2️⃣ **分类显示**
```
【新增文件】(6 个, 2.5 MB)
  - file1.md
  - file2.py
  ...

【已修改文件】(3 个)
  - existing.md
  ...

【待删除文件】(0 个)
```

3️⃣ **询问用户意图**
```
"检测到以下变更，确认推送吗？"
选项：
  - ✅ 推送全部
  - 📝 推送指定文件（列出选项）
  - ❌ 取消推送
```

4️⃣ **等待用户明确回复**
```
禁止假设
禁止自动推送
等待用户说出：
  "是" / "确认" / "推送" / 或具体文件名
```

5️⃣ **执行 + 验证**
```
只有收到用户确认后才执行：
  git add
  git commit
  git push
  验证文件在远程存在
```

---

## 【禁止的行为】

```
❌ 看到 git status 有变更就自动推送
❌ 用户说"推送"就立即执行
❌ 没有显示变更清单就执行
❌ 没有等待用户确认就执行
❌ 推送后没有验证就报告成功
❌ 虚假报告"推送成功"
```

---

## 【必须的行为】

```
✅ 始终先显示变更清单
✅ 始终询问用户确认
✅ 始终等待用户明确指令
✅ 始终在推送后验证
✅ 始终诚实报告结果
✅ 如果有问题，立即暂停并报告
```

---

## 【更新的"推送"工作流】

### 当用户说"推送"时

```bash
# 第一步：检查工作区
cd ~/i-nest
git status --short

# 输出给用户看
【当前工作区变更】
A  50_Output/Diagnosis/report.md
M  35_Simulation/exp.py
D  temp_file.txt

【统计】
新增：1 个文件 (20 KB)
修改：1 个文件 (5 KB)
删除：1 个文件

【问题】
❓ 确认推送以上全部内容吗？
  输入：
    "是" = 推送全部
    "只推送 report.md" = 指定推送
    "取消" = 不推送
```

### 等待用户明确回复

```
不能假设
不能猜测
必须等待用户说出具体指令
```

### 收到确认后执行

```bash
git add <指定的文件>
git commit -m "..."
git push github master:main
git push origin master

# 验证
验证文件在 GitHub/Gitee
验证大小一致
```
