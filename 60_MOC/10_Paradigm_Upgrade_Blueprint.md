## 二、五大核心断层 🔴

### 断层1：导入 ≠ 消化（最致命）

```
得到大脑 → 10_Inbox → ❌ 停在这里
Genspark → genspark/sync → ❌ 从不合并到main
arXiv/WoS → 20_Processing → ❌ 堆积不分类
```

**现状**: 3条导入管线都在工作，但导入后的内容**从未真正进入知识循环**。
- 10_Inbox 只有12篇，说明大部分导入内容被丢弃或未处理
- 20_Processing 79篇堆积，从未被分类到 TCC/iNEST
- 32_Technology/33_Engineering 为 0 —— 说明从未有内容从理论层流转到技术/工程层

### 断层2：分类 ≠ 链接（结构虚设）

**现状**: 目录结构定义了 `31_Theory → 32_Tech → 33_Eng` 的分层，但：
- 所有2,669篇TCC/iNEST内容全部堆在 `Theory` 层
- 没有任何文件被标记为技术攻关或工程开发
- `[[双向链接]]` 几乎不存在 —— 内容之间是孤岛

### 断层3：洞察 ≠ 任务（不可执行）

**现状**: `02_DeepSeek_Insights.md` 每日生成，但：
- 洞察是泛泛的"建议方向"，没有转化为**可执行任务**
- 看板中的任务是硬编码的，不随洞察更新
- 没有"今日该做什么"的具体清单
- 论文灵感生成后没有跟踪"是否在写"

### 断层4：看板 ≠ 真实进度（花架子）

**现状**: `70_Dashboard/index.html` 是一个静态HTML页面：
- 任务数据硬编码在 `<script>` 标签中
- 不反映 vault 中实际文件变化
- 没有与 dataview/obsidian-tasks 联动
- 按钮命令不可用（"找不到命令"）

### 断层5：交互 ≠ 聚焦（散乱）

**现状**: 你（研究员）与系统的交互方式：
- 在 Obsidian 中手动翻找文件
- 在 Codex 中发指令 → 每次都要重新描述上下文
- 看板只看不交互
- 没有"今日焦点任务"的推送
- 没有时间分段的沉浸式工作流

## 三、GitHub 最佳实践对标

基于对当前开源生态的分析，以下是最值得借鉴的项目和思路：

### 3.1 Karpathy Wiki LLM 思想

Karpathy的知识库管理核心理念：
1. **单一真相源** — 每个概念只有一处权威定义
2. **链接即思维** — 密集的双向链接形成知识网络
3. **渐进式细化** — 从stub到成熟笔记的演化路径
4. **定期回顾** — 周期性重读、重构、重组

我们已有结构但缺**演化机制**——笔记导入后从不生长。

所有工具都已安装（dataview, tasks, kanban, smart-connections, templater），但它们互不通信。看板不读dataview，任务不触发票据，洞察不生成任务。

## 四、范式级升级方案 🚀

### 设计原则

1. **数据驱动** — 一切从 vault 文件真实状态计算，永不平替
2. **单向流动** — Inbox→Processing→Knowledge→Output→Archive 不可逆
3. **交互聚焦** — 每日一个焦点会话，系统推任务、你判定
4. **自进化** — LLM 定期重构分类、链接、摘要

### 4.1 新架构：五层智能体

```
┌────────────────────────────────────────────┐
│         L0: 采集层 (非智能)                  │
│  得到大脑 / Genspark / arXiv / Web Clipper   │
│              ↓ 自动导入                      │
│         L1: 消化层 (每日)                    │
│  LLM分类 → 提取观点 → 标记链接 → 去重        │
│              ↓ 产出: 结构化笔记+标签          │
│         L2: 链接层 (每日)                    │
│  语义匹配 → 双向链接 → 知识图谱更新           │
│              ↓ 产出: 关联网络+灵感列表         │
│         L3: 任务层 (每日)                    │
│  洞察→可执行任务 → 推送到看板 → 关联产出目标  │
│              ↓ 产出: 今日焦点+进度追踪         │
│         L4: 产出层 (持续)                    │
│  论文撰写 / 专利撰写 / 代码开发 / 仿真实验     │
│              ↓ 产出: 论文/专利/代码/数据       │
└────────────────────────────────────────────┘
```

### 4.2 核心改造：统一数据总线

**不再有硬编码数据**。所有面板从一个真实的 `data.json` 读取：

```javascript
// 统一数据总线 (由 pipeline_v3.py 每日更新)
{
  "date": "2026-07-15",
  "inbox": { "new": 3, "pending": 12 },
  "insights": { "tcc": 5, "inest": 4, "cross": 2 },
  "tasks": {
    "today": [
      { "id": "T1", "title": "完善CST仿真参数", "dim": "TCC", "type": "仿真", "priority": "高" }
    ],
    "active": [...]
  },
  "papers": { "drafting": 3, "reviewing": 1, "published": 0 },
  "patents": { "drafting": 2, "filed": 0 },
  "code": { "active_repos": 2, "last_commit": "2026-07-14" },
  "progress": { "tcc_theory": 0.6, "inest_eng": 0.3 }
}
```

### 4.3 新 Home.md：研究员驾驶舱

不是信息展示页，而是**每日工作起点**：

1. **焦点区** — 今日3个最重要任务（从活跃任务提取）
2. **进度环** — TCC/iNEST 各维度完成度可视化
3. **新发现** — 过去24h导入的高价值内容摘要
4. **灵感队列** — LLM生成的3-5个可验证灵感
5. **一键操作** — "处理Inbox" / "生成今日洞察" / "同步所有源"

### 4.4 新看板：任务驱动+数据绑定

- 看板卡片**直接从 vault 文件生成**，通过 dataview 查询
- 每张卡片有：状态、优先级、关联文件、最后活动时间
- 按钮调用真实脚本，不依赖不可用的命令

### 4.5 新交互模式：每日焦点会话

```
08:00  系统推送：「今日焦点」— 3个任务 + 新导入摘要
      你确认/调整优先级
09:00  深度工作块 #1 (90分钟)
      系统只显示当前任务相关文件
10:30  快速回顾：系统记录进度，更新看板
11:00  深度工作块 #2
...
20:00  系统处理Inbox → 分类 → 链接 → 生成洞察
21:00  你评审洞察 → 标记可执行 → 生成明日任务
      系统同步到 Gitee
```

## 七、衡量标准

升级后的系统应该能回答：

1. ✅ **今天最重要的3件事是什么？** → Home.md 焦点区
2. ✅ **这篇新论文对我的哪个研究方向有启发？** → 自动链接
3. ✅ **TCC论文A 写到哪了？** → 看板追踪
4. ✅ **上次CST仿真结果支持哪个假设？** → 知识图谱回溯
5. ✅ **本周 iNEST 方向推进了多少？** → 进度环
6. ✅ **有没有重复造轮子？** → 语义去重自动检测
